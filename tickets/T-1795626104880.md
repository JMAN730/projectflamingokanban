### Bug

In `crates/victory-shader/src/emit/lower.rs` (`Lower::compare`), `v_cmp_class_f16` reads raw integer bits and applies VOP3/SDWA `abs` and `neg` modifiers bitwise (`& 0x7FFF` / `^ 0x8000`), whereas `v_cmp_class_f32` routed `src0` through `self.fsrc(inst, 0)` followed by `self.as_int(x)`:

```rust
} else {
    let x = self.fsrc(inst, 0)?;
    self.as_int(x)
};
```

Because `fsrc` lowers `abs` as `dx.op.unary.f32(FAbs)` and `neg` as `fsub -0.0, x`, floating-point arithmetic executes on `src0` before classification:
- On D3D12 hardware (FTZ enabled for f32), `v_cmp_class_f32` with `neg` on `+denormal` (`0x0000_0001`) flushes to `-0.0` (class 5) instead of classifying as `-denormal` (class 4).
- Signalling NaNs (`0x7F80_0001` / `0xFF80_0001`) can be quieted to qNaNs (class 1 instead of class 0) by float negation.

On RDNA2, `abs`/`neg` on `v_cmp_class_f32` manipulate only bit 31 without flushing denormals or quieting signalling NaNs.

### Fix

- Unified `v_cmp_class_f32` with `v_cmp_class_f16` in `Lower::compare`: read the raw `i32` operand (still applying `sdwa_src` selection if present) and apply `abs` (`& 0x7FFF_FFFF`) and `neg` (`^ 0x8000_0000`) bitwise.
- Added `emit::valu_tests::v_cmp_class_f32_matches_rdna2` in `crates/victory-shader/src/emit/valu_tests.rs` covering all 10 IEEE-754 binary32 classes (plain) plus `neg`, `abs`, and `abs+neg` modifier cases on normals, `±0.0`, `±inf`, `±denormal`, and `±sNaN` (also addressing #799).

### Verification

- **Before fix:** `v_cmp_class_f32_matches_rdna2` failed on hardware GPU (`hardware: v_cmp_class_f32[neg](0x00000001, 0x010) = 0, want 1`).
- **After fix (Windows 11, native SM 6.6 hardware GPU + WARP + `dxil.dll` validation):**
  - `cargo test -p victory-shader`: 121 passed, 0 failed, 1 ignored.
  - `cargo clippy -p victory-shader --all-targets -- -D warnings`: clean.
  - `cargo check -p victory --features diagnostics`: clean.
  - `rustfmt --edition 2024 --check` on `valu_tests.rs` and all modified lines of `lower.rs`: clean.
  - `cargo xtask policy`: 154 files ok.
