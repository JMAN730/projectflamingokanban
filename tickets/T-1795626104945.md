## Original body

Fixes #887 (related to #871, #876, #562).

Problem

After #876 resolved the black screen cutscenes, titles requesting large descriptor heaps (e.g. 1,245,184 views on GTA VI world load) run into the D3D12 Tier 1/2 hardware limit of 1,000,000 shader-visible descriptors:

HostHeap::new() attempts to allocate count + DYNAMIC and count + MIN_DYNAMIC, both of which fail with E_INVALIDARG (0x80070057) because the size exceeds 1,000,000.
The cap fallback previously gave only MIN_DYNAMIC (65,536) slots to dynamic tables and 934,464 to title views.
Under heavy world frames (3,300–5,500 draws/dispatches), 65,536 dynamic slots were rapidly exhausted. HostHeap::dynamic() returned None, causing draw.rs to drop passes (a draw or dispatch dropped: no dynamic slots for its tables reaching dropped=65536). Dropped compute dispatches and render passes ultimately led to null-pointer crashes (0xc0000005 write 0x0).
Any allocation failure at exactly 1,000,000 slots caused HostHeap::new() to return None, abandoning the host view heap entirely.
Solution

Multi-tiered Heap Fallback (crates/victory-gpu/src/descriptor/host.rs):

When requested views + dynamic headroom exceed PORTABLE_VIEWS (1,000,000), or if heap creation fails, we gracefully try a decreasing fallback ladder: [PORTABLE_VIEWS, 500_000, 250_000, MIN_DYNAMIC].
On a capped 1M heap, dynamic headroom is doubled to 131_072 (1 << 17 slots), providing sufficient breathing room for thousands of simultaneous draws.

Cursor Wraparound Fix in dynamic():

Extended the second search pass to (cursor..end).chain(0..cursor.saturating_add(n - 1).min(end)) so free contiguous blocks crossing the allocator search cursor are not falsely rejected.

Ring-Buffer Dynamic Recycling (crates/victory-gpu/src/descriptor/host.rs, draw.rs):

Implemented HostHeap::recycle_dynamic(n).
In State::tables(), table allocation now uses host.dynamic(n).or_else(|| host.recycle_dynamic(n)). When dynamic capacity is fully saturated, slots are recycled in a ring-buffer fashion instead of dropping draws or dispatches.

Safe Out-of-Bounds Mirroring:

In HostHeap::mirror(), requests for index >= self.count now recover and return the underlying title View from guest memory so resource transitions and barriers continue to run cleanly.
Verification
Added synthetic unit test heap_request_over_one_million_caps_gracefully emulating a 1,245,184 descriptor allocation request.
Added synthetic unit test dynamic_descriptor_recycling_survives_pool_exhaustion verifying safe slot recycling when the pool is completely saturated.
Added synthetic unit test dynamic_cursor_wraparound_finds_contiguous_span validating cursor-boundary allocation.
cargo test -p victory-gpu passed (53 passed, 0 failed, 1 ignored).
cargo clippy -p victory-gpu --all-targets -- -D warnings and cargo xtask policy (154 files ok) pass cleanly.

Branch: [fix/issue-887-descriptor-heap-limit](https://github.com/Xvania7/VIctory/tree/fix/issue-887-descriptor-heap-limit) (commit 0ae1f58).

### Comment 1 — @MichaelSmithAI — 2026-11-24T13:54:58Z

There is a descriptor lifetime problem in the ring fallback at 0ae1f58. A recorded list owns its fresh descriptor range until release. After the free-range search fails, `recycle_dynamic` can return slots that still belong to that list. Writing the replacement table changes the descriptors visible to previously recorded work. The earlier owner also retains its release record, so its eventual release can mark the replacement range free.

I’d keep the normal allocation-failure path until a range is available for exclusive use. That ownership has to cover both lists waiting to be submitted and submissions still using the descriptors. The free-range cursor fix can be taken independently from [#871](https://github.com/Marvisak/VIctory/issues/871). The heap-size fallback can also be evaluated separately by recording the capacity actually created and how much remains for mirrored title slots.

This finding is from source review. The allocation-count test establishes that recycling returns an index under pressure. It doesn't establish lifetime correctness for recorded tables or the cause of the reported title crash.


For the oversized-request path at the 1,000,000-slot fallback, the dynamic reserve grows from 65,536 to 131,072. That leaves 868,928 directly mirrored title slots, down from 934,464. Tables in the displaced range can now consume the extra dynamic space themselves. Returning a guest view from `mirror` allows resource preparation, but the shader still needs a materialized descriptor in the bound heap. Logging the selected total, mirrored count, and dynamic count would distinguish the outcomes, including when a smaller allocation succeeds.

The >1M test also assumes the fallback was taken. The constructor deliberately tries the full request first, and that can succeed on a capable adapter. A deterministic ladder test could control which allocation attempts succeed, with separate cases for full-size success and each fallback.
