## Original body

Save recovery can delete a committed save if its container also contains a leftover directory named `v01`. The scan parses both `v01` and `v1` as version 1. When it cleans up what it considers an older version, it reconstructs the name as `v1` and deletes the committed save.

I reproduced this on upstream `ffe310e` using a synthetic save in a temporary directory. The regression test writes a valid `v1`, creates an empty `v01`, and reads the save. Before the fix, the read removes `v1`. After the fix, the original save is still readable and both directories remain.

The patch makes recovery recognize only the canonical version names written by the save system. The commit includes the regression test. [Patch and regression test](https://github.com/THE-PRO-GAME/VIctory/commit/27491af5b8b2b53f24b4e97f608f80a314113f6b)

```powershell
cargo test --locked -p victory-hle a_noncanonical_directory_does_not_remove_a_committed_save
```

Related to the broader audit in #810. I used Codex and verified the reproduction with synthetic inputs on Windows 11.

### Comment 4 — @winne42 — 2026-11-24T20:16:40Z

I tested the fixes for this issue as Windows builds under Wine 10.0. Note that all three PRs (#1006, #1035, #1102) were closed by their own authors without being merged, so nothing open currently fixes this.

**The name fix works in all three.** #1102's code is the same as THE-PRO-GAME's `27491af`, which doesn't cherry-pick alone, because it's stacked on `1bd9a93`. Each PR's own tests pass, and its new test fails when the name check is reverted. clippy is clean.

**A stray folder with a correct name still loses the save, and #870's fix doesn't cover that.** I committed a real `v1`, added a stray entry next to it, then called `read()`:

| Stray entry next to `v1` | `main` | #1006 / #1035 / #1102 | + `ec2cff0` (THE-PRO-GAME/VIctory#2) |
|---|---|---|---|
| `v01`, `v+1`, `v001`, `v02` (empty, or a copy of `v1`) | `v1` deleted | kept, reads fine | kept, reads fine |
| `v2`: empty folder, a file, or a corrupt manifest | `v1` deleted | **`v1` deleted** | kept, read errors |

The empty-`v2` case is worse than a failed read. On `main` and on all three PRs, the next save returns `S_OK` but commits a fresh `v1` holding only the changed blobs. The following read then prunes that `v1` too, because `v2` still counts as newer. The title is told every save succeeded while nothing survives.

With `ec2cff0` the data is kept, but `submit` returns `NO_ACCESS` (`0x80830002`) until the stray folder is removed.

**Suggestion:** land the name check together with `ec2cff0`, so recovery never deletes a version before a newer one has been read successfully. A fuller fix would be for `current()` to use the newest version whose manifest parses, prune only versions below it, and number the next commit above the highest `v<N>` folder. That way a broken or stray newer folder neither hides the save nor blocks writes.
