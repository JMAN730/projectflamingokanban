### Comment 1 — @DaviTostes — 2026-11-24T11:47:40Z

Related data from a different Linux stack, with the same 1.0.2.1 package:

- **GPU/OS:** AMD RX 9060 XT (RDNA4, RADV 26.3.1), Arch Linux, kernel 6.18.x.
- **Stack:** Wine 11.22 (system), DXVK 3.1.1 `dxgi`, **vkd3d-proton 3.2.0** (DLLs from Proton Experimental), `WINEDLLOVERRIDES="d3d12,d3d12core,dxgi=n"`.
- **Build:** VIctory `main` `ffe310e`, release MSVC, `build unknown (b99f876b…b5c35a79d5decd9f716504239e93)`.

I see the same picture problem, but a different ending:

- menus 30 fps, intro **11–15 fps** (CPU-bound texture prep), loading, world **0.2–0.4 fps** with the dark frozen background and audio;
- 81 untranslated shaders in the first ~2 minutes, thousands of indirect executions (e.g. `660 draws/frame, dropped 2184 … and 4105 indirect`);
- no `d3d12core.dll+0x264b4c` here. The run instead gets Wine `RtlReleaseSRWLockExclusive … not owned exclusive!` from several threads (#774), then `host GPU device removed … 0x887A0005` after a **7-list** submission; another run kept presenting at 0.4 fps until I killed it.

Two suggestions for this report: the `d3d12core+0x264b4c` fault may be tied to GE-Proton11-11's vkd3d (3.1); with 3.2.0 the first mesh pipeline no longer crashes (see #752). And #282/#346 are the open rectangle-list fixes; #282 reached the world here without `rectangles not expanded` warnings.

**Not tested:** Intel Arc, GE-Proton11-11, #242, and a longer session after the lock warning.
