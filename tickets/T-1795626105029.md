## Original body

**No game data here.** Offsets, counts and our own analysis only.

## Setup
- Windows 11, **NVIDIA GTX 1660 SUPER (6 GB)**, Ryzen 5 5600, 32 GB RAM
- VIctory `ffe310eb` (`main`), release build; `victory run <exe> --execute`, own 1.0.2.1 package (exe hash `e95020b2…`, the #630/#1063 one)
- A local workaround from **#1063** is in place (NOP the two decode-assert `int3` sites at `+0x1330a44`/`+0x1330a4a`) so the title gets past the world-load decode failure and reaches its first-boot screens

## What happens
1. Boot, the first-boot screens and menus render normally and run at a stable **30 fps**.
2. Opening **Settings** — either the **SETTINGS** button on the *"Finish Setup?"* screen or Escape from the menu — turns the screen **black**. The process stays alive and keeps presenting at 30 fps; buttons on the black screen do nothing visible, so no setting (in particular the resolution) can be changed.
3. The log is **clean** across the transition: no new `WARN`, no `unsupported`/`refused`/`failed`, no unimplemented method, no `no host texture`. The only lines are the ordinary per-frame `30.0 fps` reports.

## Why it matters
The title validates a mode list — `1920×1080@60`, `2560×1440@60`, `3840×2160@60` — and defaults to **3840×2160**. On a 6 GB card that pins dedicated VRAM (Task Manager shows **5.5 / 6.0 GB** with only 5 draws/frame while idle in a menu), which is the wall that stops the world on this GPU.

That **Settings** screen is the only supported way to pick `1920×1080`. I tried to force it externally and it does not work, which is why the settings screen is the lever:

- patching the three `movabs …, 0x00000870_00000F00` (3840,2160) display-descriptor sites → the presented size stays 3840×2160;
- patching the mode list's 3840 entry → the title **asserts** (it looks its requested resolution *up* in that list, so removing it trips the check).

## Ask
Is the settings/pause menu a known gap — does it need a pipeline/shader/descriptor path that still misbehaves? If you can point at the pipeline it binds, `VICTORY_SKIP_PIPELINES=<hash>` would confirm it in one run. A `VICTORY_RESOLUTION` (or window/swapchain) knob would also let a small card sidestep this entirely, independent of the menu.

Secondary, possibly related: two textures are refused shortly before (`0x80070057`) — a **2560×1440 BC7** (format 86) with `ALLOW_RENDER_TARGET|ALLOW_UNORDERED_ACCESS`, and a **format 115** texture with `ALLOW_RENDER_TARGET`.
