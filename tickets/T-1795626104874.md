## Original body

Environment:

OS: Windows 10/11 x64

GPU: NVIDIA GeForce RTX 3050 8GB

Build: VIctory (commit matching post-Nov 24 waterfall loop changes), compiled with cargo build --profile diag -p victory --features diagnostics

Target: GTA 6 Xbox Scarlett (game_scarlett_master.exe)

Problem Summary:
The game launches, plays introductory videos, and completes the map loading screen without issues. However, the application consistently crashes silently at the exact moment of transitioning into the real-time 3D cutscene of the first mission.

Symptoms & Diagnostics:

Error Codes: crashes.log consistently reports 0x887A0004 (unsupported feature/interface) followed immediately by 0x887A0006 (device removed).

Command Limit: The crash occurs after submitting a specific batch of command lists (varying between 8 and 30 lists depending on background VRAM availability).

Diagnostics Failure: Despite running with VICTORY_D3D12_DEBUG=1 on a diagnostics build, the log outputs no breadcrumbs, preventing identification of the exact failing D3D12X API call.

VRAM Observation: Freeing up VRAM (closing background applications like Opera) allows the engine to render initial 2D overlay elements (developer credits) slightly further before triggering the fatal GPU detachment.

Expected Behavior:
The D3D12X translation layer should provide fallbacks for console-specific hardware instructions (such as proprietary mesh shaders or sampler feedback) to prevent total device removal on Nvidia Ampere architecture.

### Comment 1 — @Zilumz1 — 2026-11-24T13:03:20Z

One thing to split apart here: `0x887A0004` is not a D3D12X translation failure. In this tree that value is `DXGI_ERROR_UNSUPPORTED`, which is what `ID3D12DeviceRemovedExtendedData::GetAutoBreadcrumbsOutput()` returns when DRED auto-breadcrumbs are not enabled; VIctory prints it as `no breadcrumbs (... 0x887A0004)` in the device-removal report. The actual device removal is `0x887A0006`.

Also, `VICTORY_D3D12_DEBUG=1` enables the D3D12 debug layer/info queue; it does not enable DRED. Breadcrumbs and page-fault data are gated behind `VICTORY_D3D12_DRED=1` in a diagnostics build (`dred_on()` in `host.rs`). That explains why you get “no breadcrumbs” with only `DEBUG` set. If startup also logs `no D3D12 debug layer ... 0x887A002D`, DRED settings can fail too, because they are obtained through `D3D12GetDebugInterface`.

Could you rerun with both:

```powershell
$env:VICTORY_D3D12_DEBUG=1
$env:VICTORY_D3D12_DRED=1

### Comment 2 — @requiemsnkrp — 2026-11-24T14:26:20Z

Same stop on another Ampere card, with an **Nsight Aftermath dump that names it: a page fault in a translated mesh shader**, not a hang.

**Setup:** NVIDIA GeForce RTX 3060 12 GB (GA106, driver 621.24), Ryzen 5 5600X, 16 GB RAM, Windows 11 Pro 26200. VIctory `ffe310e`, `cargo build --release -p victory` (no diagnostics build), no `VICTORY_*` variables, `victory run …\game_scarlett_master.exe --execute`. The title loaded into the world and ran at about 1 fps, then the device was lost.

**`crashes.log`:** the same line as above: `host GPU device removed after a submission of 32 lists; no breadcrumbs (0x887A0004); device removed: … (0x887A0006)`.

**Aftermath** (driver-side global mode, via Nsight Graphics 2026.4's `nv-aftermath-control --mode Global --debuginfo=1 --resource-tracking=1`; the app is not instrumented), decoded with `nv-aftermath-format -j`:
- `Device state: Error_DMA_PageFault`, `Engine reset occurred: true`, `Adapter reset occurred: false`.
- Page fault: `Access Type: Read`, `Client: Graphics Processing Cluster`, `Engine: Graphics`, `Fault Type: Failed to translate the virtual address`, `GPU virtual address: 0x5BFBE9000`.
- Shader: `Shader type: Mesh`, `Shader name: mesh_01`, `Shader size: 21504`, Aftermath shader hash `0x5775541DBBE7F10C`.
- Faulted warp: `MMU Fault Error` ("a shader instruction caused an MMU fault when accessing memory"), `Shader GPU PC Address: mesh_01 @ 0x00002a20`, `Shader mapping: dxil:571`.

So on this card the `0x887A0006` is a mesh shader reading an unmapped address. A buffer address or offset out of range would fit (#542, #584 and #587 are close to that), but I have not matched the program: running `GFSDK_Aftermath_GetShaderHash` over the shader cache would name it. I can do that and post the cache entry's name if useful. The dump is not attached: it holds translated shader code.

**Not tested:** a diagnostics build with `VICTORY_D3D12_DRED=1`; more than one run.
