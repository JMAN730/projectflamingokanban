## Problem

State::tables() (crates/victory-gpu/src/draw.rs) currently copies every descriptor table containing a ResourceType::Cbv into dynamic descriptor slots (and copies its constant data through list.scratch), even when every View::Constant in the table's span is already 256-byte aligned on the host and within host.count().

On capped shader-visible view heaps (1,000,000 views / MIN_DYNAMIC = 65,536 on NVIDIA), world frames record dozens of command lists in parallel before submission and exhaust all 65,536 dynamic slots - dropping **4,096+** draws/dispatches (^G draw or dispatch dropped: no dynamic slots for its tables) even when finished lists' slots are reclaimed (#688).

## Fix (1d21e06)

- **State::tables():** only routes a CBV-bearing table through dynamic slots when some View::Constant(address, size) in its span ..n has size == 0, fails s.gpu(address).is_multiple_of(256), or whose 256-byte-padded size leaves its shadow buffer (in addition to index >= host.count()).
- **eadable():** refreshes the shadow range (shadow.refresh(list, address, size)) for View::Constant mirrored in place, keeping submission-time semantics while avoiding dynamic descriptor and scratch-buffer churn.
- **Test (draw::tests::aligned_cbv_tables_mirror_in_place_without_dynamic_slots):** verifies on a real D3D12 device that a 256-byte-aligned CBV table allocates  dynamic slots, while both a +16-byte misaligned CBV and a CBV whose 256-byte-padded size runs past the shadow buffer's end still fall back to dynamic slots.

### Comment 2 — @MichaelSmithAI — 2026-11-24T12:56:40Z

Melissa verified the bytes seen by a compute shader after recording a dispatch and then changing the guest constant buffer before submission. On RTX 4090 under Wine/vkd3d-proton 3.2, successive dispatches through the aligned CBV read 17 and 29 with zero dynamic slots. The CBV at byte offset +16 read 43 using one dynamic slot.

One interaction with static table entries: when the shader metadata names slots 0 and 2 but slot 1 is also populated, the fresh-table path materializes slot 1. A preparation test on that layout selected zero fresh tables without the extra check and one after preserving the fresh path for the unnamed entry. The integration checks the entire span against its owning heap before scanning and incorporates the unpadded shadow lookup and aligned short-tail case already identified by andrewpozdnakov7-jpg.

### Comment 3 — @alessiodeia — 2026-11-24T13:31:48Z

Thanks @andrewpozdnakov7-jpg and @MichaelSmithAI for the thorough reviews and hardware checks! Both edge cases are now fixed in `alessiodeia/VIctory@8fa463a` on `fix/reuse-aligned-cbv-tables`:

Added a unit test covering a sparse table (slots 0 and 2 named, slot 1 populated and unnamed) confirming dynamic-slot fallback.
