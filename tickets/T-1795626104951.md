### Problem

Under Wine, every indirect execution is dropped. The clamp of indirect arguments (`crates/victory-gpu/src/indirect.rs`) is HLSL compiled at run time with `D3DCompile`, and Wine's `d3dcompiler_47` (vkd3d-shader's HLSL compiler) refuses it:

```
WARN victory_gpu::indirect: argument clamp: clamp:19:27: E5005: Method 'Load' is not defined on type 'RWByteAddressBuffer'.
```

`indirect::bound` then returns false for every record and `execute_indirect` reports `not bounded (no clamp, or arguments not 4-byte aligned)`. In the world that is most of the frame: in one run here, per world frame on average, 1,449 mesh dispatches (kind 10), 776 dispatches (kind 2), 285 draws (kind 0) and 79 indexed draws (kind 1) were dropped for that reason alone. I found no issue or PR that mentions it; anyone testing under Wine or Proton with the builtin compiler has it.

Wine's compiler has a second gap that the first one hides: it ignores the `RootSignature` attribute (`W5302: Ignoring unknown attribute "RootSignature"`), so the compiled blob has no `RTS0` part and `CreateRootSignature` from the shader bytes would fail next.

### Change

One file, the clamp only:

- `args` and `budget` are `RWStructuredBuffer<uint>` instead of `RWByteAddressBuffer`, indexed in words. `bound` already refuses addresses and strides that are not multiples of 4, so the same words are read and written. A root descriptor can be a structured buffer.
- The root signature (4 root constants at b0, root UAVs u0 and u1) is serialized with `D3D12SerializeVersionedRootSignature` beside the shader, as `pipeline/host.rs` does for its own, instead of being read from the shader blob.
- The bounds, the budget and the `InterlockedAdd` on it are unchanged.

### Testing

RTX 5070 Ti, driver 615.78.08, Nobara 44, Wine 11.21 Staging, vkd3d-proton and DXVK `dxgi.dll` from GE-Proton11-14, diag build cross-compiled on Linux, Series X 1.0.2.1, network off.

- The new source compiles with `D3DCompile` (`cs_5_1`) from both Wine's builtin `d3dcompiler_47` and Microsoft's (a small test program, run under Wine with and without the native DLL). The old source compiles only with Microsoft's.
- In the title (tree: `ffe310e` + #454 #177 #259 #233 #646 #578 + the #783 fallback), one 450 s run each:

| | old clamp, Wine's compiler | old clamp, Microsoft's `d3dcompiler_47.dll` beside the exe | this change, Wine's compiler |
|---|---|---|---|
| `argument clamp` warning | yes | no | no |
| `not bounded` drops | every indirect record | none | none |
| host pipelines created in the run | 618 | 1,063 | 782 |

  With the clamp in place the next reasons for dropped indirect work are pipelines still being made, wave64 mesh programs refused by #578 on this 32-lane host, and shaders that do not translate.
- `cargo clippy -p victory-gpu --all-targets --all-features --locked -- -D warnings` (target `x86_64-pc-windows-msvc`) is clean.

**Not tested:** native Windows (the pipeline is created through vkd3d-proton in all three columns, so D3D12's own check of a structured-buffer root UAV against this shader is not exercised), AMD, `cargo test` (the existing `argument_clamp_builds` test covers this path on a machine with a GPU), and the clamped values themselves beyond the title running with them.

A workaround without this change: put Microsoft's `d3dcompiler_47.dll` next to `victory.exe` and add `d3dcompiler_47=n` to `WINEDLLOVERRIDES`.
