## Original body

`crates/victory-gpu/src/list.rs:1169` matches `([[kind, ..]], Some(address))`, which is exactly one argument. A signature with more than one argument (for example root constants or a root view per record, then a draw or dispatch) is counted and dropped. It logs "indirect execution dropped (first time for this signature)".

**Suggestion:** build host command signatures for the root-constant and root-view arguments as well, mapped onto our root signature's parameters.

Testers: the `args` field of those log lines shows which signatures the world uses.

_AI use: found and written with Claude from reading the code at `8e79c80`; not run on hardware._

Branch ready on fork (since PR creation is currently collaborators-only): https://github.com/MartinIndra02/VIctory/tree/feat/gpu-multi-arg-execute-indirect (commit `71967c1`, based on `main` `ffe310e`).

### What it implements
- **`crates/victory-gpu/src/indirect.rs`**:
  - Uses the existing 4th dword of `cbuffer Record` (`arg_offset`) so the GPU argument clamp bounds the trailing Draw / DrawIndexed / Dispatch / DispatchMesh arguments at `id.x * stride + arg_offset` without disturbing preceding root constants.
  - Adds `plan_indirect()` to map single-argument signatures and multi-argument signatures whose prefix arguments are `D3D12_INDIRECT_ARGUMENT_TYPE_CONSTANT` onto the bound `HostPipeline`'s `user_data` root-constant parameters (checking contiguity, bounds, collisions with other `UserData` entries, and cross-stage sharing; unused constants land in an unoccupied contiguous `user_data` range when available, otherwise the signature is cleanly dropped).
  - Non-constant prefix arguments that carry console GPU virtual addresses (vertex/index buffer views, root CBV/SRV/UAV) are still cleanly rejected rather than passing untranslated console addresses to the host.
- **`crates/victory-gpu/src/pipeline/host.rs` & `draw.rs` & `list.rs`**:
  - Passes full `args` from `list.rs` into `State::execute_indirect`, creates and caches multi-argument host `ID3D12CommandSignature`s against `p.root` on `HostPipeline`, and keeps the signature alive on the host list until reset.
