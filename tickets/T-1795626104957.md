## Problem

`victory-gpu/src/texture.rs`: "shortcut: a change detiles the whole texture, not the pages written." When one 64 KiB page of a title texture changed, the whole memory was read back (watched memory) or hashed as one, and then every mip and slice was detiled again. A streamed texture filling page by page paid that full cost at every submission that sampled it.

## Change

- **`Layout::extents(mip, slice)`** (`victory-formats`): the tiled byte ranges a subresource is detiled from. There is one range per depth slice or slab, merged. Tail mips get the part of the tail block they span.
- **Watched memory**: after the first detiling, only the pages written since the last asking are read again into the kept copy.
- **Hashed memory**: one hash per 64 KiB page instead of one for the whole texture.
- **Both**: only the subresources whose extents overlap a changed page are detiled.
- **Unchanged**: the first detiling is still whole, and so is every subresource's copy into the host texture.

## Tests

- **`extents_hold_what_a_subresource_detiles`** covers 9 layouts: tiled S/D at 256 B, 4 KiB and 64 KiB, linear, mip tails, arrays and 3D. It checks four things:
  - every element is inside its extents;
  - flipping every byte outside them leaves the detiled result unchanged;
  - ranges are sorted and disjoint;
  - a 2D mip outside the tail spans no more than its own blocks.
- **`texture::tests`**: overlap, changed pages and page-to-range conversion.

## Checked / not checked

- `cargo test -p victory-formats` passes, run on macOS.
- `cargo clippy -p victory-formats -p victory-gpu --all-targets [--all-features] --target x86_64-pc-windows-msvc -- -D warnings` is clean. Locally I needed blake3's `pure` feature, because there is no Windows C compiler here.
- **Not run on Windows, and not measured in the game.** The `texture::tests` unit tests and the GPU path have not been executed. The gain depends on how much frame time goes into detiling.
- **Known edge:** a page that is decommitted without being written can leave stale bytes in the kept copy. The existing code had the same gap, but a full re-read sometimes hid it.
