## Original body

Under Wine/Proton, `indirect::clamp()` returns `None`, so every indirect draw and dispatch is dropped ("no argument clamp: indirect execution dropped"). #128 lists the failing test as an environment gap; this issue is about the runtime consequence and what does and does not fix it.

### Environment

`main` at `d2a4bae`, cross-built for `x86_64-pc-windows-msvc` on Linux Mint, Proton 10.0 (wine-10.0 with its builtin `d3dcompiler_47`, vkd3d-proton), NVIDIA RTX 5090, driver 595.99.2.

### What fails

`indirect::tests::argument_clamp_builds` fails: `D3DCompile` of `SOURCE` in `crates/victory-gpu/src/indirect.rs` is rejected with `E5005: Method 'Load' is not defined on type 'RWByteAddressBuffer'` (as reported in #128).

### What I tried: the same shader on indexed buffers

I rewrote the clamp to use `RWStructuredBuffer<uint>` for both buffers (indexing instead of `Load`/`Load3`/`Store*`, and the free function `InterlockedAdd(budget[0], ...)`). Wine's compiler answers:

```
clamp:11:1: W5302: Ignoring unknown attribute "RootSignature".
clamp:23:6: E5017: Aborting due to not yet implemented feature: Structured buffers store is not implemented.
```

So two separate things are missing there, and no rewrite of the HLSL gets around both:

1. **No store to a raw or structured buffer.** Byte-address methods are undefined and structured stores are unimplemented. Typed `RWBuffer` stores may work, but a typed buffer cannot be a root descriptor, so that would mean a descriptor table and a heap of our own in the middle of the title's list.
2. **The `[RootSignature]` attribute is ignored.** Even a shader that compiled would carry no root signature, and `CreateRootSignature(0, bytes)` on the shader blob would fail.

### Options

- **Workaround today:** a native Microsoft `d3dcompiler_47.dll` in the prefix (not tested here; I don't have one in this setup).
- **A fix that does not depend on the system compiler:** build the clamp's DXIL with the shader crate's own writer, the way `emit::host::stub_vs` builds its vertex shader, and create the root signature from a description in code. vkd3d-proton already takes the DXIL this project emits. It would also drop the runtime dependency on `d3dcompiler_47.dll` on Windows.

I am willing to do the second one if that direction is wanted; it is a moderately sized change (the clamp has branches, raw buffer loads and stores, and an atomic add), so I would rather ask first than send it unannounced.

No game data used. AI-assisted (Claude Code).

The "no rewrite of the HLSL gets around both" part turns out to depend on the Wine version. I tried the same rewrite and it works on Wine 11. It doesn't on Proton 10, which matches what you saw.

The rewrite: `RWStructuredBuffer<uint>` for both buffers with plain indexing, the free function `InterlockedAdd(budget[0], ...)`, and the root signature built in code through `pipeline::host::root_signature`, since the `[RootSignature]` attribute is ignored.

| Compiler | Original shader | Rewrite |
|---|---|---|
| Proton 10.0 (UMU-Proton-10.0-4) | E5005 | E5017, "Structured buffers store is not implemented" |
| Wine 11.22 | E5005 | compiles |
| GE-Proton11-14 | E5005 | compiles |
| Microsoft's d3dcompiler_47 | compiles | compiles |

On GE-Proton11-14 (RX 6900 XT, RADV 26.2.6, the vkd3d-proton it ships) `argument_clamp_builds` passes with the rewrite. I also added a test that runs the clamp on the GPU and reads the records back. It checks that draw counts are cut to the bounds, that a dispatch over the group limit comes back empty, and that when three draws together go over the budget one of them is emptied. That passes too.

So structured buffer stores must have landed in Wine's compiler somewhere between 10 and 11. The byte-address methods and the attribute are still missing in 11.

Which gives a third option besides #178 and #190: +84 -18 in `indirect.rs`, test included, without DXC and without more DXIL to maintain. The cost is that Proton 10 still gets no indirect execution. #190 is the only one of the three that doesn't care what the host's compiler can do. I ran it here as well, merged onto d2a4bae: the clamp test passes, its two new tests pass, nothing else in the workspace moves.

I can open a PR with the rewrite if you'd rather take that trade. Otherwise I'd go with #190.

I didn't use any game files for this, only the test suite.

### Comment 3 — @crashbashash — 2026-11-24T13:13:39Z

Tested the native-compiler workaround mentioned above: it works, no code change needed.

**Setup:** CachyOS (kernel 7.3.4), RX 6800 XT (RDNA2, RADV, Mesa 26.2.6), GE-Proton11-14 (vkd3d-proton `cae8353ed`), `main` at `ffe310e`, diagnostics build cross-compiled with cargo-xwin, Series X, 1.0.2.1.

**Before**, with Proton's builtin `d3dcompiler_47`:
```
WARN victory_gpu::indirect: argument clamp: clamp:19:27: E5005: Method 'Load' is not defined on type 'RWByteAddressBuffer'.
WARN victory_gpu::indirect: no argument clamp: indirect execution dropped
```
Every indirect kind (0, 1, 2, 10) was dropped as `not bounded (no clamp, or arguments not 4-byte aligned)`.

**Workaround:**
```sh
WINEPREFIX=<prefix>/pfx WINE=<proton>/files/bin/wine winetricks -q d3dcompiler_47
```
This installs Microsoft's DLL (FileVersion 10.0.17134.12) and sets `d3dcompiler_47=n`. If you start `victory.exe` with `proton runinprefix`, Proton applies none of its DLL overrides, so set them yourself:
`WINEDLLOVERRIDES="d3d9=n;d3d10core=n;d3d11=n;dxgi=n;d3d12=n;d3d12core=n;d3dcompiler_47=n"`

**After:** the clamp builds, and the `E5005` / `no argument clamp` lines are gone. Nothing is dropped for a missing clamp any more. The remaining indirect drops are `prepare failed`, while a pipeline is still being built or its shaders don't translate. Signatures that change root arguments are still dropped, as on Windows (#757).

The scene is still dark, as on Windows: 260 compute shaders didn't translate in that run.

This only matters until #178, #190 or the clamp in #844 lands. With any of those, nothing needs installing.

No game data used. AI-assisted (Claude Code).
