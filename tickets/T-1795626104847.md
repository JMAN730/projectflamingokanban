## Original body

**Environment**
- VIctory commit: ffe310e (release and `--profile diag --features diagnostics` builds)
- GPU: NVIDIA GeForce RTX 2070 (8 GB), driver 32.0.16.2124
- CPU/RAM: Intel Core i7-11700KF, 32 GB
- OS: Windows 11 Pro 10.0.26300
- Title: GTA VI (Xbox Series build), run with `victory run <exe> --execute`
- Network disconnected during the tests (the title also tries to upload crash reports).

**What happens**
The game reaches the menus and loading screen at ~30 fps with sound. When the intro videos start, the frame rate drops to 0, the window goes black, and a few seconds later VIctory exits with:

    host GPU failure: host GPU device removed after a submission of 28 lists ... (0x887A0006)
    debug layer: DXGI_ERROR_DEVICE_HUNG (TDR triggered)

Windows logs nvlddmkm event 153 at the same moment. Raising TdrDelay to 10 s did not change the result.

**Diagnostics build with VICTORY_D3D12_DEBUG=1 and VICTORY_D3D12_DRED=1**
The breadcrumbs show all lists finished except one:
`a list stopped at command 4 of 11 (op 6)` (commands 0..7 between barriers: op 46, 6, 6, 6, "no marker").
The log does not describe the commands of that 11-command list, so I cannot tell which shader it runs. It would help if the failure message named the pipeline hash of the stopped command.

**What I tried**
1. Earlier (before the newest fixes), the same hang appeared in a mesh-shader draw in the world (`DispatchMesh`, op 42, stopped at command 177 of 200). Candidate mesh pipelines in that frame: 6eb61098d0009b93, 43c92378a1d4222d, 04b9be3756e8f41c.
2. With `VICTORY_SKIP_PIPELINES` listing those three, the hang moved earlier, to the 11-command list above.
3. Adding 9146291b38ea9ce1 and 65e969746fffdb7d to the skip list did not move it: the stopped list is still "command 4 of 11 (op 6)" in two consecutive runs. So I believe my earlier guess about these two hashes was wrong.
4. Failures across many runs happen after 11-33 submitted lists, in the same area.

**Possibly related**
Wave size: NVIDIA runs 32-lane waves, while the console shaders assume 64. I did not see this mentioned in the recent shader commits (waterfall loops / per-lane descriptors), so I am not sure whether a 32-lane path is handled for this case.

**Questions**
- Is NVIDIA (32-lane) currently expected to work, or is the project AMD-only for now?
- Is there a way to make the failure message print the pipeline hash of the stopped command, or a switch to run those dispatches one by one with a fence to isolate the culprit?
- I can attach the crashes.log entries, the dump from the temp folder and the pipeline cache listing if useful. I will not share any game files.

Thanks for the project; happy to test patches on this hardware.
