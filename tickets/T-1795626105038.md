## Windows 11 / RTX 5070 and Radeon iGPU — synthetic D3D12 wave tests

I ran synthetic D3D12 tests on an RTX 5070, the integrated Radeon GPU
and Microsoft WARP. The tests cover device capabilities, pipeline
creation and compute shader execution with GPU buffer readback.

### Test environment

- OS: Windows 11 Pro 26H2, build 26300.9974
- CPU: AMD Ryzen 7 7800X3D, 8 cores / 16 threads, AVX2 available
- RAM: 30.61 GiB visible to Windows
- NVIDIA GPU: GeForce RTX 5070, driver 621.40
- Integrated GPU: AMD Radeon Graphics, driver 32.0.21045.29003
- Software adapter: Microsoft WARP
- Rust: 1.98.1, x86_64-pc-windows-msvc
- Windows SDK: 10.0.26100.0
- DXC: 1.9.2602.17
- VIctory base revision: `ffe310eb2098e52169f4c44db5ffdabf43a72622`
- Tests: local changes based on that revision
- Test data: original synthetic HLSL shaders

### 1. Device capabilities and pipeline creation

Each adapter was opened explicitly through DXGI. The probe queried
the shader model, wave lane range and mesh shader tier, then tried
to create SM 6.6 compute and mesh pipelines.

| Adapter | Shader model | Wave lanes | Mesh tier |
| --- | --- | --- | --- |
| RTX 5070 | 6.8 | 32–32 | 1 |
| Radeon integrated GPU | 6.8 | 32–64 | Not supported |
| Microsoft WARP | 6.8 | 4–4 | 1 |

| Adapter | Default compute | Wave32 | Wave64 | Mesh |
| --- | --- | --- | --- | --- |
| RTX 5070 | Created | Created | Rejected | Created |
| Radeon integrated GPU | Created | Created | Created | Rejected |
| Microsoft WARP | Created | Rejected | Rejected | Created |

The rejected pipeline creations returned `0x80070057` (`E_INVALIDARG`).

The RTX 5070 accepted the Wave32 compute pipeline and rejected the
Wave64 pipeline. Its reported wave lane range was 32–32. The
integrated Radeon reported 32–64 and accepted both compute variants.

This test only created pipeline state objects. It did not submit
GPU commands.

### 2. Compute execution and buffer readback

A second test dispatched an original SM 6.6 compute shader.
Each dispatch used one group of 128 threads. Every thread wrote:

- its reported wave width;
- its lane index;
- the result of `WaveActiveSum`;
- the result of `WavePrefixSum`.

The test read the buffer back and checked each thread's values.
Fixed wave sizes outside the adapter's advertised range were skipped.

| Adapter | Shader variant | Observed width | Verified records |
| --- | --- | --- | --- |
| RTX 5070 | Default | 32 | 128 |
| RTX 5070 | Wave32 | 32 | 128 |
| Radeon integrated GPU | Default | 32 | 128 |
| Radeon integrated GPU | Wave32 | 32 | 128 |
| Radeon integrated GPU | Wave64 | 64 | 128 |
| Microsoft WARP | Default | 4 | 128 |
| Microsoft WARP | Wave4 | 4 | 128 |

All seven dispatches passed. The test verified 896 thread records
in total.

As a negative control, I supplied the Wave32 shader in place of
the Wave64 fixture on the Radeon. The test failed as expected
because it observed 32 lanes where the fixture required 64.

### 3. VIctory shader test suite

After adding the readback test, the ordinary `victory-shader` suite
reported:

- 120 passed;
- 0 failed;
- 2 ignored.

The new readback test is ignored during the ordinary suite and was
run separately on each of the three adapters. Four existing
console-compiler-dependent tests returned early because the console
compiler was unavailable.

Strict Clippy for `victory-shader` with all features passed.
The repository asset-policy check also passed.

### Scope and reproducibility

The readback test uses native PC DXIL compiled from synthetic HLSL.
It verifies D3D12 wave operations and buffer readback on these
adapters. It does not establish how translated game shaders behave.

The local readback test commit is `b885020`. Its patch was checked
for clean application against base revision `ffe310e`. The patch
and reproduction instructions are currently local and can be shared
if useful.

No game files were used for these tests.
