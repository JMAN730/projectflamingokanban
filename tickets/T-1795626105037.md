## Black world after loading on NVIDIA: measurements, a ranked list of hypotheses, and a research dossier

This issue collects what we measured on one NVIDIA machine and ranks the hypotheses that follow from it, so other
contributors can test them and report back. A long research dossier with the background, the literature and the
reasoning behind each hypothesis is linked at the end.

**Our setup:**
- RTX 3080 10 GB, i5-10400F, 32 GB DDR4, Windows 11.
- Our own retail copy of the title (`b99f876b…`, Xbox Series 1.0.2.1).
- Diag builds of `main` from 24 Nov, plus open PRs #89, #189, #211, #282, #493, #530 and #587, plus our own local changes listed in each section.

No game data is included here or in the dossier.

### 1. What we measured

| Observation | Evidence |
|---|---|
| **Series S profile halves GPU time** | `--console series-s` on the same build: 2,699 → 1,898 ms/frame; GPU 1,512 → 701 ms; internal resolution 1280x720. On a 10 GB card the Series X profile (4K targets, 13.5 GiB title memory) is the wrong target. |
| **Frame cost is mostly CPU coherence work** | Series S, world: `preparing` ~860 ms (copies ~270 MB ≈ 440 ms; texture checks ~475 MB ≈ 140 ms), GPU ~700 ms, `copying back` ~330 ms for ~12 MB. |
| **The G-buffer is drawn; lighting is not** | Target dump at a world frame (229 targets): G-buffer colour, normal and mask targets show picnic tables, a street lamp, pedestrians and power lines. Every lighting/HDR target (DXGI formats 10, 26, 42 and 61 at 1280x720) is all zero, and the final 1920x1080 output is uninitialised. This matches #638 and the RTX 5090 report in #71. |
| **Untranslated shaders, 627 → 430 with local changes** | 627 → 520: raw view of the view-descriptor heap for "descriptor read only as data". 520 → 450: spilled user data (compute past 16 user SGPRs, graphics past 32) and wave-uniform `v_readfirstlane` in divergent flow. 450 → 430: raw root UAVs and 64-bit addresses held in root constants. |
| **Remaining refusals in our build** | "select on an untracked mask" 77; "lane mask holding lanes elsewhere read as data" 68; "cross-lane wave operation in divergent control flow" 60; "structured buffer of unknown stride" 41; "v_readfirstlane in divergent control flow" 37; "address not from a root parameter" 29. |
| **Hang pair** | DRED stops at `mesh 04b9be3756e8f41c` + `pixel 1af4a50c7fb40c97`, as in #71. The mesh program has no loop. The pixel program has nested light-list loops; the outer one exits on an *equality* between an index and a bound read from a buffer. |
| **Loop caps** | 1,024 iterations on pixel, mesh and vertex stages only: no device removal for 17+ minutes, and the gameplay HUD ("Move / Move camera") appears over the black world. #493 alone did not prevent the hang on this machine. |
| **Loading-time crashes** | Every run that invalidated or bypassed the shader cache (changed loop limits) crashed at `+0x164a298`, with a stack through the title's watchdog thread (`+0x2215eca`). |

### 2. Top hypotheses (P0/P1)

The IDs refer to the dossier. "Test" says how to confirm or refute each one with VIctory's log line or a target dump.

| ID | Hypothesis | Test |
|---|---|---|
| **H-6.14** | `ID3D12CommandQueue::Wait` is a no-op (`queue.rs`, `wait` returns `S_OK`), and `ExecuteCommandLists` runs synchronously when called. A consumer queued behind `Wait(fence, N)` therefore runs **before** the producer that another queue submits later and that signals `N`. It reads unwritten data, which gives black lighting targets and loops on invalid bounds (hangs). The XCL author independently reported the same mechanism. | Defer a queue's later submissions until the awaited fence value is reached; flush them when it is signalled. Run without loop caps and dump world targets. |
| **H-6.13** | Loading-time crashes are the title's watchdog firing while shaders translate on a cold cache. | Fill the cache with a fixed configuration, then repeat it. Long term: translate asynchronously. |
| **H-6.7 / H-6.8** | The remaining hangs are consumers of producers that did not run: dropped or out of order. Zero-filling what a dropped producer would have written makes equality loops exit. | `VICTORY_PRODUCERS=1` from #638, a map of reader and dropped producer, then zero-fill. |
| **H-6.1 / H-6.2** | Materialise SGPR lane masks as 64-bit integers (ballot at definition, integer ALU when combined, bit test at use). This removes "select on an untracked mask" and "lane mask … read as data" (~145 shaders, mostly lighting/culling compute). | Recount refusals; dump targets; lighting targets become non-zero. |
| **H-6.3** | DPP row, quad and `permlane16` operations never cross lane 32, so they need no barrier and are legal in divergent flow. | Log refusals by operation kind, then implement. |
| **H-6.4 / H-6.5** | #704 (raw view for unknown strides) and the waterfall-loop work now on `main` cover part of the remaining refusals. | Rebase and recount. |
| **H-1.1 / H-2.6** | Series S as the default on GPUs with ≤ 12 GB, and DXGI modes that match it (`dxgi.rs:246` is fixed at 3840x2160). | Confirmed for GPU time; check VRAM with `QueryVideoMemoryInfo`. |
| **H-2.1 / H-1.2** | Copy disjoint dirty ranges instead of one `[min, max]` union per shadow (`host.rs` `Batch::add`). Replace in-process `ReadProcessMemory`/`WriteProcessMemory` with guarded direct copies. | `copies` MB and ms drop several-fold. |
| **H-1.5 / H-2.2** | Validate textures by page generation instead of re-hashing after every step (`host.rs` `title_written` clears the per-batch texture set). | `textures` ~475 MB → a few MB per frame. |
| **H-2.3 / H-7.6 / H-7.7** | Classify buffers (GPU-only vs read by the CPU); copy back only what the CPU reads, lazily through read guards. | `copying back` ~330 ms → near 0. |
| **H-8.1 / H-8.2** | Occlusion queries always report "visible" (`list.rs`, `1 << 20`) and GPU timestamps are CPU time. The title's own culling and dynamic resolution cannot work. | Real query heaps; measure overdraw and resolution changes. |

### 3. Suggested order of experiments

1. Warm-cache protocol (H-6.13), so later runs are comparable.
2. Honour queue waits (H-6.14); run without loop caps; dump targets.
3. Merge #638, then build the producer map (H-6.7); zero-fill the missing producers (H-6.8).
4. Rebase on `main` + #704; then masks as values (H-6.1/H-6.2) and intra-half cross-lane operations (H-6.3).
5. Coherence work for speed: disjoint ranges, page generations, lazy copy-back (H-2.1, H-1.5, H-2.3).
6. Real queries and timestamps (H-8.1, H-8.2).

Success criterion for the black screen: in a target dump of a world frame, at least one lighting/HDR target and the final
output contain scene content.

### Comment 8 — @HenriqueSBueno — 2026-11-24T19:47:12Z

@rpmaster2 thanks, reaching the prologue in 13 minutes is the furthest data point in this thread. I added it to the dossier as confirmation that the Series S profile works once the front end gets dense enough input.

On the new removal shape (`page fault at 0x1a93cc000; no title memory copy below it`): an address below every title copy looks like a GPU read through a pointer or descriptor that was never filled, rather than through a stale copy. That fits a consumer running before its producer (H-6.7/H-6.14). On our RTX 3080 the title held work behind command-list 64-bit memory waits 32+ times in ~5 minutes once #1388 was applied, so adding #1388 to your stack may change or remove this shape. If you try it, the `held=` counter we described on #1388 would show whether those waits fire on AMD as well.

For readers tracking the hypotheses: `fxceless/victory-gta6` (see @luisaugustz's report in #71) has since implemented several of them behind switches and reports a lit opening cutscene and a rendered prologue on an RTX 4070:
- in-place title memory as a graphics heap (`VICTORY_INPLACE`, H-2.4/H-4.x);
- submissions sent ahead of the GPU wait with a relay thread (`VICTORY_LATE_WAIT`, `VICTORY_RELAY`, H-7.1);
- large title buffers copied to card memory with GPU-side write detection (`VICTORY_CARD_BUFFERS_*`, H-1.3/H-2.1);

Its README lists ray-traced bounce light and shadows as the remaining gap (anything not directly sunlit is black), which matches the BVH discussion in #1533. We'll update the dossier's hypothesis matrix with these as "implemented elsewhere" so measurements can be compared.
