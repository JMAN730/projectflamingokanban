### RX 6750 XT on Windows 10 22H2: SM 6.6 root signatures refused by the inbox D3D12 runtime (fixed with Agility SDK), then GPU hang ~2 min into the intro

## Setup
- GPU: AMD Radeon RX 6750 XT (RDNA2), driver 32.0.21045.29003 (2026-11-17)
- CPU: Intel Core i7-9700K · RAM: [XX] GB
- OS: **Windows 10 Pro 22H2 (19045)**, inbox `d3d12.dll` 10.0.19041.5794
- Build: `main` @ [commit hash, `git rev-parse --short HEAD`], plain release profile (`cargo build --release -p victory`), no extra PRs
- Language: French (Game Locale EU / SKU ROW)

## 1. Crash at boot on main (Windows 10 only)

On plain `main`, the title crashes about 5 s after launch, right after `XUserAddAsync: the offline local user`, before the menus.

Just before the crash, several menu pipelines are refused:
```
root signature: Unsupported bit-flag set (root signature flags c01).
host root signature refused error=Paramètre incorrect. (0x80070057)
```
Then two threads fault at the same place:
```
unhandled exception 0xc0000005 at victory-image-….dll+0xb5a5f8 (read 0x68: nothing mapped there)
```
Frames before the crash show `drawn=0`.

**Cause:** flags `0x400 | 0x800` (`CBV_SRV_UAV_HEAP_DIRECTLY_INDEXED`, `SAMPLER_HEAP_DIRECTLY_INDEXED`) need SM 6.6 binding. The Windows 10 inbox runtime does not support them, and the README tests only Windows 11.

**Workaround (local patch):** export the Agility SDK markers from `victory.exe` and put `D3D12Core.dll` (Agility SDK 1.620.2) in `target\release\D3D12\`:
```rust
#[unsafe(no_mangle)] #[used] pub static D3D12SDKVersion: u32 = 620;
#[unsafe(no_mangle)] #[used] pub static D3D12SDKPath: SdkPath = SdkPath(b".\\D3D12\\\0".as_ptr());
```
plus a `build.rs` with `/EXPORT:D3D12SDKVersion,DATA` and `/EXPORT:D3D12SDKPath,DATA`.

With this patch, no root signature is refused, every queued draw is executed (`drawn=3328`), and the menus run at 30 fps. Happy to open a PR if this approach is wanted. The DLL would not be committed, per the asset policy.

## 2. World: intro then GPU hang

With the patch, the title loads the world and plays the story intro: credit titles, French subtitles, the crocodile title art. It runs at about 1 fps (1,000–1,500 ms/frame, 1,100–2,800 draws/frame). The 3D scene is missing or dark. Subtitles and credits overlap, probably crossfades caught at 1 fps.

After about 2 minutes in the world, the device is removed:
```
host GPU device removed after a submission of 11 lists; no breadcrumbs (0x887A0004);
device removed: … (0x887A0006)
```
Just before it, these shaders fail to translate:

| Reason | Shaders |
|---|---|
| a scalar memory read as data | pixel `73644c6a0b7b5b35`, mesh `d6c491e1d17d60cb` |
| a descriptor read only as data | compute `cdfefd6c8bb5dddd`, `3a59b63b97ad1abd` |
| a lane mask holding lanes elsewhere read as data | compute `5f8cf29b763648eb` |

## 3. DRED (diag build, local-perf: main + #693 #388 #69 #617 #357 #151 #298, per-list submission from #458)

Every run ends in a device removal ~2 min into the world, at a DispatchMesh whose user data points at unpopulated heap slots:

- Run 1: list stopped at command 422/606, command 419 `mesh 1 [mesh a56a584996afb040, pixel 5630e9f88a7bf24d]`: `u9=0x1356240 [heap 633618: null]`, `u10=0x13560c0 [heap 633606: null]`. That list took 2,371 ms.
- Run 2 (`VICTORY_SKIP_PIPELINES=a56a584996afb040`): list stopped at command 397/505, command 396 `mesh 1 [mesh ba8d52f4ea1a1bac, pixel b37565055f2f7d3b]`: `u8 [heap 333792: null]`, `u9 [heap 395855: null]`, `u10 [heap 395843: null]`.

Skipping one pipeline moves the fault to the next mesh draw that reads null slots, which looks like the same class of fault as #743.
