### Technical Details for All Newly Identified Findings

#### 1. `VIC-BT-001` — Host::execute() clobbers HostList::prelude command allocator/list when the same HostList appears twice in runs (`P0`)
- **Location:** `crates/victory-gpu/src/host.rs` lines `504-511, 582, 931-963`
- **Prior-Work Check:** 0% overlap across Marvisak_VIctory (0 hits for list.prelude() clobbering on duplicate list in runs).
- **Root Cause:** In crates/victory-gpu/src/host.rs (lines 504-511), Host::execute() iterates `for list in runs`, calls `list.prelude()`, and pushes the returned ID3D12CommandList into `lists` before calling `self.queue.ExecuteCommandLists(&lists)` at line 532. Each HostList owns only a single reusable `(prelude_allocator, prelude_list)` pair, and HostList::prelude() (lines 931-963) unconditionally calls `allocator.Reset()` and `list.Reset()` before recording barriers and closing it. If `runs` contains the same HostList twice (e.g., `[L, L]` or `[L, M, L]`), the second `list.prelude()` resets the allocator and command list while the first occurrence's COM pointer is still sitting in `lists[]` awaiting ExecuteCommandLists. Both entries in `lists[]` now point to the second prelude's barriers (and the first prelude's barriers are lost, leaving textures in the wrong D3D12 resource state for the first execution of L).
- **Edge-Case / Verification Note:** Verified at host.rs:582 that VIctory explicitly anticipates duplicate lists in a single submission ('a submission may name a list twice'). Also verified that prelude() returns a clone of the same underlying ID3D12CommandList COM object (`self.prelude_list.cast().ok()`) after resetting `self.prelude_allocator`.
- **Synthetic Reproducer:** Record a closed command list L that transitions texture T from COPY_DEST to RENDER_TARGET and draws. Submit `[L, L]` in one ExecuteCommandLists call while T starts in COMMON. The first list.prelude() records COMMON->COPY_DEST into prelude_list; the second list.prelude() resets prelude_allocator/prelude_list and records RENDER_TARGET->COPY_DEST. ExecuteCommandLists executes `[prelude_list, L, prelude_list, L]`, attempting RENDER_TARGET->COPY_DEST when T is actually in COMMON.
- **Proposed Fix & Risk:** - **Fix:** Allocate preludes from a per-submission pool on Host (or split `runs` into separate ExecuteCommandLists batches whenever a HostList pointer repeats in `runs`) so two queued entries in `lists[]` never alias the same underlying prelude allocator/command list.
- **Regression Risk:** Low; splitting on duplicate HostList pointers (or pooling prelude lists on Host) preserves exact barrier ordering with zero overhead in the common non-duplicate case. (Estimated size: `M`)

#### 2. `VIC-BT-002` — SSA construction inserts NONE (Value(u32::MAX)) into phi.args for unreachable predecessors, panicking remove_trivial_phis in release builds (`P0`)
- **Location:** `crates/victory-shader/src/ir.rs` lines `139-143, 198, 217-264, 343-352, 594-601`
- **Prior-Work Check:** 0% overlap across all 3,661+ records in Marvisak_VIctory (issues_and_prs.json, pulls.json, issue_comments.json, review_comments.json); checked remove_trivial_phis, unreachable phi, NONE phi, u32::MAX phi.
- **Root Cause:** In crates/victory-shader/src/ir.rs, leader discovery (lines 139-143) creates basic blocks for instructions immediately following s_branch/s_endpgm, and link() (line 198) populates block.preds from ALL blocks including unreachable ones. However, reverse_postorder(), liveness(), and SSA renaming (lines 217-264, 343-352) visit only blocks reachable from block 0. Consequently, outs[unreachable_pred] remains empty, so when filling phi.args for a reachable merge block that has an unreachable predecessor in block.preds, lookup(&outs[p], phi.reg) returns NONE (Value(u32::MAX)). In debug builds this trips debug_assert! at line 261; in release builds NONE flows into remove_trivial_phis() (lines 594-601), which indexes replaced[v.0 as usize] with u32::MAX and panics with an out-of-bounds slice index.
- **Edge-Case / Verification Note:** Checked whether link() or split_blocks() prunes unreachable blocks before SSA construction: neither does, and reverse_postorder() is only computed inside ssa() without filtering block.preds. Because AMD's console shader compiler frequently emits unreachable padding/tail blocks or dead jump-table fallthroughs before reachable labels, reachable merge blocks legitimately inherit unreachable predecessors in block.preds.
- **Synthetic Reproducer:** Construct a GFX10 shader where block 0 unconditionally jumps via s_branch to block 2 (a merge block using s0), while dead block 1 (immediately after s_branch) writes s0 and falls through to block 2. Call ir::build() in release mode: block 2 gets a phi for s0 with preds [0, 1], outs[1] is empty, phi.args receives NONE (Value(u32::MAX)), and remove_trivial_phis panics indexing replaced[u32::MAX as usize].
- **Proposed Fix & Risk:** - **Fix:** Filter unreachable predecessors out of block.preds (or prune unreachable blocks from the CFG / skip preds with rpo[p] == usize::MAX when inserting and populating phis) before SSA renaming and phi placement in ir.rs.
- **Regression Risk:** Low; pruning unreachable predecessors from CFG edges and phi operand lists strictly restores SSA invariants without affecting reachable control flow. (Estimated size: `S`)

#### 3. `VIC-BT-003` — create_list() and create_list_x() ignore the pInitialState pipeline parameter, dropping initial draws/dispatches (`P0`)
- **Location:** `crates/victory-gpu/src/list.rs` lines `160-230, 261-277`
- **Prior-Work Check:** 0% overlap across Marvisak_VIctory (0 hits for pInitialState, create_list pipeline, create_list_x pipeline, new_list pipeline).
- **Root Cause:** In crates/victory-gpu/src/list.rs, both create_list() (line 165: `_pipeline: This`) and create_list_x() (line 187: `_pipeline: This`) discard the pInitialState parameter and call new_list(), which initializes `state: Default::default()` (line 227) with `pipeline: null`. By contrast, reset() (line 272) properly calls `state.reset(pipeline)` to bind the initial pipeline state. Per D3D12 specification, CreateCommandList opens the command list with pInitialState already bound (if non-null), just like Reset.
- **Edge-Case / Verification Note:** Verified in draw.rs that State::default() sets pipeline to null and that draw/dispatch paths check `pipeline::host_pipeline(self.pipeline)` and drop the draw when pipeline is null. Also verified that pipeline::bound(pipeline) is not called on initial state during create_list/create_list_x.
- **Synthetic Reproducer:** Call CreateCommandList(0, DIRECT, allocator, valid_pso, IID, &list), set root arguments/targets, and immediately call DrawInstanced or Dispatch without an intervening SetPipelineState. Because state.pipeline is null, the draw/dispatch is silently dropped.
- **Proposed Fix & Risk:** - **Fix:** Pass `pipeline` into new_list(), call `crate::pipeline::bound(pipeline)` if non-null, and initialize `state` with `state.reset(pipeline)` (matching reset() at line 272).
- **Regression Risk:** Low; brings CreateCommandList / CreateCommandListX into exact parity with Reset(). (Estimated size: `S`)

#### 4. `VIC-BT-004` — fits() rejects NULL-desc and DXGI_FORMAT_UNKNOWN SRV/UAVs on typed textures promoted to typeless by host_texture() (`P0`)
- **Location:** `crates/victory-gpu/src/descriptor/host.rs, crates/victory-gpu/src/resource.rs` lines `descriptor/host.rs:599-611, 648-696; resource.rs:827-836`
- **Prior-Work Check:** 0% overlap across Marvisak_VIctory (0 hits for fits() rejecting view == 0 on typeless-promoted textures; #392 comment is about Host::rtv on B5G5R5A1/B4G4R4A4).
- **Root Cause:** In crates/victory-gpu/src/resource.rs (lines 827-836), host_texture() promotes typed console textures to *_TYPELESS on the host in two common cases: (1) depth textures without DENY_SHADER_RESOURCE, and (2) sRGB textures with ALLOW_UNORDERED_ACCESS. On the console, the title's resource is still typed, so D3D12 allows the title to pass pDesc == NULL or pDesc->Format == DXGI_FORMAT_UNKNOWN (0) to CreateShaderResourceView / CreateUnorderedAccessView to inherit the resource's format. However, in descriptor/host.rs:599-611, fits() inspects the host texture's promoted typeless format (`typeless == true`) and sees `view == 0`, returning `!typeless` (`false`). make() then returns None and null_for() silently writes a null descriptor into the host heap.
- **Edge-Case / Verification Note:** Checked descriptor.rs:220-235 (`RtvRecord::host_desc`) which explicitly calls `crate::resource::view_format(self.resource)` to recover the title's original typed format when creating NULL-desc RTVs/DSVs on typeless-promoted resources. descriptor/host.rs `make()`/`fits()` never performs that lookup for SRV/UAVs.
- **Synthetic Reproducer:** Create a 2D texture with DXGI_FORMAT_R8G8B8A8_UNORM_SRGB (29) and ALLOW_UNORDERED_ACCESS (0x4): host_texture() creates it as DXGI_FORMAT_R8G8B8A8_TYPELESS (27). Call CreateShaderResourceView(tex, NULL, handle) or CreateUnorderedAccessView(tex, NULL, NULL, handle): fits() computes typeless=true, view=0, returns false, and the host heap receives a null view.
- **Proposed Fix & Risk:** - **Fix:** When desc is None or desc.Format == DXGI_FORMAT_UNKNOWN (0) on a typeless-promoted host texture, resolve the title's original format via crate::resource::view_format(resource) (mapping sRGB to linear for UAVs and depth formats to their SRV format such as R32_FLOAT/R24_UNORM_X8_TYPELESS) and construct the explicit host view description before calling CreateShaderResourceView / CreateUnorderedAccessView.
- **Regression Risk:** Low; matches the exact pattern already used by RtvRecord::host_desc and eliminates silent null-view substitution on valid D3D12 calls. (Estimated size: `S`)
