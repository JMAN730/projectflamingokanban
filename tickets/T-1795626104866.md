## Original body

## What happens
The title boots, plays through the menus and loads into the world. Then the host GPU hangs while the world is drawing and the device is removed with `0x887A0006`.

## Environment
- GPU: NVIDIA GeForce RTX 4070 Ti SUPER, driver 32.0.16.2101
- Windows: 11 25H2
- Repo commit: ffe310e
- Build: `cargo build --profile diag -p victory --features diagnostics`
- Env vars: `VICTORY_D3D12_DRED=1`, `VICTORY_D3D12_DEBUG=1`, `VICTORY_LOG=info`
- Console mode: default (series-x)

## Command
```
target\diag\victory.exe run "G:\games\GTA6_my_own_dumb\game_scarlett_master.exe" --execute
```

## Result
From `crashes.log`:
- Failure after a submission of 25 lists
- One list stopped at command 2958 of 4295 (op 42), mesh draws
- Several other lists stopped at command 0 (op 46)
- Final error: `The GPU will not respond to more commands, most likely because of an invalid command passed by the calling application. (0x887A0006)`

Full `crashes.log` is attached.

## Notes
- This matches the hang described in the README status section, but on a different GPU (NVIDIA rather than the tested RX 6700 XT).
- An earlier run without DRED/DEBUG failed with `0x887A0004` ("feature level not supported") followed by `0x887A0005`.
- A MuMuPlayer virtual display adapter is also installed on this machine.

### Comment 1 — @lines9686-rgb — 2026-11-24T12:29:56Z

Same hang on an RTX 3060 Ti (NVIDIA 621.24, Windows 11 26200, ffe310e, `--profile diag --features diagnostics`, `VICTORY_D3D12_DRED=1`), own 1.0.2.1 copy: menus, intro and loading into the world work, then `0x887A0006` (DEVICE_HUNG) after ~2–3 min, each time with the stopped list on a mesh draw (op 42), like your command 2958.

Two things I ruled out:
- **One bad shader:** with `VICTORY_SKIP_PIPELINES` set to the mesh shader of the stopped draw, the next run hangs the same way on a *different* mesh draw (op 42 again, a different mesh/pixel pair).
- **Unbounded loops:** with `VICTORY_SHADER_LOOP_LIMIT=4096` (fresh shader cache entries) it still hangs on a mesh draw (op 42), at ~168 s.

Peak process memory 23 GB, commit not exhausted (an earlier run that hit the commit limit failed differently, with an allocation failure). #791 already reports that `TdrDelay` 10 s doesn't help on a 2070. So it looks like a class of mesh draws hanging on NVIDIA rather than one shader or a long loop. Happy to run more diagnostics (GBV, a list of mesh shaders to skip, timing) if useful.
