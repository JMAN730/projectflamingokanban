### Comment 1 — @pickles976 — 2026-11-24T15:45:38Z

First A/B before anyone reads the minidump, from your own #1086 table: this host is **wave32** and the log says `wave64-on-wave32` warnings — that is row 2 territory. `recommended_wave64_mode` picks native Wave32 on NVIDIA by default (legalizes without lane remap → wrong cross-lane compute, and the title then drives the world pass with corrupted results); the nine-change stack that reaches `world stage running` sets **`VICTORY_WAVE64_EMULATE=emulate`** explicitly (#189). 16 GB card + 32-list device-removed at world init is also consistent with wrong lane results turning into oversized/garbage resource traffic before the GPU gives up — but the one-variable test costs one run: same everything, add `emulate`, see if the removal still comes at 32 lists. If it moves anywhere, this issue becomes the second data point that native Wave32 should not be the default recommendation on NVIDIA (the #1086 author argued the same from the eternal-loading side; device-removed is the same root cause wearing a louder hat). Second-line screening from #1054 if it survives: `TdrLevel` value from the tester.'s registry — with it off this same event would freeze the desktop instead and get filed as something else entirely.
