## Original body

# NVIDIA RTX 4070 SUPER: D3D12 resource state validation failure when binding title buffer as vertex buffer

## Environment

- VIctory commit: `9aef3d9c062387c126f1c8ebacc5b95937c1ab9d`
- Build: `cargo build --profile diag -p victory --features diagnostics`
- CPU: AMD Ryzen 7 5800X
- RAM: 32 GB
- GPU: NVIDIA GeForce RTX 4070 SUPER (12 GB)
- NVIDIA driver: `32.0.16.2124`
- OS: Windows 11 Home, version `10.0.26300`, build `26300`
- Title: Xbox Series X build 1.0.2.1

## Summary

VIctory successfully executes the title on an NVIDIA RTX 4070 SUPER.

The game passes the initial profile selection, accessibility settings and legal screens. The opening cinematic subsequently plays, including audio and subtitles, for several minutes.

The process eventually hangs and the host D3D12 device is removed with `DXGI_ERROR_DEVICE_HUNG (0x887A0006)`.

Unlike a generic TDR, the D3D12 debug layer identifies a specific resource state validation error: a title buffer is still in `UNORDERED_ACCESS` state when VIctory binds it as a vertex buffer.

## Steps to reproduce

Build the diagnostics executable:

```powershell
cargo build --profile diag -p victory --features diagnostics
```

Set the environment variables:

```powershell
$env:VICTORY_D3D12_DRED = "1"
$env:VICTORY_D3D12_DEBUG = "1"
$env:VICTORY_LOG = "info"
```

Run the title without WARP:

```powershell
.\target\diag\victory.exe run "<game directory>\game_scarlett_master.exe" --execute
```

The same resource state validation error was reproduced both with and without `VICTORY_GPU_TIMING=1`.

## Observed result

The game reaches the opening cinematic and plays audio/subtitles. After several minutes, rendering slows down and the GPU device is removed.

The final diagnostic reports:

```text
DXGI_ERROR_DEVICE_HUNG (0x887A0006)

ID3D12CommandList::DrawIndexedInstanced:
Using IASetVertexBuffers

Resource state:
D3D12_RESOURCE_STATE_UNORDERED_ACCESS

Expected:
D3D12_RESOURCE_STATE_VERTEX_AND_CONSTANT_BUFFER

Actual:
D3D12_RESOURCE_STATE_UNORDERED_ACCESS

Missing State:
D3D12_RESOURCE_STATE_VERTEX_AND_CONSTANT_BUFFER
```

Affected resource:

```text
title buffer 0x19b10000+0xae00000
```

The buffer range is approximately 174 MiB.

## Possible area to investigate

The current implementation appears to handle title buffer barriers differently from texture barriers.

In `crates/victory-gpu/src/list.rs`, `host_barrier()` cannot translate barriers for title buffers because their host copies are represented by `Shadow` objects. The current buffer barrier handling adds a global UAV barrier.

In `crates/victory-gpu/src/draw.rs`, `State::prepare_for()` calls `shadow.refresh()` and then binds the shadow buffer using `IASetVertexBuffers()`.

Could the host shadow buffer be missing an explicit state transition from `D3D12_RESOURCE_STATE_UNORDERED_ACCESS` to `D3D12_RESOURCE_STATE_VERTEX_AND_CONSTANT_BUFFER` before the draw?

Index buffers may require equivalent handling for `D3D12_RESOURCE_STATE_INDEX_BUFFER`.

This is a suspected implementation issue, not a confirmed patch.

## Additional observations

- The same state validation error occurs with `VICTORY_GPU_TIMING` enabled and disabled.
- A separate WARP run fails earlier with a Wave64 compatibility limitation; it does not reproduce this exact NVIDIA validation error.
- The failure happens after the title has executed substantial real game code, including its opening cinematic.
- No game binaries, archives or proprietary assets are attached.

Full diagnostic output and `crashes.log` can be supplied for further investigation.
