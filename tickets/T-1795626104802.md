## Original body

### Summary
The title crashes immediately at startup, before any intro screen
(`Game State: Game Init`, frame 0, running time 0 s). Two title threads
fault on the same instruction (null pointer + 0x68). It reproduces on
every launch (5/5) with every option I tried.

Right before the crash the host refuses to create a 1920x1080
R9G9B9E5_SHAREDEXP texture with render-target and UAV flags, which looks
like the cause (details below).

### Environment
- VIctory: 8e79c80, `cargo build --release -p victory`
- Rust: 1.98.1 (from rust-toolchain.toml)
- OS: Windows 10 Pro 22H2 (build 19045.6466)
- CPU: AMD Ryzen 5 5600 (AVX2)
- GPU: NVIDIA GeForce RTX 5060
- RAM: 16 GB
- Game: own dump of the Xbox Series package, version 1.0.2.1
  (title build string: 930.048.020-vb_sub_story)
- Windows display language: Russian

### Steps
target\release\victory.exe run <game dir>\game_scarlett_master.exe --execute

### Likely cause
Right before the crash the console shows:

WARN victory_gpu::resource: no host texture error 0x80070057 (E_INVALIDARG)
ResourceDesc { dimension: 3, alignment: 0, width: 1920, height: 1080,
depth_or_array_size: 1, mip_levels: 1, format: 67, sample_count: 1,
sample_quality: 0, layout: 0, flags: 5 }

Format 67 is DXGI_FORMAT_R9G9B9E5_SHAREDEXP, and flags 5 are
ALLOW_RENDER_TARGET | ALLOW_UNORDERED_ACCESS. The host D3D12 device
refuses this on Windows 10 + NVIDIA, so the title's resource is probably
null when it reads +0x68 shortly after. Perhaps it needs a check with
CheckFeatureSupport and a fallback format (e.g. R11G11B10_FLOAT or
R16G16B16A16_FLOAT) when the host can't render to or write R9G9B9E5.

Other warnings in the same run, probably unrelated:
- `a host DLL outside the host policy: refused amd_fidelityfx_upscaler_xbox.dll`
- the title's crash reporter tries to upload a minidump to
  submit.backtrace.io and the HLE blocks it as expected
  (`HTTP connection blocked`)
