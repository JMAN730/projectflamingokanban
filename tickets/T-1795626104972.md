### Comment 9 — @Dufftwt — 2026-11-24T18:46:28Z

@AwkGrep256 thanks, and no rush on the sync branch. For the `amdxc64.dll` crash during pipeline compilation, two ways to name the pipeline without the title:

- `victory translate --pipelines --list --jobs 1` translates every program offline, creates a host pipeline for each emitted shader, and prints a line per program. With one worker, if AMD's compiler crashes on one of them, the run stops there and the last line names it. It runs without the world or a save, and repeats exactly.
- #491 (desplmfao) records a pipeline whose creation crashed the process and skips it on the next run (`VICTORY_PIPELINE_JOURNAL`). That gets you past the crash in-game while the compiler issue is chased separately.

If `translate --pipelines` reproduces it, the hash it stopped at is worth its own issue: a driver compiler crash on valid DXIL is reportable to AMD, and the translation may be able to avoid the pattern.
