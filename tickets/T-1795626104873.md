First run of the test suite on an NVIDIA GPU, as far as I can tell (the README lists only an RX 6700 XT). No game data involved.

**System**
- GPU: NVIDIA GeForce RTX 5060 Ti, driver 610.88 (32.0.16.1088)
- CPU: AMD Ryzen 5 5600GT (integrated graphics disabled; the RTX is the only adapter)
- OS: Windows 11 Pro
- Commit: ffe310e

**Results**
- `cargo test --workspace`: all pass.
- `cargo test -p victory-shader -- --nocapture --test-threads=1`: 120 passed, 1 ignored (benchmark). `valu_tests` and `waterfall_tests` ran on both the hardware device and WARP (no "skipped" message for either). `diff_tests` skipped (no console/PC compiler).

**Note**
The first run of `xtask`'s `repository_passes_policy` failed because I had saved test output with PowerShell 5.1's `Tee-Object` inside the repo folder. It writes UTF-16, so the policy flagged the .txt as binary. Moving the file out fixed it. Not a bug, but it may trip up other Windows contributors who capture logs the same way.

Happy to run anything else on this GPU if useful (e.g. a specific wave32 case).

- `cargo test -p victory-shader -- --nocapture --test-threads=1`: 120 passed, 0 failed, 1 ignored. The same `skipped` lines show up here: `no console compiler` and `no console or PC compiler` (diff_tests), and `no dxil.dll` (validation).

**One setup note for other Windows contributors**
This machine's Windows SDK had no `delayimp.lib`, so `victory-loader`'s `load_probe` failed to link (`LNK1181: cannot open input file 'delayimp.lib'`). I built the library locally from MSVC's own `delayhlp.cpp` plus the three data symbols that `delayimp.h` declares (`__pfnDliNotifyHook2`, `__pfnDliFailureHook2`, `__bChangeProtectionOfWholeDloadSection`), and put its folder first in `LIB`. With that the whole workspace is green. It is not a repository issue, but a minimal SDK install will hit it: the NuGet Windows SDK package does not ship that file either.

**What this GPU cannot cover**
The adapter reports 32-lane waves only (WaveLaneCountMin = Max = 32), so wave64 mesh and compute programs cannot run here unless they are split or refused. Happy to run a specific wave32 case if that helps.
