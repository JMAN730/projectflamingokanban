## Original body

On #566 head e09dbb6, a four-word descriptor selected across an if/else can drive the correct sampler. A subsequent masked write of one word, even when it writes exactly what those active lanes already held, stops resource tracking. This documents a reproducible coverage limit of the conservative refusal discussed in #566.

**Small repro without a game or GPU**. Add the following test inside the existing tests module of `crates/victory-shader/src/resource.rs` on that head. It reuses the existing image-descriptor fixture so the reproducer is just four extra instructions.

```rust
#[test]
fn joined_descriptor_redundant_partial_write() {
    let mut words = WATERFALL_JOINED_WAVE32.to_vec();
    let at = words.iter().position(|w| *w == 0x887e147e).unwrap() + 1;
    words.splice(at..at, [
        0x7d880090, // compare lane ID < 16
        0xbe923c6a, // save EXEC to s18 and enable the lower 16 lanes
        0x7e080218, // v4 = s24, the original value from their then arm
        0xbefe0312, // restore EXEC
    ]);
    waterfall(&words, false).unwrap();
}
```

Observed: resource tracking refuses at 0x108 with `a per-lane descriptor written where some lanes may keep the old one`. Expected: the same two per-lane resources as the unmodified fixture. Upper lanes preserve the else-arm word. Simply skipping the guard check would be wrong for a write that changes the active lanes' value.

**Independent sampler control**: a 32-thread synthetic compute shader uses the same 2×1 texture for all lanes and selects a point WRAP or CLAMP sampler through four joined dwords. At U=2.0 the expected red values are 1 and 2. The RTX 5070 Ti and WARP both returned the expected value for every lane, including with the two sampler slots swapped. Adding the analogous masked identity write to the first sampler word (v4 = s32 in this fixture) instead fails at 0xc0 before DXIL generation.

**Retail scope**: on the same head, mesh shaders 89a622617919c92a and fe660f2d6d57de76 still stop at image_sample_lz (0x5fe8, computed first-lane VGPRs; 0x5d90, partial control-flow join). Both read four sampler words with v_readfirstlane_b32. Their errors differ from the synthetic refusal. We have not established that supporting the synthetic case would fix either retail shader or the black scene.

AI disclosure: Codex authored and ran the synthetic tests locally, checked the results and wrote this report at my request.

### Comment 3 — @YouKnowWh — 2026-11-24T09:54:16Z

Follow-up on the new emission blocker (local #566 + the previous resource-tracking change). In fe660f2d6d57de76, 0x1254 is the conditional branch where the missing value surfaces. At 0x10b0 the title loads an SRV descriptor (table param 210, offset 0, used-resource stride 80). It uses dword 2 in (count - 1) * 80, then s_buffer_load_dword reads at that byte offset (0x10ec).

Recognizing scalar buffer uses with the raw-handle descriptor-data case from #437 made all five mesh samples emit, validate, and create hardware PSOs locally. This alone can produce incorrect data. A synthetic three-record buffer (240 bytes, with dwords 1000..1059) should return [3,1040] for [count, first dword of last record]. On RTX 5070 Ti it returned [240,0] with a raw SRV and [60,0] with a structured SRV when the DXIL handle was annotated raw. WARP returned [240,0] in both cases.

With the host view explicitly controlled, two separate experiments returned [3,1040] on both adapters: a verified raw SRV using byte length / 80 and byte addressing, and a matching structured SRV using element count and record-relative addressing. The actual view bound by this title at this draw has not been measured. This is a numerical regression case and not a validated retail fix; no game pixels or performance change claimed. The behavior concerns the descriptor count used as data, beyond the fixed byte-offset load tested in #437. AI-assisted local tests.
