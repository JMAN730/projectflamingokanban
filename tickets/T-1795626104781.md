## Original body

Hi VIctory team,

Following Halfect's work in #712 on DXIL validation for compute shaders (25,889 matched program labels, 1693/1693 validation), I'd like to offer a complementary tool that may help with the FidelityFX CAS portion of the shader pipeline.

**What ffx-kit does:**
- Compiles official AMD FidelityFX-CAS sources (MIT) with DXC to SPIR-V/DXIL
- Runs them on a real GPU (Vulkan/D3D12) and verifies output against a CPU golden model
- The CPU model exactly mirrors AMD's fast-math approximations: `APrxLoRcpF1` / `APrxMedRcpF1` / `APrxLoSqrtF1` bit tricks, green-channel weight path, D3D `saturate(NaN)=0` semantics

**Why this matters for VIctory:**
A naive "mathematically exact" CPU reference disagrees with AMD's intended fast-math paths by up to ~8.5% of signal. When validating translated CAS shaders against exact math, this produces false failures. ffx-kit provides the *correct* reference to validate against.

**Results (RTX 4070 Ti, DXC 1.9.2609.5):**
- 8/8 fp32 variants (BETTER_DIAGONALS × GO_SLOWER × SLOW): **PASS**, worst max diff 4.77e-07
- 4K (3840×2160): PASS, max diff 2.98e-07
- `manifest.json` with SHA-256 hashes for each compiled variant

**How it could integrate:**
- Use the provided `.spv`/DXIL files as ground-truth references for your CAS shader translator
- Port the Python golden model (`cas_golden.py`) to Rust for CI integration
- The fp16 packed variant (`CasFilterH`) is ready for native runtime integration (Python harness limited by wgpu's `RelaxedPrecision` handling on Windows)

**Repo:** https://github.com/Cobrall/ffx-kit

No game files, console binaries, or keys involved — only official open-source AMD FidelityFX headers.

Happy to adapt the harness to VIctory's CI, answer questions about the bit-exact golden model, or provide the Rust port of the CPU reference if useful.

cc @Halfect — this may complement your DXIL validation work on compute shaders.

**Update:** The repository now includes a zero-dependency Rust reference implementation at [`rust/cas_golden.rs`](https://github.com/Cobrall/ffx-kit/blob/main/rust/cas_golden.rs). 

It has been verified via `cargo check` and tested against the Python reference, mirroring AMD's fast-math approximations (`APrxLoRcpF1`, `APrxMedRcpF1`, `APrxLoSqrtF1`) and D3D `saturate(NaN)=0` semantics exactly. 

This can be dropped directly into a Rust or C++ test harness to validate translated CAS shaders against the *intended* AMD output, bypassing the need for the Python harness or naive "mathematically exact" references (which disagree by up to ~8.5% of signal).

Happy to help adapt this further if it fits into VIctory's CI pipeline!
