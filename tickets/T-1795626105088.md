## Original body

Hi, and thanks for VIctory.

I made a fork that puts the community work in one tree that builds and passes
its tests: https://github.com/DesertGamer/VIctory-V2

It is **not** meant to replace this project. The history of this repository is
kept intact, V2 is synchronized from it, and V2 says so in its README.

What it contains:
- the bundles by MamaLeVrai merged one at a time, with `cargo test --workspace`
  after each: #1617 (with #1542, #1418, #1426, #1439), #1593, #1521 (with #1368,
  #1386), #1363, #1358, #1389, #1452, #1456, #1459, plus what those already
  carry (#1402, #1504, #1319, #1492, #1511). The authors of the original
  commits stay the authors in the history.
- not merged, because they conflict with the rest: #1638, #1644, #1589, #1632,
  #1603, #1610. They are listed in a tracking issue so nobody redoes the work.
- contributor files: CONTRIBUTING, a PR template, issue forms, SECURITY.md.
  Every pull request is checked for binary files, scripts, `build.rs`, hooks
  and new dependencies before it is taken. The asset policy applies unchanged:
  there is no game data in V2.

Result on one machine, entering the world, compared with upstream `main` on the
same run: about 3050 draws per frame reach the GPU instead of 2430, and 688 are
dropped for lack of a host pipeline instead of 1408. The game is still not
playable: the host GPU still fails with a device removed error on entering the
world (V2 issue 1).

Anyone is welcome to take anything from V2 into this repository, with no
credit needed. If you would rather this note were not here, say so and I will
remove it.

Thanks for putting this together. Since V2 is about making community work usable in one tree, here are three PRs that would fit your intake checks (no new crates, no `build.rs`, no scripts) and aren't in it yet:

- **#961, compute fallback for GPUs without mesh shaders** (GTX 10 series, RX 400 to 5000, older Intel). Without it, the world's mesh pipelines are refused on those cards (`host GPU has no mesh shaders`). It has been run with the title on an RX 470 and a GTX 1070 Ti, has one approval, and fixes from three testers. It changes no `Cargo.toml`. #1648 is an alternative take on the same thing; both pass their tests on a GTX 1060.
- **#959, then #1609**: a menu on double-click, plus `victory doctor`, which names known problems in a run's log with where each is tracked. Measured against 1,462 reported runs, it names the cause of 69% of the ones that ended badly. They're app-only (`apps/victory`) and only add edges to crates the workspace already has (`windows`, `windows-sys`; `tempfile` and `toml` in tests), so they're unlikely to conflict with the bundles.
- **#1454** (the docs bundle) carries #1091 (installing Rust on Windows), in case you take docs.

I wrote #959, #961 and #1609, so take this as a pointer rather than a review.
