## Original body

1. Identify each Shadow using its resource identity.  
2. Record the requested uses: vertex, index, SRV, UAV, indirect, and root descriptors.  
3. Coordinate states across all command lists in the same submission.  
4. Insert transitions when a subsequent use requires an incompatible state.  
5. Treat COMMON as the initial state of Shadows for each new submission, thanks to buffer decay.  
6. Also handle the ExecuteIndirect count buffer.  
7. Keep UAV barriers for write synchronization: they shouldn't be confused with state transitions.  
There's an additional constraint: the command lists are recorded before being submitted. So tracking can't just read the current GPU state during recording, ignoring the order in which the lists will actually run.  
The solution must respect the run order and any prelude lists.

The next step should be to examine the HostList code that creates, closes, gathers, and submits the lists, to precisely define where to insert tracking without violating execution order. Only then write.
