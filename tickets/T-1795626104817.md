## Original body

`crates/victory-gpu/src/texture.rs:109-113`: once a texture is in `HOST_WRITTEN`, `upload()` always returns early. `CopyResource`, `CopyTextureRegion` and resolves add textures to that set (`list.rs:454`, `550`, `634`), and it is cleared only when the resource is dropped (`resource.rs:976`). If the title later writes that texture's memory (for example by streaming new mips), the host copy keeps the old contents.

**Suggestion:** record the write-watch point when the host copy happens. If the title's memory changes after that, detile it again.

_AI use: found and written with Claude from reading the code at `8e79c80`; not run on hardware._

A fix, on a branch of my fork since PR creation is limited to collaborators:

The branch is based on `c7a5f49`, just before the CI commit (my token can't push a branch that contains `.github/workflows`). It merges cleanly into the current `main`. The change is three files in `victory-gpu`: `texture.rs`, plus test helpers in `resource.rs` and `watch.rs`.

## What

- `HOST_WRITTEN` now keeps, per texture, the write-watch asking current when the host copy (`CopyResource`, `CopyTextureRegion`, resolve) was recorded.
- `upload()` asks the journal (`watch::writes`) for the texture's memory. If a page was written after that asking, the texture leaves the host-written state and its staging cursor is reset, so the upload detiles title memory again. A later host copy makes it host-written again.
- Memory without a write watch keeps the host's contents, as before (`shortcut:` note).
- A texture the host renders to or writes as a UAV is never uploaded from title memory, so it isn't recorded.
- `host_written` runs when the copy is recorded, not when it executes. A title write between recording and submission gets a later asking, so the next upload takes the title's contents.

## Tested

Linux, cross-built with `cargo xwin` for `x86_64-pc-windows-msvc`, run under Wine 10. GPU tests ran on vkd3d-proton 3.1 over lavapipe (a real D3D12 device).

- New tests:
  - `written_since_detects_pages_written_after_asking`: the rule itself.
  - `host_written_yields_after_write_in_watched_memory`: a write before the copy keeps host ownership; a write after it ends it; a new copy takes it again; unwatched memory keeps it.
