## Original body

System Information:

OS: Windows 11

CPU: AMD Ryzen 5 5600X

GPU: NVIDIA RTX 3070 Ti

RAM: 32 GB DDR4

Describe the bug:
The game crashes with a GPU hang (DXGI_ERROR_DEVICE_REMOVED / 0x887A0004) when loading into the 3D game world (after the intro). This happens consistently both on a physical NVIDIA GPU and in WARP (software) mode, which proves the issue is in the emulator's shader translation pipeline, not the host GPU driver.

Root Cause Analysis:
The attached full log (INFO victory_gpu.txt) shows the crash occurs because the emulator fails to translate a massive amount of compute shaders right before the world loads. The specific errors are:

GFX10 code at 0x...: a descriptor read only as data is not supported

GFX10 code at 0x...: a structured buffer of unknown stride is not supported

Because victory-shader cannot translate these, it drops the shaders (draws are dropped). When the game subsequently submits a batch of 25 command lists, the missing pipeline bindings/resource states cause the GPU to hang.

Proposed Architectural Solution:
Instead of dropping the shader on unsupported patterns, we should implement safe fallbacks to prevent the GPU hang:

For "Descriptor read as data": Pack the descriptor DWORDs into Root Constants (or a small Constant Buffer) on the host side and load them in the translated shader. If unmapped, fallback to 0u.

For "Structured buffer of unknown stride": Do not guess a stride. Instead, lower these to ByteAddressBuffer / RWByteAddressBuffer and perform explicit byte-offset reads (Load/Store).

I have attached a conceptual Rust implementation (use stdcollectionsBTreeMap;.txt) generated via AI architectural analysis. It outlines how to structure ShaderEmulationMetadata, handle the ValueExpr lowering, and emit the HLSL expressions for these fallbacks within the victory-shader crate.
