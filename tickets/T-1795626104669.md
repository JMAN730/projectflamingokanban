## Destination

VIctory playable on the reference machine, reached in two stages.

- **Stage 1, lit and controllable.** Boot, story load, prologue, then on foot and driving in the world. The picture is lit and substantially correct, a pad and keyboard/mouse both work, audio plays, and a save survives a restart. No crash and no device removal. Any frame rate.
- **Stage 2, playable.** The same at 30 fps or better at 1440p internal, for 30 minutes.

This map charts the route to stage 1 in detail. Stage 2 is sketched in the fog below and sharpens once stage 1 holds.

## Notes

**Reference machine (tier 1).** Windows 11, NVIDIA GPU with 32-lane waves and at least 12 GB of video memory, 32 GB of RAM. A ticket is done when it holds there.

**Tier 2, kept working but not gating.** AMD hosts with 64-lane waves on Windows; Windows 10.

**This map carries execution.** Wayfinder maps normally hold only decisions. This one also holds build work, because much of the route is already diagnosed. Ticket labels:

- `wayfinder:research`: facts from outside the repo (documentation, other public trees). Worked by an agent alone; findings land on a throwaway `research/<name>` branch that is never merged, linked from the ticket.
- `wayfinder:grilling`: a decision between named options. Resolved in conversation with the maintainer; the answer is recorded as a comment.
- `wayfinder:prototype`: a decision that needs a rough artifact to react to.
- `wayfinder:task`: work with done criteria. Either a build task (the fix is known) or an investigation that needs the game and the hardware. These are the tickets to claim if you want to write code.

## Decisions so far

<!-- one line per closed ticket: gist of the answer, linked to the ticket that holds the detail -->
- [Host limits on descriptor heaps, and ways past one million views](https://github.com/JMAN730/victory/issues/41): no host guarantees more than 1,000,000 views (Tier 3 may accept more, driver decides; the cap is queryable); a slot cannot be reused within a list, heap switches are legal but may stall, and directly indexed slots cannot be remapped without changing the index.
- [What a lit public tree changes that main lacks](https://github.com/JMAN730/victory/issues/39): ranked causes are depth and stencil twins for compute writes, rectangles completed in a geometry stage, alias copies for views placed over host-written textures, wave64 compute on 32-lane hosts, and descriptor supply on capped heaps; which one lit it is unproven, and nothing is taken from that tree without a licence check.
- [Wave size rules on host D3D12](https://github.com/JMAN730/victory/issues/40): a wave size can be declared for compute only (a range from shader model 6.8), never for mesh; a size outside the device range fails pipeline creation, and 64 loads only on AMD-class hosts; wave intrinsics never cross waves and how threads are dealt to waves is unspecified, which bounds any scheme that spreads one console wave over two host waves.
- [Which fixes from the parent project's open pull requests main already carries](https://github.com/JMAN730/victory/issues/37): of 25 fixes, 6 are on main, 5 partly, 6 exist only in open pull requests here (five of them only in one conflicting branch), 8 are absent; both byte and halfword local-data-share attempts merged and one is dead code.
- [Scoreboard: shader refusals on main, ranked by reason](https://github.com/JMAN730/victory/issues/38): 90.3% of programs emit and validate; of 2,226 refusals 35% are descriptor or address provenance, 30% lane-mask provenance, 12% interpolation, and under 2% are missing instructions.

## Not yet specified

- **Refusal reasons under about sixty programs each.** Cross-lane operations outside compute, whole-wave steps the simulation does not follow, descriptors chosen by control flow, cube samples, conditional exports and the few missing instructions. Small alone; revisit once the large families on the scoreboard have moved, since some will fall with them.
- **Draws still dropped with a warm pipeline library.** Over a thousand per frame in some reports. Includes pipelines that miss the per-frame readiness budget and workers starved behind shared dependencies. Waits on the baseline's drop counts by reason.
- **The mesh shader hang that only goes away when a few culling programs are skipped.** Not yet reproduced here.
- **Video memory headroom at 12 GB.** The host texture mirror can overrun; host textures made by address and shadow window copies are never released. Whether the reference machine hits this waits on the baseline.
- **Title pools running dry after several minutes.** Believed to follow from the frame rate; revisit when the frame rate moves.
- **Stage 2 frame rate.** Submissions are waited for one at a time, a changed texture is detiled whole, and title-memory copies dominate the frame. Asynchronous submission and cheaper copy-back are the suspected route; one decision is ticketed, the rest waits on a frame-time breakdown.
- **Presentation.** One plane, no scaling or placement, a fixed 4K60 mode list. Matters once the picture is lit.
- **Audio completeness.** Decoding plays; the rest of the console mixer (rate conversion, equalisers, filters, flowgraph mixing) is not emulated. Whether stage 1 audio is acceptable without it is unknown.
- **Runtime slots the title calls and we do not answer.** Waits on the ranked list.
- **Device-removed reports in release builds.** Today they need the diagnostics build.
- **Upscaler modules that carry no DXIL.** Hypothesised to matter for the final picture; no evidence yet.
- **A second game build.** One build identity is known; the thread-local rewrite and the watchdog hook are verified against it only.

## Out of scope

- **Linux, Proton, Wine and macOS.** The destination is the Windows reference machine.
- **Cards with 8 GB of video memory or less, and machines with 16 GB of RAM.** They need memory work beyond stage 2.
- **Online play, the store, frame generation, and correct ray-traced lighting beyond what stage 1 needs.**
- **The parent project's pull request backlog and CI approval queue.** This map plans work on this fork.
