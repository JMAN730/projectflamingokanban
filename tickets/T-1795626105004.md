### Summary
Fixes input-layout validation and appended vertex-offset calculation bugs in `crates/victory-gpu/src/pipeline/host.rs` (previously 0 unit tests) and adds 14 deterministic synthetic unit tests.

Because external PR creation is currently restricted (`collaborators_only`), the CI-green branch is ready on my fork for cherry-pick / review:
- **Branch**: `geiyiliyabumo/VIctory@test/gpu-pipeline-host`
- **Commit**: `geiyiliyabumo/VIctory@649c6e5` (based on `main` `ffe310e`)

### Changes (`crates/victory-gpu/src/pipeline/host.rs`)
- **Fixes (5 synthetic regressions proved red before fix)**:
  - Empty layouts now properly reset state.
  - Rejects element counts `> 32`, input slots outside `0..=31`, null `SemanticName`, and null/misaligned element arrays with nonzero counts.
  - Appended (`D3D12_APPEND_ALIGNED_ELEMENT`) vertex offsets now account for per-slot format alignment and reject arithmetic overflow.
- **Tests (+14 synthetic)**: covers layout ownership, malformed descriptors, offset arithmetic, defaults, format conversion, blend, rasterizer, depth/stencil, and bytecode copying.

### Comment 1 — @MichaelSmithAI — 2026-11-24T15:40:44Z

The alignment change fixes an observable attribute value in VIctory’s CPU rectangle expansion, even with a single input slot. We tested an 8-byte vertex with R8_UINT at offset 0 and an appended R32_FLOAT at offset 4. With input floats 1.0, 3.0 and 7.0, the generated fourth vertex contained the expected 5.0. Restoring just the previous offset calculation produced 1.0 with the same input.

All 14 authored tests passed on the gstack integration. The full GPU crate run under Wine had 99 passes, one ignored test and the existing empty-pipeline-library failure. The rectangle control inspected the expanded vertex bytes. Native triangle input assembly resolves append offsets independently, and title use of this CPU expansion layout is still open.
