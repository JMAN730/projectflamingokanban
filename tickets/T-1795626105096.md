## Original body

### Summary

On an NVIDIA RTX 4080 SUPER, the host D3D12 device is removed (`0x887A0006`, `DXGI_ERROR_DEVICE_HUNG`) during the first-boot screens, before the world. Windows then resets the display driver (`nvlddmkm`, event 4101). The README lists the GPU hang only when entering the world, and only one AMD machine as tested, so this may be NVIDIA-specific.

### Setup

- VIctory `main` at `e8f3b1c`, release build and a `diag` build (`--features diagnostics`)
- GPU: NVIDIA GeForce RTX 4080 SUPER, driver 616.56 (Windows driver version 32.0.16.1656)
- CPU: AMD Ryzen 7 7800X3D; 32 GB RAM
- Windows 11 23H2 (build 22631)
- Own Xbox Series dump, version 1.0.2.1

### What happens

1. `victory run <game_scarlett_master.exe> --execute`
2. Boot, first-boot screens and the settings screen render at about 24-30 fps.
3. The device hangs on the next screens. Two runs: once right after choosing the settings, once on the copyright/legal screen.

Both runs: `host GPU device removed after a submission of 4 lists`, `0x887A0006`.

### Device-removed data (`diag` build, `VICTORY_D3D12_DRED=1`)

From `crashes.log` (summarised; no title memory or constants quoted):

- One list stopped at **command 117 of 145 (op 4, indexed draw)**; commands 100..142 lie between its barriers.
- Commands 101-107: indexed draws with **vertex `3cbf9d0ff906c983` / pixel `b424d979b3c665e4`** (SRVs: 2048x2048 format 65, 3840x2160 format 65).
- Commands 109-123: indexed draws (about 3,200-4,350 indices each) with **vertex `98b739f0e80dfb84` / pixel `872592596b3651f0`**. The pixel shader's table holds one SRV, 3840x2160 format 65 (`DXGI_FORMAT_A8_UNORM`), flags `0x1`, plus a constants CBV. **Command 117, where the list stopped, is one of these.**
- A second list stopped at command 0 of 1 (op 15), with no pipelines.
- The other in-flight list (list 2 of 4) ends with draws using `98b739f0e80dfb84` / `872592596b3651f0`, `571fe570756bc393` / `02c6cf86ca283ce1`, `67e814f3c3be6dac` / `46447d58f4954cd1` (a placed 64x64 format 77 texture, layout `0x105`), and a 6-vertex draw with `0602c2384acbb3b2` / `a78d088fa55aa495` reading a 3840x2160 format 28 target.
- DRED reported no page fault, so the GPU stalled rather than faulted. That fits a translated program that never finishes, most likely pixel shader `872592596b3651f0`.

I looked at whether this could be the 32-lane vs 64-lane wave difference, but `emit/lower.rs` (`MaskData`) already limits pixel and vertex programs to mask uses that mean the same on any wave size, so I don't have a confirmed cause. I could not run with `VICTORY_D3D12_DEBUG=1`: this machine lacks the Graphics Tools debug layer. A device hang would likely not be caught by it anyway.

### Happy to test

I can rerun with other diagnostics switches, a patched build, or `VICTORY_D3D12_WARP=1`, and report counts and outcomes (no game data).

*Diagnosis and write-up were AI-assisted (Claude Code); the runs, logs and hardware are mine.*
