[Branch and diff](https://github.com/Marvisak/VIctory/compare/main...Filip722:gpu/early-pipeline-keys-without-host-library) · commit `c449c24dd999e41d41c33690ab97760e8be72daa`

When D3D12 refuses the host pipeline library, the patch saves the title pipeline keys separately so VIctory can start compiling them during the next launch. #347 addresses one reason library creation fails. This change covers the case where the library remains unavailable.

On Proton Experimental 11.0-20261112 with vkd3d-proton 3.2.0 and NVIDIA driver 615.78.08, the library was unavailable on all four Series X launches. Both builds reached startup frame 512 at about 30 fps. The baseline wrote no early list. The patch saved six keys and read all six on relaunch. Both new regression tests passed, and the full GPU suite had the same two existing Proton failures on both builds. Windows-target Clippy and the asset-policy check passed.

I can offer hands-on testing on a hybrid graphics laptop with an Intel Core 7 240H and an NVIDIA GeForce RTX 5060 Laptop GPU. It runs Bazzite 44.20261011.0, a SteamOS-style Linux setup with Steam Gaming Mode and Proton. I also have plenty of ChatGPT usage available to help review code, prepare small patches, and turn build and test logs into concise repro reports. The GPU results come from actual runs on this laptop. I’m happy to focus on issues or existing PRs you want tested.

AI assistance was used for reviewing the patch, running verification, and preparing this report.
