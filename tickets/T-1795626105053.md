### What this is, and what it is not

A second, independent GTA VI Xbox→PC attempt (*Project Leonida*). We classified 303 translation failures from one world-frame window (posted separately); this issue is the three rules we use where **the same seams your open PRs are already working**. For each rule we say first what overlaps, then only what does not.

**AI-assisted write-up, human-checked against our own reports.** No game bytes, no shader names.

We are not offering a patch in this issue. Where we have code, it goes as a PR and gets linked here.

---

### Rule 1 — A mask needs materialising only if something downstream reads its whole value

**Overlaps:** #1115 (a `v_cndmask_b32` whose mask is `s_cselect -1, 0` is refused as "an untracked mask"), #878 (mask dwords at data joins; ready to merge), #750 (redundant masked write after a per-lane descriptor join). Your `ir.rs:551 liveness()` already computes `live_in` / `live_out` — but at **block granularity**, a `RegSet` per basic block.

**What we do differently is the granularity and the question.** Instead of asking "is this value a mask?" at the use site, ask "does anything read this register's *whole* value before it is overwritten, and if not, does it need a value at all?"

- A register is **whole-live** after an instruction when some path may read its full value before it is written again: any SALU or SMEM operand, any VALU scalar operand, a branch on `VCCZ`, and so on.
- A mask write whose destination is **not** whole-live needs **no materialisation**. Only the reading lane's own bit is ever consulted — `v_cndmask_b32`'s mask, the carry-in of `v_add_co_ci` / `v_sub(rev)_co_ci` — and that lane's half of the wave already holds it.
- A mask write whose destination **is** whole-live is materialised as a ballot.

The point is that the refusal condition cannot arise for the first class, so it stops being an error path rather than becoming a special case.

**Three details that cost us real debugging time.** They are the difference between this producing a refusal and producing a *silently wrong* translation:

1. **A write is not an overwrite.** Treat a mask write as killing the old value only where the emitter replaces the register whatever it held: not `s_cmov*` (conditional), not `s_addk` / `s_mulk` / `s_bitset*` (they read the old value), not `s_movreld` / `s_movrelsd` (they write `s[dst + m0]`), and not SDWA compares that write their SDST instead of VCC.
2. **`s_movrels*` reads `s[src + m0]`**, so every register from `src` upward is live, not just `src`. SDWA scalar sources (S0 / S1) and SMEM register offsets are reads too.
3. **Conservative where you cannot see:** an indirect jump makes every SGPR whole-live; `EXEC` is always whole-live; every SGPR is whole-live at the end of a program that reads state back; and anything live after an emitted loop is live before each of its instructions, because the loop may be left at its iteration-budget check.

**Where this lands relative to #878.** #878's data-join shortcut takes `undef` on the non-data edge, which is the same assumption #180 makes for descriptor dwords. That is sound only if rule detail 1 holds — if a register that looks dead is actually read-merged, the `undef` becomes a wrong value rather than a refusal.

**Honest scope:** this involves all **127** class-A failures, but we are not claiming it recovers all 127. The 60 `a lane mask holding lanes elsewhere read as data` cases read bits belonging to the *other* half of the wave; whether whole-liveness covers them depends on where those bits are consumed, and we have not measured that split.

### Rule 2 — A descriptor's console fields survive translation; only word 0 and the sampler index change

**Overlaps:** #1130 (a descriptor read only as data takes the kind of another load of the same heap entry — 819 → 53 programs), #1067 (kind from the table range — 4,123 → 3,749), #1325 (4-dword buffer views inferred from `UsedResource`, closed), plus #979 and #798. These are the right direction and they cover most of class B (62 failures).

**What we would add is a representation argument, not a tracking one.** Our lowering never rebuilds a descriptor from host-side knowledge at the use site. The console's words live in SGPRs and the shader reads them raw:

```hlsl
Texture2D<float4> t_T = ResourceDescriptorHeap[NonUniformResourceIndex(tw0)];
SamplerState     t_S = SamplerDescriptorHeap[NonUniformResourceIndex(s3 & 0xFFFu)];
```

`tw0` is exactly the SGPR the descriptor was loaded into — no mask, no shift. What makes that legal is that **the runtime rewrites the descriptor on the way into the heap**:

```
T# word 0             -> the SRV's index in the PC heap   (word 1's high byte cleared)
S# word 3 bits [11:0] -> the sampler's index in the PC heap
every other field (format, size, swizzle, dst_sel) -> untouched, exactly as the console wrote it
```

**Why that dissolves the largest class-B shape.** `a descriptor read only as data` (51 of 62) means the program used the descriptor's *words* for arithmetic — dimension reads, address arithmetic — without ever sampling through it. If words 1–3 still hold the console's own numbers, a program doing arithmetic on stride, `num_records` or format gets the values it expects, with no inference needed at all. Only word 0 means something different, and word 0 is the field a program should not be doing arithmetic on. In our corpus it does not: the arithmetic touches dwords 1–3.

Your `resource.rs:47` comment already records `dword 1 (stride, swizzle), dwords 2 and 3 as given` for the *built* case, so the field semantics are clearly understood here. The open question we would raise is whether the *loaded* path keeps those fields byte-identical when the descriptor reaches the shader.

**One measurement worth having before anyone treats the descriptor heap address as a blocker.** We spent a round convinced the 32-bit table address in a root argument was fatal, because our host heaps all landed above 4 GiB — 19 segments of 65,536 descriptors, every one of them. It was not fatal; we had conflated two layers. On the console, that dword is the **32-bit UMA address of the table's first slot**. After translation it must be the **heap-relative index of that slot**. If any part of a pipeline treats it as an address end to end, a whole cluster of descriptor failures can come from that one representation question. *(This measurement is from a separate experiment in our project, not the three-minute run above.)*

### Rule 3 — `stride == 0` is a raw buffer, not an unknown one

**Overlaps:** #155 (runtime stride channel, design + anchors), #193 (runtime stride table for structured buffers), #704 (unknown-stride buffers read through a raw view of the same bytes, stacked on #193). Those three are the complete line on this, and #704 in particular is close to the conclusion.

**The predicate we use for the same V# field:**

- **stride 0 = raw.** `num_records` counts **bytes**, and the descriptor is a flat byte buffer.
- **stride != 0 = structured or typed.** `num_records` counts **elements**, and the element size is the stride.

The stride is V# dword 1 bits [29:16], the count is dword 2. So a stride-0 descriptor arriving at a structured-buffer path is **not an unknown stride — it is the wrong path**. Concretely, your three refusals read `if stride < 4 || !stride.is_multiple_of(4) { return Err("a structured buffer of unknown stride") }` (`emit/lower.rs:6281`, `:6364`, `:6425`), which catches 0, 1, 2 and 3 together.

**What we would check first:** how many of the 27 are stride **exactly 0**. If they are, the fix is a branch rather than an analysis, and the error string is currently hiding a routing decision inside a tracking failure. We have not measured that split on your corpus — this is a hypothesis with a cheap test.

**A second suggestion for class D, on `a scalar memory read as data` (18).** #979 reports 771 programs offline with this string and finds the use instruction is always an `s_` operation. One addition: not every `s_load` is a descriptor load. `s_load_dword` from a constant table appended after the code — read through `s_getpc_b64` — is data by construction, and it appears in the same programs. Splitting on "is the base a `s_getpc_b64` result" separates two populations that currently share one string, and only one of them is a descriptor problem.
