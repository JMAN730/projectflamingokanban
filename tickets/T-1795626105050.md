## Original body

This PR adds diagnostic infrastructure for the `FSPX` compute containers used by `amd_fidelityfx_upscaler_xbox.dll` (FSR4 post-process upscaler). It does not yet translate RDNA2 bytecode to DXIL — that remains future work — but it makes the problem visible and opens a path to force the engine's internal DXIL fallback.

### What it does
1. **FSPX container parsing (`crates/victory-shader/src/dxbc.rs`):**
   - Added `FourCC::ACCC` detection.
   - Implemented `Fspx::parse()` and `inspect_fspx()`, extracting `NumThreadsX/Y/Z`, `wave32/wave64`, RDNA2 code size, and kind 1/6/7 metadata.
   - `translate()` now returns an explicit `Unsupported("FSPX compute module")` instead of a misleading `no DXIL part`.

2. **Device slot 67 (`DeserializeComputePipelineStateX`) mapping (`crates/victory-gpu/src/pipeline.rs`):**
   - Slot 67 (`0x218`) is now wired to return a configurable HRESULT (`E_FAIL` by default), zeroing the out pointer.
   - Environment variable `VICTORY_SLOT67_HR` allows testing `E_FAIL`, `E_INVALIDARG`, `E_NOTIMPL`, and `S_OK` without rebuilding.
   - Slot 62 (`create_compute_x`) can reject FSPX with `VICTORY_FSPX_REJECT_SLOT62=1`.

3. **Diagnostics:**
   - `Shader::translated()` logs the shader hash, thread group dimensions, wave size, and container size for every FSPX module.
   - `missing()` in `pipeline/make.rs` now tags dropped pipelines as `compute <hash> (FSPX compute module)`.

### Why it matters
Before this change, the DLL's `E_NOTIMPL` on slot 67 caused it to fall back to slot 62, which returned `S_OK` with a "no-shaders PSO". Every dispatch was then dropped in `draw.rs`, leaving the 2560×1440 target at clear color (the black screen). With slot 67 mapped and configurable, testers can now observe how the DLL and the engine react to pipeline creation failures, and whether the engine's internal DXIL post-process fallback activates.
