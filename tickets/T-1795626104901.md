## Original body

## Bug

The cache in `Lower::handle` (`crates/victory-shader/src/emit/lower.rs`) keys a heap handle by its first resource-property word only (kind and UAV flag). Suppose a block does a size query on an image UAV (`image_get_resinfo`, f32 x4, `0x409`) and then an atomic on the same image (`image_atomic_*`, u32 x1, `0x105`). The atomic reuses the query's **f32** handle. dxil-spirv then declares a float image and emits:

```
%3252 = OpAtomicUMax %float %3251 %uint_5 %uint_0 %3180
```

`spirv-val` rejects this: `AtomicUMax: expected Result Type to be integer scalar type`. NVIDIA's compiler crashes on it under vkd3d-proton (`vkCreateGraphicsPipelines Exception 0xc0000005 in Unix call`), which ends the title while it loads into the world. AMD's D3D12 driver seems to tolerate it, but the DXIL is wrong on every GPU.

## Fix (ready on my fork)

Branch: https://github.com/NicolaiVdS/VIctory/tree/shader/atomic-handle-type
Commit: https://github.com/NicolaiVdS/VIctory/commit/ae7e0bef6a9bc834358d48f39902c284f3d9218e
Diff against main: https://github.com/Marvisak/VIctory/compare/main...NicolaiVdS:VIctory:shader/atomic-handle-type

- **The fix:** the cache key holds both property words. Every caller goes through this one cache, so structured buffers read with two strides get separate handles too.
- **The regression test:** `an_image_atomic_after_a_size_query_gets_an_integer_handle`. It sees one handle (`[0x409]`) before the fix and two (`[0x409, 0x105]`) after.
- **Checks:** `cargo test -p victory-shader` passes. Clippy on the Windows target, with and without `--all-features`, is clean with `-D warnings`.
- **Verified on an RTX 5070 Ti, Wine 11, vkd3d-proton master `30b0eb9`:**
  - `translate --pipelines` over `shaders.rpf` builds 21,566 pipelines with no driver crashes.
  - All 13,274 SPIR-V modules vkd3d-proton dumped pass `spirv-val`.
  - The title loads into the world with no driver crashes.

## Side note for Linux/NVIDIA

This one isn't a VIctory bug. vkd3d-proton 3.1's dxil-spirv produces invalid SPIR-V for 40 of the title's shaders (structured-exit and empty-merge-block errors), and NVIDIA crashes on one of them (`0xc000001d`). vkd3d-proton master fixes all 40, so Linux users need a version newer than 3.1.

This is the bug #177 fixes (Ortomanic, open since 01:08 UTC). `handle()` keys the cache by `props.0` only, so an atomic on a UAV that was also read as float gets the float handle. dxil-spirv then emits an atomic on a float pointer, and you get the same `spirv-val` error ("expected Result Type to be integer scalar type") and the same NVIDIA driver crash under vkd3d-proton as the title enters the world. #177 adds `props.1` to the key, which is what your branch does.

#177 was tested against #144 (the NVIDIA + vkd3d-proton crash in `vkCreateComputePipelines`). MichaelSmithAI also found the size-query + atomic case on #728 and stacked it on #177's key.
