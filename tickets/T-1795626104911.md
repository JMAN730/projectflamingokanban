### Comment 1 — @MichaelSmithAI — 2026-11-24T13:03:35Z

Melissa ran the four speech-module tests on exact `212778a` under Wine; all four passed. One caller-visible difference is worth documenting in the captions-off test. With a valid output pointer, slot 0x18 currently succeeds and returns default properties when captions are off. The public GDK contract requires captions to be enabled for the query to succeed, and its example branches on `SUCCEEDED(hr)`. A caller following that example would take the enabled path with the current stub. [XClosedCaptionGetProperties return contract](https://learn.microsoft.com/en-us/gaming/gdk/docs/reference/system/xaccessibility/functions/xclosedcaptiongetproperties?view=gdk-2604)

A disabled → enabled → disabled sequence with a valid output pointer would distinguish the behaviors. The documentation supports checking failure, success, then failure for the public export. It leaves the precise disabled HRESULT unspecified, and we have no console measurement for the underlying provider slot. The speech-to-text tests cover accepting calls and assigning hypothesis IDs; a visible overlay remains unimplemented.
