## Original body

Under Wine + vkd3d-proton, every deferred copy into a host-mapped destination is skipped, because the guard in `copy_mapped` checks `VirtualQuery(...).State == MEM_COMMIT` and vkd3d-proton's mapped memory is not in Wine's virtual-memory bookkeeping.

### Environment

- Arch Linux x86_64; Wine 11.22; vkd3d-proton 3.1 (system `vkd3d-proton-bin`); AMD Radeon RX 9060 XT (RADV 26.3.1).
- Windows build of `main` `7d33c46`: `cargo xwin build/test --release --target x86_64-pc-windows-msvc` (cargo-xwin 0.24.1, rustc 1.98.1).
- No game data, no `victory.toml` (synthetic tests only).

### Reproducer

`victory_gpu-*.exe resource::tests::buffer_data_reaches_the_host_texture` fails:

```
assertion `left == right` failed: row 0
  left: [0, 0, 0, 0, ...]
 right: [0, 1, 2, 3, ...]
```

The rest of the crate's host-GPU tests pass: **36 passed, 3 failed** (the other two are environment gaps, listed below).

### Cause

`HostList::run_deferred` runs `Step::Copy` as

```rust
copy_mapped(dst as *mut u8, src as *const u8, len, true)   // crates/victory-gpu/src/host.rs:1120
```

and `copy_mapped` starts with

```rust
if len == 0 || title_dst && !crate::texture::committed(dst, len) { return; }   // host.rs:1214
```

`texture::committed` (`crates/victory-gpu/src/texture.rs:260`) walks the range with `VirtualQuery` and requires `MEM_COMMIT`. In this environment `VirtualQuery` on the staging upload buffer that `Map` handed out returns:

```
n=48 state=0x10000 (MEM_FREE) type=0x0 protect=0x1 base=0x7fdebf000000 size=0xb7e0000
```

so the copy is skipped and the texture keeps zeros. The address is a vkd3d-proton allocation (large mmap arena) that Wine's `VirtualQuery` reports as free.

### Scope

`copy_texture_region`'s staging path uses `defer_copy` (`crates/victory-gpu/src/list.rs:529`), and `copy_buffer_region` / `copy_resource` use the same `Step::Copy` arm, so any deferred copy whose destination is host-mapped memory is exposed. On Windows the same guard reads `MEM_COMMIT`; this shows up only under Wine/vkd3d.

### Confirmed fix direction

Changing the `Step::Copy` call locally to pass `title_dst = false` makes the test pass under Wine:

```
test resource::tests::buffer_data_reaches_the_host_texture ... ok
```

The flag also drives `watch::writing`, so the real fix should distinguish a destination we mapped ourselves (the staging buffer from `HostList::upload` / `Host::upload_buffer`, known committed) from title memory that needs the guard — a per-step flag or a registry of our mapped ranges — rather than flipping it globally.

### Other failures in the same run (environment, not this issue)

- `indirect::tests::argument_clamp_builds`: Wine's builtin `d3dcompiler_47` cannot compile the clamp shader — `E5005: Method 'Load' is not defined on type 'RWByteAddressBuffer'`. Under Wine this also drops indirect execution at runtime (`clamp()` returns `None`); a native Microsoft `d3dcompiler_47.dll` in the prefix is the likely workaround.
- `pipeline::library::tests::a_rejected_blob_gives_an_empty_library`: vkd3d-proton returns `D3D12_ERROR_DRIVER_VERSION_MISMATCH` (`0x887E0002`) for the damaged blob (expected) and `E_INVALIDARG` (`0x80070057`) for the empty library, so `open()` returns `None`. The runtime handles that (no pipeline cache), only the test's expectation differs.
