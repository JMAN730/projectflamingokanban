## Original body

On `787f665`, the guest `CheckFeatureSupport(FORMAT_SUPPORT)` returns the same all-capabilities masks for every format. The query reports `RENDER_TARGET` for `DXGI_FORMAT_BC1_UNORM`, while a direct native D3D12 query on the selected adapter clears that bit. This reproduces on RTX 5090 and WARP.

## Reproduction

Query `FORMAT_SUPPORT` through the guest device for BC1 and RGBA8. Compare both returned support words with a native query on the same adapter. RGBA8 is the positive render-target control. The guest and native BC1 answers disagree on both adapters.

## Source fix

[Commit `7007f33`](https://github.com/fuzeofficlal/VIctory/commit/7007f33cae6dfc5bc2db508055ab089b03957989) uses the existing guest-to-PC format mapping and the selected native device. It reports zero support for five guest formats with no host mapping, including 189–191 whose numeric IDs describe different native PC formats.

The synthetic check passes ten format cases on each adapter, including positive RGBA8, BC1, the three mapped depth formats and the five unmapped formats. It also checks that the input format ID is preserved and malformed queries still reject. The GPU diagnostics suite passes 45 tests with one benchmark ignored on each backend.
