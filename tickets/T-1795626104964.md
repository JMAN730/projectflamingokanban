## Original body


## Summary

In `crates/victory-loader/src/crash.rs:176`, single-instruction `clwb` emulation is gated on `n >= 15` (remaining bytes before the end of the 4 KiB page):

```rust
let room = 0x1000 - (context.Rip as usize & 0xfff);
let mut bytes = [0u8; 32];
let n = room.min(bytes.len());
std::ptr::copy_nonoverlapping(code, bytes.as_mut_ptr(), n);
...
if n >= 15
    && let Some(len) = clwb_len(bytes[..15].try_into().unwrap_or([0; 15]))
{
    context.Rip += len as u64;
    return true;
}

```

A `clwb m8` instruction (`66 [rex] 0f ae /6 [SIB] [disp8/disp32]`) is only 4 to 10 bytes long. If a standalone `clwb` (or one not matched by `clwb_loop`) sits within the last 14 bytes of a page (`Rip & 0xfff` in `0xFF2..=0xFFB`), `n < 15`, so `clwb_len` is skipped entirely and the exception falls through to `sse4a()` → `false` → unhandled `STATUS_ILLEGAL_INSTRUCTION` (`0xc000001d`) on pre-Ice Lake Intel CPUs (and any CPU without `CLWB`).

## Suggested fix

Change `clwb_len` to accept a slice `&[u8]` (just like `clwb_loop(&[u8])` right above it) and bounds-check each byte as it decodes `66`, optional REX, `0f ae`, ModRM, optional SIB, and displacement, returning `Some(len)` whenever `len <= code.len()`. Then remove the `n >= 15` guard in `emulate_amd_only`.

## Synthetic unit test

In `crates/victory-loader/src/crash.rs` (`mod tests`):

* Call `clwb_len(&[0x66, 0x0f, 0xae, 0x31])` (4-byte slice, simulating `Rip & 0xfff == 0xffc`) → expect `Some(4)`.
* Call `clwb_len(&[0x66, 0x41, 0x0f, 0xae, 0x31])` (5-byte slice) → expect `Some(5)`.
* Call `clwb_len(&[0x66, 0x0f, 0xae, 0x70])` (truncated `disp8`) → expect `None`.
