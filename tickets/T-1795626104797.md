### Comment 3 — @JFIREonFIRE — 2026-11-24T18:18:53Z

A note on `wave64-emulation` (`61b04f7`), found while comparing the wave64 branches on an RTX 3090 (numbers in https://github.com/Marvisak/VIctory/pull/439#issuecomment-7140465446):

The branch learns the host's lane counts only in `victory-gpu`'s `Host` at device creation. `victory translate --pipelines` makes its own `victory_shader::emit::host::Host` and never calls `emit::set_host_wave64`, so the tool still emits `WaveSize(64)` on a 32-lane card. There the driver refuses all 319 programs it emits (`The parameter is incorrect`), and the tool reports none of the emulation's work.

With one line after `Host::new(false)` in `apps/victory/src/translate.rs`, the same set gives 71 pipelines. The line hard-codes 32..32 for the local test; the real fix would read the device's `OPTIONS1`:

```rust
victory_shader::emit::set_host_wave64(32, 32);
```

The remaining refusals: 212 "a step across lanes in lane-dependent code", 36 "a compute group of several 64-lane waves". In the game itself the host path does set the lanes, so this only affects the offline tool's counts.
