### Comment 2 — @LAKSHYA-cmd-tech — 2026-11-24T07:56:51Z

﻿### Root Cause Identified for the `[mesh 413144fb9d62e37e, pixel 633c1f8872ed8c6d]` GPU Hang (`0x887A0006`)

Comparing the crash logs in #619 and #625 reveals the exact same indirect mesh dispatch and pipeline failing across both systems:
`indirect kind 10 max 1 at ... [mesh 413144fb9d62e37e, pixel 633c1f8872ed8c6d]`

Notice the exact diagnostic output for the pixel shader:
`633c1f8872ed8c6d: u8=0xa13a00 [heap 330192: null]`

#### The Bug
1. `u8=0xa13a00` is a descriptor table offset `10,566,144` bytes into the view heap, which indexes host descriptor slot `330,192` (`0xa13a00 / 32 = 330,192`).
2. In `crates/victory-gpu/src/descriptor/host.rs` (lines 343-353):
   ```rust
   let later = !for_draw && view.is_buffer();
   made[index as usize] = if later { 0 } else { key };
   let kept = if later {
       None
   } else {
       make(&view, self.cpu(index))
   };
   if kept.is_none() && !self.sampler {
       null_for(&view, self.cpu(index));
   }
   ```
3. When the title writes a buffer descriptor to slot `330,192`, `mirror()` is called with `for_draw: false`.
4. Because `view.is_buffer()` is true, `later` is set to `true`:
   - It **skips** calling `make(&view, self.cpu(index))`.
   - It executes `null_for(&view, self.cpu(index))`, populating slot `330,192` with a **null view** (`DXGI_FORMAT_R8G8B8A8_UNORM` dummy 2D texture or empty buffer).
   - It sets `made[330,192] = 0`.
5. When the draw runs, `table_entry` is only invoked for resources statically declared in `UsedResource`. Dynamically indexed buffer descriptors or descriptors indexed via root constants/user data that were not in `used` never get `mirror(..., for_draw: true)` called on them.
6. When the mesh dispatch runs `[mesh 413144fb9d62e37e, pixel 633c1f8872ed8c6d]`, pixel shader `633c1f8872ed8c6d` executes a typed/raw buffer operation against heap slot `330,192` (which is still a null view). On NVIDIA hardware (RTX 3060 / 3060 Ti), this invalid memory access halts the hardware queue and triggers `DXGI_ERROR_DEVICE_HUNG (0x887A0006)`.

Eliminating the artificial `later` deferral for buffer views or ensuring dynamically referenced heap slots are realized before execution resolves this crash.


### Comment 3 — @LAKSHYA-cmd-tech — 2026-11-24T08:23:38Z

Identical root cause to #619:
Crash occurs at \[mesh 413144fb9d62e37e, pixel 633c1f8872ed8c6d]\ attempting to read dynamically indexed view heap slot \[heap 330192: null]\ (passed via user data register \u8 = 0xa13a00\).

Because \crates/victory-gpu/src/descriptor/host.rs\ deferred buffer view mirroring on creation (\let later = !for_draw && view.is_buffer();\), slot 330192 was populated with a null descriptor. Shaders dynamically computing heap offsets at runtime bypass static descriptor tables and therefore never triggered instantiation of the real SRV/UAV before the draw.

The fix mirrors buffer views immediately upon creation if their host shadow exists, and keeps \made[index] = 0\ as a null fallback only when backing memory is not yet registered.

Full technical details and branch:
https://github.com/Marvisak/VIctory/issues/619#issuecomment-7126076304

### Comment 4 — @Vaximous — 2026-11-24T11:01:09Z

A likely cause of this NVIDIA world hang, with a fix: https://github.com/Marvisak/VIctory/pull/307#issuecomment-7128461640

Short version:
- Pixel shaders with waterfall loops over a per-lane descriptor index (`v_readfirstlane` → `v_cmpx_eq` → `s_andn2_wrexec`) rely on whole-quad mode putting helper lanes in EXEC on the console. On the host, `WaveReadLaneFirst` skips helper lanes. Once only helper lanes are left, no lane matches, and each one runs to the translator's loop limit.
- On an RTX 4070 Ti this showed up as world submissions of ~1.16 s every frame (single draws of 0.3-1.3 s), until one passed the 2 s TDR: `DEVICE_HUNG` 200-260 s into the world. DRED stopped at the same instanced draws each time.
- Fix: in pixel shaders, a helper lane's `v_readfirstlane` takes its own value. After the fix there were zero slow submissions, and two runs of 363 s and 366 s in the world with no device removal.
- Upstream main still lowers `v_readfirstlane` to a plain `WaveReadLaneFirst`, so this should apply there too.
