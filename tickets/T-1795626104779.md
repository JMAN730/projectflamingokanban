### Comment 2 — @LAKSHYA-cmd-tech — 2026-11-24T07:46:51Z

﻿This pool exhaustion (`INSTANCE_LIST: 45000/45000`) is directly coupled with the dynamic descriptor exhaustion and dropped draws during world load.

Here is the chain of events:
1. **Instance Culling & Unknown Stride**: As identified in PR #704, the title's world geometry and instance-culling compute shaders select structured buffers via runtime heap indices. Previously, unknown-stride structured buffers failed translation or returned zeros on Nvidia due to typed/structured view mismatches, causing instance-culling passes to drop output.
2. **Descriptor Pool Depletion**: When dynamic descriptor heaps hit their ceiling (e.g. 65,536 on Nvidia), `HostHeap::dynamic` drops further draws/dispatches. Unexecuted lists leave their allocated instance lists unconsumed in the guest heap.
3. **Remediation**:
   - Applying **PR #688** (`dynamic-slot-reclaim`) allows dynamic descriptor slots of executed command lists to be reclaimed, preventing the dynamic descriptor pool from saturating at 65,536.
   - Applying **PR #704** ensures unknown-stride structured buffer reads resolve to raw views with matching byte offsets, allowing the instance culling shaders to complete correctly.
   - Together with **PR #653 fixes** (lowering untracked/constant masks in `v_cndmask_b32` and `_co_ci_u32`), the instance-culling compute pipelines will no longer abort translation or drop dispatches.

### Comment 6 — @LAKSHYA-cmd-tech — 2026-11-24T09:56:22Z

Regarding the `INSTANCE_LIST` pool overflow (45,000/45,000) and the 3D scene remaining black:

The root cause is in `crates/victory-gpu/src/list.rs:1074` (`dispatch_mesh_x`). In GTA VI, 3D world geometry instances are dispatched via indirect mesh dispatches (`indirect != 0`). However, `dispatch_mesh_x` previously contained:
```rust
if indirect != 0 {
    static ONCE: std::sync::Once = std::sync::Once::new();
    ONCE.call_once(|| tracing::warn!("indirect mesh dispatches dropped"));
    return;
}
```
Because every indirect mesh dispatch was dropped, none of the world geometry instances were drawn or retired. Instance allocations continued to accumulate until the engine hit its 45,000 pool limit and asserted with `0x80000003`.

The backend indirect execution infrastructure (`State::execute_indirect` in `draw.rs` with `kind = 10` (MESH) and stride 12, as well as the argument clamp in `indirect.rs`) is already fully implemented. We have patched `dispatch_mesh_x` to execute them:
```rust
if indirect != 0 {
    const MESH: u32 = 10;
    const STRIDE: u32 = 12;
    with_state(this, |list, s| {
        s.execute_indirect(list, (MESH, STRIDE, x.max(1)), indirect, None);
    });
    return;
}
```

The fix and synthetic tests are available in branch:
`https://github.com/LAKSHYA-cmd-tech/VIctory/tree/fix/gpu-indirect-mesh-dispatch`
(PR: https://github.com/LAKSHYA-cmd-tech/VIctory/pull/2)

### Comment 12 — @SantannaCarlos — 2026-11-24T18:57:13Z

Notes on what the title's `int3` at `+0x5149aec` stops on, from the executable and a 15-minute RTX 4070 run that read the pools every frame. No cause found yet; offsets only, no title bytes.

**Which pool stops the title.** `+0x5149aec` is in the allocator at `+0x5149980`, which serves only the **Building** and **Object** pools (chosen by type through a function table) and breaks when that pool's free list is empty or its base is null. INSTANCE_LIST is entity type 12, the CEntityBatch pool, with its own allocator (`+0x51e6c50`).
