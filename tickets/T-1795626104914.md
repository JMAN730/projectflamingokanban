## Original body

`suggestions_follow_the_use` in `crates/victory-hle/src/modules/xg.rs` tests three of the four branches of `XGSuggestSwizzleMode` but never exercises the `TEXTURE_1D` branch, which is the first check in the helper.

## Implementation evidence

`xg.rs`, `fn suggested()`, line 58:

```rust
fn suggested(desc: &ResourceDesc) -> Swizzle {
    if desc.dimension == TEXTURE_1D {   // TEXTURE_1D = 2
        Swizzle::LINEAR                 // → output 0x100 (SWIZZLED | LINEAR)
    } else if desc.flags & ALLOW_DEPTH_STENCIL != 0 {
        Swizzle::SW_64KB_Z_X            // → 0x118
    } else if desc.flags & ALLOW_RENDER_TARGET != 0 {
        Swizzle::SW_64KB_R_X            // → 0x11b
    } else {
        Swizzle::SW_4KB_S               // → 0x105
    }
}
```

`XGSuggestSwizzleMode` returns `SWIZZLED | suggested(desc).0`. For a 1D texture this is `0x100 | 0 = 0x100`.

## Missing test

`fn suggestions_follow_the_use()` (line 657) constructs its descriptor with `desc(256, 256, 1, 98, 0)` which always sets `dimension: 3` (TEXTURE_2D). The test then varies `flags` to reach the depth-stencil and render-target branches and the else-branch, but never changes `dimension` to `TEXTURE_1D (= 2)`.

The three covered branches produce `0x118`, `0x11b`, and `0x105`. The `TEXTURE_1D` branch producing `0x100` is never asserted.

## Why it matters

According to the D3D12 / Xbox GDK specification, 1D textures must use row-major (linear) layout — there is no tiled 1D swizzle mode. If the branch were accidentally removed or its condition changed to something else (e.g., `TEXTURE_3D`), no test would catch the regression, and titles that query `XGSuggestSwizzleMode` for a 1D texture would receive a wrong swizzle mode.

## Suggested fix

Add a single assertion to `suggestions_follow_the_use`:

```rust
// TEXTURE_1D → LINEAR (the only swizzle valid for 1D textures).
let mut d1d = desc(256, 1, 1, 10, 0); // R16_FLOAT, 1D dimensions
d1d.dimension = TEXTURE_1D;
XGSuggestSwizzleMode(&d1d, 0, &mut out);
assert_eq!(out, 0x100); // SWIZZLED | LINEAR
```

`cargo test -p victory-hle` — the new assertion passes, all existing assertions still pass. No GPU or game data needed.

**AI-assisted:** found with Kiro (Claude) and independently confirmed by five separate analysis passes without cross-contamination; no hardware run, no game data.
