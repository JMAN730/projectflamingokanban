## What changed

The title's geometry pipelines (`VS_VoxelizeGeneric_*` + `GS_VoxelizeGeneric_*` + `PS_VoxelizeVisiblity_*`, 195 GS records, 13 distinct triples) use the console's legacy merged ES-GS with both rings on chip: the vertex container's `Es` program writes each vertex to the ESGS ring in LDS, and the `Gs` program reads three vertices from it, writes its emitted vertices to the GSVS ring in LDS and signals them with `s_sendmsg` `GS_OP_EMIT` / `GS_OP_CUT`, with no `exp`. Today every GS fails with "resources: an address in an SGPR that is no root parameter" (the ring-table pointer in user data 0/1), and pipelines with a geometry stage get no host pipeline.

**The record.** Each `Gs` record embeds its copy shader: the `Gs` stage data holds a complete 0x54-byte record for it at +0x34 (code at the end of the payload) and Vs-style stage data at +0x88, so `vs_io` reads its outputs. The GSVS vertex size is at +0x28c (4 + 4 x outputs dwords), the max vertex count at +0x284.

**Translation (6e8f760).**
- `native.rs`: `StageIo::Gs(GeometryIo)` (the copy shader's code and outputs, max vertices, GSVS vertex size); `Es` stage data parsed like a VS.
- `io.rs` `rings()`: classifies LDS accesses by their address: input vertex k's offset (v0 lo/hi, v1 lo) plus a constant is an ESGS read of vertex k; lane index times a stride plus a uniform is the lane's own ring slot. `copy_exports()` decodes the copy shader generically: which GSVS dword or constant each `exp pos0` / `exp param<n>` component takes.
- `lower.rs`: `Es` ring writes become `storeOutput` (param n = row n); its closing `s_setpc` to the GS becomes a return. `Gs` ring reads become `loadInput` with the vertex index; GSVS writes go to a per-thread array; at `GS_OP_EMIT` the copy shader's outputs are stored from that array and `emitStream` follows; `GS_OP_CUT` is `cutStream`. Outputs are named as a normal VS's, so the title's pixel shaders link.
- `gs_6_6` with geometry state metadata (triangle in, triangle strip out, max vertices from the record, one stream), PSV0 geometry fields.
- The prologue's GS lane-count `exec` setup becomes a no-op: on the host every invocation is a real primitive.
- `victory translate` counts geometry programs and the ES halves of vertex containers.

**GPU (828f825).**
- `emit::translate_stage(container, HwStage)`; `shader_cache::host_shader` takes the stage, with a separate cache key for the ES translation.
- `pipeline.rs`: `Program { Main, Es, Gs }`. A vertex container in a pipeline with a geometry stage is translated as its `Es` program; one container can be a VS in one pipeline and an ES in another.
- `pipeline/host.rs`: the PSO gets the GS bytecode and its root parameters at geometry visibility (user data at `b0`, root views, static samplers, like the other stages); topology type triangle. Pipelines without a GS keep their exact behaviour and library names.

Shortcuts (marked in code): triangle input and triangle-strip output are fixed; the ES vertex and instance IDs are taken from v5 and v8 (the VS's plus 5); one output stream.
