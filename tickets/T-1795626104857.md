## Original body

`6638098` ("Shaders: per-lane descriptors chosen by control flow", merged with #566 on 2026-11-24 at 09:53) added a fourth parameter to `victory_shader::resource::track`:

```rust
pub fn track(p: &Program, layout: &[RootParam], stage: HwStage, lanes: Option<&Structured>)
```

`main` itself builds and passes (342 passed / 6 ignored at `ffe310e`). But **63 open PRs added new calls with the old three arguments**. When this was filed, each of them broke `cargo test --workspace` once merged:

```
error[E0061]: this function takes 4 arguments but 3 arguments were supplied
   |     resource::track(&p, &native.layout, native.stage)
   |     argument #4 of type `Option<&structure::Structured>` is missing
```

**The fix in each PR** is to pass the fourth argument at the call the PR adds. `main`'s own tests pass `Some(&st)` (the structured program); `None` keeps the old behaviour the test was written against. I checked `None` on 7 of these PRs (#200, #171, #166, #165, #142, #265, #160): with it, each PR's tests pass on an RTX 5060 and Clippy is clean.

**The risky ones: GitHub shows these as mergeable**, because there is no text conflict. CI was added at 08:55 and only runs when an author pushes again, so when this was filed none of them showed a red check.

*Updated 2026-11-24, 17:56 UTC, with the check below run on each PR's current head.*

Still adding a three-argument call (4):

- #101 at `9fbd7e9`
- #694 at `efd02d5` (two calls)
- #705 at `ee037b0`
- #391 at `a3f219e`, now a draft

Fixed since this was filed (11):

Each of the 11 merges cleanly onto `ffe310e` and passes `cargo check --locked -p victory-shader --tests`. I also re-ran the full tests on the RTX 5060 for #265, #655 and #683: they pass with no local change. #164 had the same problem and was fixed earlier, at `e469b7c`.

The [CI run on the other mergeable PRs](https://github.com/Marvisak/VIctory/issues/1184) found more build breaks of the same kind, from other signature changes on `main`.

**The other 48 already conflict with `main`.** When their authors rebase, git won't flag the old call, so it needs fixing by hand at the same time:

#69, #91, #92, #109, #116, #138, #145, #156, #157, #162, #189, #192, #193, #223, #226, #231, #233, #269, #292, #294, #298, #305, #306, #309, #317, #320, #328, #329, #332, #342, #383, #385, #395, #404, #498, #499, #526, #542, #551, #576, #586, #645, #650, #660, #667, #704, #709, #710

**How I found them:** no build, just a diff check. For each open PR head, the lines it adds under `crates/victory-shader/src` (diffed against its merge base with `main`) were searched for a `track(` call that ends at the stage argument. One match (#667) splits the call over several lines, and I checked it by hand. A PR author can check their own branch the same way:

```sh
git diff origin/main...HEAD -- crates/victory-shader/src | grep -E '^\+.*\btrack\(' | grep -vE 'Some\(|None\)|lanes'
```

No game files involved. AI-assisted (Claude Code).
