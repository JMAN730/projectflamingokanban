## Original body

## Environment

- VIctory commit `d2a4bae1f49533ef5cb512fd1b1ba1513f2e1989` (2026-11-24), built with Rust 1.98.1 (pinned toolchain)
- Windows 11 (build 26100), x64
- GPU: NVIDIA GeForce RTX 3060, driver 32.0.16.2124
- CPU: AMD Ryzen 7 5700X, 32 GB RAM
- Game files on an HDD, cache and data on an SSD (`cache_dir`, `data_dir` in `victory.toml`)
- Builds used: `--release` and `--profile diag --features diagnostics`
- D3D12 debug layer: Graphics Tools installed (`d3d12SDKLayers.dll` present), `VICTORY_D3D12_DEBUG=1`

## What happens

1. Boot, first-boot screens, language/settings and loading work as in the README.
2. Entering the world, the first mission's title card ("2 years ago") renders.
3. **Release build, no debug layer:** the host GPU is removed during a submission of 31-32 lists:
   `device removed ... (0x887A0006)`, plus `0x887A0004` as the reason, `no breadcrumbs`. Exit code 5. `crashes.log` contains the same line. Reproduced 3 times, all in the same place.
4. **`diag` build with the D3D12 debug layer on:** no device removal this time, but the world has **no image**. Dialogue audio plays. Run reached frame 13029. A warning reported `black_frames=5`.

## Findings from the diagnostics run

### 1. Wave64 compute shaders on a 32-lane GPU (NVIDIA-specific)

135 warnings of the form:

> `ID3D12Device::CreateComputeShader: Shader wants wave lane count of 64 but maximum wave lane count for device is 32.`

112 distinct compute pipelines were then refused:

> `host pipeline refused error=El parámetro no es correcto. (0x80070057) shaders=[compute <hash>]`

This matches the README note that some compute programs need 64-lane waves. On NVIDIA (32 lanes) those pipelines are never created, so anything depending on them is dropped.

### 2. Shaders that do not translate

331 distinct shaders log `shader does not translate; its pipelines' draws are dropped`. The most frequent reasons in this run (first 60 chars of the message, counts include repeats):

| Count | Reason |
|------:|--------|
| 74 | a select on an untracked ... |
| 66 | a lane mask holding lanes ... |
| 35 | an address in an SGPR that ... |
| 31 | a structured buffer of ... |
| 17 | an address not from a root ... |
| 16 | a scalar memory read as data ... |
| 16 | a descriptor read only as ... |
| 13 | a descriptor neither loaded ... |

These are probably the known "untranslated shaders" gaps from the README, but I'm listing them in case the counts on a different GPU/driver help. Counts differ slightly between runs because the loaded shader set differs.

### 3. Resource-state mismatches reported by the debug layer

224 warnings from `ExecuteCommandLists` and 18 from `DrawIndexedInstanced`, e.g.:

> `ResourceBarrier ... Before state (0x8: UNORDERED_ACCESS) of resource ... specified by transition barrier does not match with the current resource state (0x1: VERTEX_AND_CONSTANT_BUFFER) (assumed at first use)`

> `IASetVertexBuffers ... Resource state (0x8: UNORDERED_ACCESS) ... is invalid for use as a vertex buffer. Expected: 0x1 VERTEX_AND_CONSTANT_BUFFER, Actual: 0x8 UNORDERED_ACCESS`

My guess (not verified): a buffer written by compute and then used as vertex/constant data does not get the right transition. That could plausibly be related to the device-removed in the release build, but I have no evidence beyond the timing. Happy to test patches.

### 4. Other warnings (counts only)

- 596 + 306 `ID3D12PipelineLibrary::Load*Pipeline` warnings (library does not match / state differs) and 312 `StorePipeline` name collisions.
- 26 `slow host submission` warnings (lists=11 and lists=32, several seconds each).

## Questions

- Is wave64 on 32-lane GPUs something you plan to support (e.g. with `WaveSize`/emulated lane masks)? XCL's README mentions a slower workaround for NVIDIA.
- Would a `VICTORY_D3D12_DEBUG=1` log of the barrier warnings be useful in a specific format?
- Anything else you want me to capture on an RTX 3060? I can run builds and share logs.

## Notes

- No game data is attached. Only shader hashes and log messages appear above; full logs available on request.
- I only used the diagnostics build for the second run; the first two were the plain release build.
