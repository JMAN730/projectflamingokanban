## Original body

## What's wrong

While running VIctory on an NVIDIA RTX 3060 Ti, the application crashes with `DXGI_ERROR_DEVICE_HUNG (0x887A0006)`.

Before the crash, multiple shaders fail to translate and several successfully translated compute shaders are rejected during host pipeline creation with `E_INVALIDARG (0x80070057)`.

## Crash details

The final GPU submission takes 4,850 ms and contains 30 command lists:

```
WARN victory_gpu::host: slow host submission ms=4850 lists=30
ERROR victory_gpu::host: host GPU device removed after a submission of 30 lists
```

DRED breadcrumbs are unavailable (`0x887A0004`). A subsequent mesh pipeline also fails with `DXGI_ERROR_DEVICE_REMOVED (0x887A0005)`.

Affected pipeline:

```
mesh ecfe2f8317bda619
pixel 16053957ff2dff5c
```

## Shader translation failures

Some affected shaders:

- `2d0cace65bc05bb2` — barycentrics read directly is not supported.
- `3cea4534bbc15632` — an address in an SGPR that is no root parameter is not supported.
- `f6e47efa50226beb` — same SGPR error.

## Host pipeline failures

The following compute shaders translate successfully but their host pipelines are refused with `0x80070057`:

- `bfad8c6743ac5977`
- `0e90505eff274aa4`
- `1f1fbd86759b3da2`
- `b96880482a17f632`
- `e4a9f58e3acfcf7b`
- `c4183d3cbee28e8e`

## Test environment

- GPU: NVIDIA GeForce RTX 3060 Ti
- CPU: AMD Ryzen 5 3600
- RAM: 16 GB
- OS: Windows 11
- Build: Release
- Test date: 2026-11-24

## Possible investigation

The exact GPU command responsible for the device hang has not been identified. Further testing with `VICTORY_D3D12_DEBUG=1` and `VICTORY_D3D12_DRED=1` may help identify the failing command.

No source code changes or fixes have been tested. This report is intended to provide additional NVIDIA hardware testing data to the developers.
