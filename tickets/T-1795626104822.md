## Original body

## What's wrong

`GetProcAddress` on one of our pseudo modules, such as the handle `LoadLibrary("xgameruntime.dll")` returns, can return NULL without setting the last error. That happens in two places in `crates/victory-hle/src/modules/kernel.rs:158-175`:
- for an ordinal, since we export by name only;
- for a name the module doesn't export.

Microsoft's docs for `GetProcAddress` say that on failure it returns NULL and `GetLastError` gives the reason. Windows sets `ERROR_PROC_NOT_FOUND` (127). Code that turns the failure into `HRESULT_FROM_WIN32(GetLastError())` gets `HRESULT_FROM_WIN32(0)` here, which is `S_OK`, and carries on as if the lookup worked. `find_module` in the same file already sets `ERROR_MOD_NOT_FOUND` for a missing module.

I haven't seen a title depend on this. It's a small correctness fix.

## Repro

Each call below comes after `SetLastError(0)`:
- `GetProcAddress(GetModuleHandleW(L"kernel32.dll"), "NotAnExport")`, which goes to the host: NULL, last error 127.
- `GetProcAddress(LoadLibraryA("xgameruntime.dll"), "NotAnExport")`: NULL, last error **0**.
- The same with ordinal 9999: NULL, last error **0**.

## Fix

- **Branch:** https://github.com/Peppacodes/VIctory/tree/fix/getprocaddress-last-error
- **Compare:** https://github.com/Marvisak/VIctory/compare/main...Peppacodes:VIctory:fix/getprocaddress-last-error
- **Commit:** `d0662f4`, rebased on `main` (`ffe310e`), 0 commits behind it. One file, with its test.

Both failure paths now call `host::set_last_error(ERROR_PROC_NOT_FOUND)` before returning NULL.

Related: #512 makes ordinals resolve on pseudo-module handles, and unexported ordinals still return NULL there. This change sets the last error for those as well. The two touch neighbouring lines in the same function.

## Test

`a_missing_export_of_our_modules_sets_the_last_error`, in `kernel.rs`'s tests:
- It clears the last error before each lookup.
- First a missing name on the host's kernel32, for comparison.
- Then a missing name and an ordinal on `xgameruntime.dll`.
- It fails on `main` (`left: 0`, `right: 127`) and passes with the fix.
