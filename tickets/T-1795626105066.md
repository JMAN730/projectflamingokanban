## Original body

## Summary

VIctory crashes during System Init at `XSystemGetConsoleId()` before reaching any menu. Reproducible on both WARP and real GPU.

## Reproduction

1. Copy `victory.example.toml` to `victory.toml` outside the repo, point `game_dir` at an unpacked Xbox Series dump of `game_scarlett_master.exe` (build 1.0.2.1).
2. `cargo build --release -p victory`
3. `target\release\victory.exe run <exe> --execute` (with or without `VICTORY_D3D12_WARP=1`, identical result)

## Observed behavior

Title maps the image, binds imports (88 hle, 427 host, 72 missing), detects Xbox Series X, connects gameinput devices, starts dstorage workers — then crashes:

```
VIctory: unhandled exception 0x80000003 at victory-image-b99f876b74d4a77f.dll+0x2237178
```

Stack top frames all point into `victory-image-...dll+0x2237178` (`XSystemGetConsoleId()`).

Crash log records `Game State: System Init [T:71155682]`, `TitleID: 00000000`, `Console Type: Anaconda`, `Sandbox: RETAIL`, `Locale: EU`, `SKU: ROW`.

Exit code: -2147483645.

## Expected behavior

Title should proceed past System Init to first-boot screens / menus.

## Environment

- Windows 11
- Built from main on 2026-11-24
- Tested both WARP adapter and real D3D12 GPU — identical crash

## Crash artifacts (outside the repo, per asset policy)

`crashes.log` and minidump written under `%LOCALAPPDATA%\victory\data\00000000\`. Not attached here because the repository must not contain game-derived data; available on request.

## Notes

72 missing imports include XboxBvhBuilder, amd_fidelityfx_loader_xbox, libHttpClient.GDK, Bink2Scarlett. TitleID reads `00000000`, suggesting console identity is not yet provided by victory's `xgameruntime` HLE, which may be why `XSystemGetConsoleId` hits a breakpoint.

This is an early-boot crash, pre-menu, so it blocks reaching any menu or the world.
