### Summary
Implements `ID3D12GraphicsCommandList::ClearState` (vtable slot `11`, `0x58`) in `victory-gpu` across both older (`LIST_FUNCTIONS`) and newer (`NEWER_LIST_FUNCTIONS`) console command-list layouts.

Because external PR creation is currently restricted (`collaborators_only`), the CI-green branch is ready on my fork for cherry-pick / review:
- **Branch**: `geiyiliyabumo/VIctory@feat/list-clear-state`
- **Commit**: `geiyiliyabumo/VIctory@d57ea67` (based on `main` `ffe310e`)

### Changes
- `crates/victory-gpu/src/draw.rs`:
  - Added `State::clear(&mut self, pipeline: This)` resetting guest bindings (`pipeline`, `heaps`, `graphics`, `compute`, `vertex`, `index`, `targets`, `depth`, `topology`) and cached host state (`host_pipeline`, `host_roots`, `host_heaps`, `fresh_tables`, `table_failed`) while preserving `self.dynamic` descriptor slots still referenced by earlier recorded commands in the same list.
  - Added unit test `draw::clear_state_tests::clear_resets_bindings_but_retains_dynamic_slots`.
- `crates/victory-gpu/src/list.rs`:
  - Added `clear_state(this: This, pipeline: This)` wired at slot `11` (`0x58`) in `METHODS` (shared by both `LIST_FUNCTIONS` and `NEWER_LIST_FUNCTIONS`).
  - Calls `unsafe { host.list.ClearState(None) }` (leaving translated host pipeline binding lazy on the next draw/dispatch), resets guest state via `state.clear(pipeline)`, preserves `HostList::states` resource-state tracking, and records a `diagnostics` op note when enabled.
  - Added tests `list::tests::clear_state_slot_is_stable` and `list::tests::clear_state_preserves_recorded_gpu_commands` (clears pixel 0 red before `ClearState`, verifies tracked `RENDER_TARGET` state survives `ClearState`, clears pixel 1 green after `ClearState`, submits and verifies `[255, 0, 0, 255, 0, 255, 0, 255]` readback).

Melissa checked ClearState together with #158, which adds a dynamic depth range to the list. The two patches apply cleanly, but the saved range survives ClearState and the next bind replays it. With depth cleared to 0.5, a draw after ClearState still failed the old bounds and left 0.5 in the pixel. A draw after Reset wrote the expected 0.25.

Earlier recorded commands can still use those slots. On RTX 4090 under Wine/vkd3d-proton 3.2, the draw after ClearState then wrote 0.25. The vertex and mesh readbacks covered fresh, excluded, included, cleared, and reset states. All three original ClearState controls passed, including the two recorded clears.

This is a synthetic result on the combined branches. On #848 alone, the saved-depth-bounds field does not exist. The helper change and readback are available in the [integration commit](https://github.com/MichaelSmithAI/VIctory/commit/5beacc44d558f58b58cfca08e18409303354cb91).
