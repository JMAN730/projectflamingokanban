## Original body

## What's wrong

`map_dll` (`crates/victory-loader/src/windows.rs:149-151`) lowercases a title DLL's name and joins that to the title folder:

```rust
let name = name.to_ascii_lowercase();
let path = dirs.0.join(&name);
if !seen.insert(name.clone()) || !wanted(&name) || !path.is_file() {
    return Ok(());
}
```

In an ordinary NTFS folder that works, because lookups ignore case. In a case-sensitive folder, `GameLib.dll` and `gamelib.dll` are different names, so `is_file()` is false and the DLL is skipped with `Ok(())`. Both callers go through it:
- `load_title_dlls`, for the exe's imports at start-up.
- `load_title_dll`, for a title's own `LoadLibrary`, which then reports "not a title image".

WSL creates folders on Windows drives as case-sensitive, and new subfolders inherit the flag. So a dump extracted with Linux tools under WSL gets it.

What a user sees: the DLL is never mapped and its imports go to stubs. With the default `--unimplemented trap`, the run stops at the first call into it, and nothing says the DLL wasn't found.

## Repro

`Late.dll` (a copy of `version.dll`) is in a case-sensitive temp folder.
- `load_title_dll` returns no DLLs for `Late.dll`, `LATE.DLL` and `late.dll`, including the exact spelling.
- In an ordinary folder it maps all three.

## Fix

- **Branch:** https://github.com/Peppacodes/VIctory/tree/fix/title-dll-name-case
- **Compare:** https://github.com/Marvisak/VIctory/compare/main...Peppacodes:VIctory:fix/title-dll-name-case
- **Commit:** `1e24f34`, rebased on `main` (`ffe310e`), 0 commits behind it. It changes `windows.rs` and its test.

What changed:
- The lowercased name is still the key for `seen`, `wanted` and the returned list, so callers get the same names as before.
- A new `file_in` looks the file up by the name as written. If that fails, it takes the folder's entry that matches ignoring ASCII case, the way the Windows loader ignores case.
- Error messages now show the file's real name.

## Test

`a_title_dll_in_a_case_sensitive_folder_is_found_by_any_spelling`, in `crates/victory-loader/tests/title_dlls.rs`:
- It makes a case-sensitive temp folder with `fsutil file setCaseSensitiveInfo` (no admin needed). It then loads `Late.dll` as `Late.dll`, `LATE.DLL` and `late.dll`.
- It fails on `main` (`left: []`) and passes with the fix.
- It skips where Windows can't make such a folder.

Results on Windows 11 with Rust 1.98.1, using the CI's own commands:
- `cargo test --workspace --locked`: 343 passed, 0 failed.
- `cargo clippy --workspace --all-targets --locked -- -D warnings`, with and without `--all-features`: clean.
- `rustfmt --edition 2024 --check` on the two changed files: clean.
- `cargo xtask policy`: 154 files ok.

Not checked: a folder WSL created itself, since the test sets the same flag directly; and case-sensitive network shares.

### Comment 1 — @MichaelSmithAI — 2026-11-24T10:27:15Z

I tested the lookup from `1e24f34` in Wine 11.22 on an ext4 directory using a source-built DLL. The directory contained a folder named `LATE.DLL` and a file named `late.dll`. A request for `LATE.dll` fell back to directory enumeration, which returned the folder first. Both `load_title_dll` and `load_title_dlls` returned an empty list.

The fallback can skip the folder by changing the first `.find(|e| …)` to `.filter(|e| …)` and the trailing `.filter(|p| p.is_file())` to `.find(|p| p.is_file())`. With just those two changes, both entry points returned `["late.dll"]` in the same fixture. The exact-name lookup and lowercase key stay as in your patch.
