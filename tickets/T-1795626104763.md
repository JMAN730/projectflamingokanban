## Original body

VIctory commit d2a4bae, AMD Radeon RX 6700 XT, driver 32.0.21045.29003.

In Series X mode, the menus work and the loading artwork appears. The hardware run crashes before the first mission title card with 0x887A0006 (DEVICE_HUNG) after submitting 31 command lists.

The diagnostics build with WARP and VICTORY_D3D12_DEBUG=1 runs at about 1 FPS and exits with 0x887A0005 (DEVICE_REMOVED) after submitting one command list. The available output has no command-specific D3D12 ERROR. Immediately before the crash, VIctory reports an unsupported lane-mask operation in compute shader e5742545a3591526. The link between that warning and the crash is unclear.

### Comment 4 — @wwwwwwww3333333 — 2026-11-24T05:08:18Z

One lead from your first DRED follow-up: the bindings `Uav s0+288: uav None` with `u4=0xa67100 [heap 340872: null]` are the same pattern as #508. On `d2a4bae`, a table slot with no view is a null **Texture2D SRV** (`HostHeap::fill_null` / `make_null`), so a compute shader writing it as a UAV through `ResourceDescriptorHeap[]` hits a descriptor-type mismatch. D3D12 leaves that undefined, and AMD hardware can fault on it.

Two open PRs make those slots null UAVs: #552 (all table paths; see my review there for a dimension fix it needs) and #135 (fresh tables, plus dropping draws whose tables can't be made). It'd be worth a run with either one on this card. If the page fault moves or goes away, that's useful signal; if `Uav … uav None` still shows up in the dump, the fault is likely elsewhere.

I can't tell from the logs whether the hardware runs (faults at `0x47fc000` / `0x5a44000`) hit the same dispatches. That link is unproven.

Source-level analysis; not runtime-tested with game files. *AI-assisted (Claude).*
