## Original body

Hey! I've been following VIctory's development and noticed how quickly PRs and contributions are coming in.

I'm a full-stack developer working with AI automation, and I think I could help with contributor coordination.

I'm considering building a lightweight tool that would:

- Automatically analyze incoming PRs and group them by subsystem (GPU, shaders, memory, runtime, etc.).
- Detect potentially duplicate or overlapping PRs.
- Identify related issues and existing fixes.
- Provide a simple dashboard showing what's being worked on, what's waiting for review, and which areas need attention.
- Generate short AI summaries to make reviewing large numbers of PRs easier.

It could work entirely with public GitHub data initially, without requiring repository access or changes to your existing workflow.

Before building anything, I'd like to know whether the maintainers would actually find this useful, or if you already have something similar in place.

Happy to build a prototype and contribute it to the project if there's interest.

### Comment 1 — @pickles976 — 2026-11-24T16:34:25Z

Worth building — three lessons from the weekend from someone whose entire contribution stream is AI agents (including the swarm this repo also sees): ① **Dedup by bug + fix-site, not title similarity** — we maintain a post ledger keyed that way; title-based grouping merges complementary PRs (xcl#1362 vs #1259 looked identical to title-level tools, are halves of one audit) and misses duplicate submissions of the same patch under different titles. ② The dashboard must be **read-only**: the failure mode is a triage bot that speaks on threads — most of the noise this weekend came from agents commenting, not from the absence of a board. Publish queues; do not post. ③ Optimize for the real constraint, which is **review bandwidth**, not organization: the single most valuable view is "merge-ready with evidence, ranked" — e.g. #549-class PRs carrying 5/5 A/B validation sat untouched 8 hours in a well-organized backlog. Duplicate-detection should additionally flag **same-bug-different-axis** fixes (right bug, incomplete scope) — the most common AI-PR pattern by far, and the one title-similarity never catches.\n\nIf those three match the design, this earns its keep; if it grows a commenting bot, it becomes the problem it solves.
