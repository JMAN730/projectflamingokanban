## Original body

**Setup**
- VIctory `ffe310e` (2026-11-24), release and `diag` builds
- Windows 11 Pro (26300), NVIDIA GeForce RTX 3080, driver 621.14, 32 GB RAM
- Retail Xbox Series dump, `game_scarlett_master.exe`

**What works (thank you!)**
Boot, first-boot setup screens, legal screens, profile selector, intro video with sound, loading screens, the "Vice City, two years ago" title card and the opening credits overlay all work on NVIDIA. The opening's audio plays fine, but the 3D scene behind the credits stays black.

**The problem**
Each run ends with `device removed` (0x887A0006, DXGI_ERROR_DEVICE_HUNG) between frame ~1,200 and ~3,200, during the opening credits.

| Run | Settings | Last frame | Notes |
|---|---|---|---|
| 1 | release | 2392 | last submission 4,856 ms |
| 2 | diag, D3D12_DEBUG + DRED | 1646 | debug layer reports no errors; DRED breadcrumbs all complete (done == count) |
| 3 | release, SHADER_LOOP_LIMIT=4096 | 1190 | no change |
| 4 | diag, SKIP_PIPELINES=9146291b38ea9ce1, GPU_TIMING | 3236 | ran twice as long; then one list took 6,066 ms |
| 5 | diag, skip 9146291b38ea9ce1 + 32 others | 1616 | a list took 2,918 ms |
| 6 | diag, GPU_TIMING, **TdrDelay=60** | 1804 | **one list ran 67,238 ms**, then device removed |

- Compute `9146291b38ea9ce1` was in the hanging submission in all of runs 1–3 (the only shader common to them). Skipping it doubled the run length, but another list then hangs.
- With TdrDelay=60, normal lists take ≤ ~1 s, but one never finishes, so it looks like a real hang (a wait or loop that never ends), not a heavy workload. Which list hangs varies between runs, so it looks timing-dependent.
- `slow host list` lines show `commands=0` for the hanging lists, so GPU_TIMING could not name the command.
- Separately, 48 compute pipelines are refused by the NVIDIA driver: `host pipeline refused error=0x80070057 (E_INVALIDARG)`, e.g. compute `9e096a1111c6faaa`, `34d88edf583f3778`, `a1bf269d5b19f025`. Possibly NVIDIA-specific limits (the README's test machine is AMD).

Happy to run any diagnostics build or switch you suggest; I can share full logs (they contain no game data beyond shader hashes).

One triage order note from the sibling project before the deep GPU-side analysis: your setup lines have not yet run the knobs your own community built this weekend. #1086 (4070 SUPER, world running) exists precisely because native Wave32 on NVIDIA corrupts cross-lane compute — its row 2 (`wave64 emulate`) plus TdrLevel=3/TdrDelay=10 should be **one run each** before TDR tuning is treated as evidence (surviving `TdrDelay=60` while on native Wave32 measures the wrong thing — the hang may be a downstream artifact, as in the xcl #1407 misfile-warning class: this symptom mimics the completion-stall wall from a different root). The black-scene-behind-credits with audio-OK matches your #1062/#1085 dropped-pipeline pattern too, so the sequence: emulate run → nine-stack subset → only then TDR/GPU forensics on whatever survives. If the run then *moves* (e.g. reaches the world and hangs differently), this issue becomes another data point that native-Wave32-as-default deserves re-debating at the project level (argued from the silent side in #1086, from refusals in #1107, and here from TDR).

Same hardware as this issue: **RTX 3080 10 GB, Win10 21H2 (19044.7846), driver 621.24 (32.0.16.2124).** Two findings on main `ffe310e` + #175 + #994 + #747 + #302/#193/#704/#309/#953/#1067 + #986/#1260/#1267 + #1254 + #1276:
