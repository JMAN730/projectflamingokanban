## Original body

Problem

The victory-loader integration test loads_binds_and_calls_probe builds its HLE probe fixture by invoking Cargo at runtime.

When running Windows-targeted tests on Linux through Wine, the test executable attempts to launch the Linux Cargo binary from the Windows test process. This prevents the integration test from running in this environment.

Proposed change

This patch adds an optional VICTORY_HLE_PROBE_DLL environment variable to build_probe().

When set, the test uses the supplied prebuilt DLL.

The path is checked before use.

When unset, the existing behavior is preserved: the fixture is built through Cargo as before.

This keeps the normal Windows CI workflow unchanged while allowing cross-platform test runners to provide a Windows fixture built in advance.

Validation

Tested on Fedora Linux with Wine, targeting x86_64-pc-windows-msvc.

victory-loader package tests: 25 passed, 0 failed.

Integration tests in load_probe: 2 passed, 0 failed.

The HLE probe DLL was built separately for the Windows MSVC target.

This is a test-infrastructure change. It does not modify loader behavior or claim official Linux/Wine support.
