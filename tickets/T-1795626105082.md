## Original body

**Hardware / software**
- GPU: NVIDIA GeForce RTX 5080, driver 32.0.16.1742 (the PC also has Intel integrated graphics; VIctory set to High performance in Windows graphics settings)
- CPU: Intel Core Ultra 7 270K Plus
- OS: Windows 11 Pro, build 26200
- VIctory: `ffe310e`, release build

**What happens**
Boot, menus and loading work. In the world, VIctory runs for ~1,200 frames at ~1.3 fps (766 ms/frame: 380 ms preparing, incl. 250 MB of copies; 263 ms on the GPU; 2,764 draws/frame, 1,196 dropped without a host pipeline, 3,698 indirect). Dialogue and subtitles play. Then a 3.8 s submission (29 lists) is followed by device removal (0x887A0006), and VIctory exits. Audio stutters during that stall.

```
INFO victory_gpu::host: 1.3 fps, 766.6 ms/frame (379.9 preparing: copies 255.5 ms 249.5 MB, textures 18.4 ms 111.2 MB; 263.3 on the GPU; 106.0 copying back 8.5 MB), 2764 draws/frame, dropped 1196 without a host pipeline (0 being made) and 3698 indirect
WARN victory_gpu::host: slow host submission ms=3842 lists=29 pipelines={...}
ERROR victory_gpu::host: host GPU device removed after a submission of 29 lists; no breadcrumbs (The specified device interface or feature level is not supported on this system. (0x887A0004)); device removed: The GPU will not respond to more commands, most likely because of an invalid command passed by the calling application. (0x887A0006)
```

Also logged in the world: `a draw or dispatch dropped: no dynamic slots for its tables dropped=8192`.

**With the debug layer** (diag build, `VICTORY_D3D12_DEBUG=1 VICTORY_D3D12_DRED=1`, same GPU)

The world runs at ~1 fps until a hang (`DXGI_ERROR_DEVICE_HUNG`, TDR) after a 3.3 s submission of 28 lists. Starting about 25 s before the hang, the debug layer reports the same resource-state mismatch 73 times, always on one buffer: `title buffer 0x1e820000+0xae00000` (182,452,224 bytes; mesh and compute pipelines bind it as an SRV at `0x1e820000`):

```
D3D12: ID3D12CommandQueue1::ExecuteCommandLists: Using IASetVertexBuffers on Command List (...): Resource state (0x8: D3D12_RESOURCE_STATE_UNORDERED_ACCESS) of resource (...:'title buffer 0x1e820000+0xae00000') (subresource: 0) is invalid for use as a vertex buffer.  Expected State Bits (all): 0x1: D3D12_RESOURCE_STATE_VERTEX_AND_CONSTANT_BUFFER, Actual State: 0x8: D3D12_RESOURCE_STATE_UNORDERED_ACCESS, Missing State: 0x1: D3D12_RESOURCE_STATE_VERTEX_AND_CONSTANT_BUFFER.
D3D12: ID3D12CommandQueue1::ExecuteCommandLists: Using ResourceBarrier on Command List (...): Before state (0x8: D3D12_RESOURCE_STATE_UNORDERED_ACCESS) of resource (...:'title buffer 0x1e820000+0xae00000') (subresource: 0) specified by transition barrier does not match with the current resource state (0x1: D3D12_RESOURCE_STATE_VERTEX_AND_CONSTANT_BUFFER) (promoted from COMMON state)
```

The state tracking for that buffer looks out of sync between lists: it's used as a vertex buffer while in UAV state, then a barrier expects UAV while it has been promoted to VERTEX_AND_CONSTANT_BUFFER.

DRED breadcrumbs: 480 lists complete; one stopped at **3/70**, and the four after it never started (0/1, 0/2, 0/2, 0/339). The mesh and compute work in flight (lists 24 and 27 of 28) binds that buffer. I can reproduce and run other diagnostics on request (full log not attached, per the no-game-data rule).

Before the world, the debug build also logs `no host texture error=The parameter is incorrect. (0x80070057)` for 2560x1440 textures (DXGI formats 86 and 115).

### Comment 2 — @JurajSimicevic — 2026-11-24T21:03:18Z

Tested #1691 (`667e7dc`) on the RTX 5080 from this issue (driver 32.0.16.1742, Windows 11 26200), diag build with `VICTORY_D3D12_DEBUG=1 VICTORY_D3D12_DRED=1`, same route into the world as the original report.

**The state mismatch is fixed.** The debug layer reports no resource-state errors at all now: 0 messages on that title buffer (it was 73 before), and no `ExecuteCommandLists` or `ResourceBarrier` validation errors of any kind. The new `shadow::tests::buffer_states_follow_submission_order_and_combine_reads` passes.

**The hang remains, so it has a second cause.** After ~20 frames in the world at ~0.9-1.5 fps, a 3.3 s submission ends in `DXGI_ERROR_DEVICE_HUNG` (TDR) again, with no validation error before it. DRED: 419 lists complete; one stopped at **654/1424**, and the lists after it never started. Without a validation message, it looks like GPU work that runs past the TDR timeout (or loops) rather than an invalid command.

Also from the debug layer on this GPU: 116 compute shaders are refused at creation with "Shader wants wave lane count of 64 but maximum wave lane count is 32", which matches the README's note about programs that need 64-lane waves.

Happy to run more diagnostics on this machine (for example with `VICTORY_D3D12_GBV=1`, or skipping pipelines) if that helps narrow down the hang.
