### Problem
In `crates/victory-formats/src/xma.rs`:
1. `Bits::signed(n)` (lines 192–194) performed:
   ```rust
   ((self.read(n) << (32 - n)) as i32) >> (32 - n)
   ```
   Unlike `read(n)` above it which checked `if n == 0 { return 0; }`, `signed(n)` did not check for `n == 0`. When `n == 0`, `32 - n` is `32`. Shifting a 32-bit integer by 32 bits (`val << 32` or `val >> 32`) is undefined behavior in C/C++ and triggers an unconditional overflow panic in Rust (`attempt to shift left with overflow`).
2. If `n > 32`, `32 - n` underflows `u32`, triggering an arithmetic underflow panic.
3. In `Bits::read(n)`, if `n >= 32`, computing `32 - n` also suffers from shift overflow or underflow.

### Fix
1. Guard `signed(n)`: return `0` when `n == 0`, and return `self.read(n) as i32` when `n >= 32`.
2. Guard `read(n)`: when `n >= 32`, return `self.peek32()` directly, advancing `self.pos += n as usize`.
3. Added synthetic unit test `bitstream_handles_zero_and_boundary_bit_widths` asserting `n == 0`, `n == 32`, and signed two's-complement parsing across boundary widths without panic.
