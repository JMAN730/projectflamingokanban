## Original body

## Description

Ran VIctory using a **customized diagnostic setup with forced WARP** (software rasterizer) to isolate host D3D12 / GPU issues.

The title (Xbox Series X build) boots, maps DLLs, opens the expected `.rpf` files via DirectStorage, and reaches the world-loading stage. Shortly after the first frames, the host device on the software adapter hits severe memory exhaustion, repeated `E_OUTOFMEMORY` (0x8007000E), access violations inside `d3d10warp.dll`, and finally device removal.

## Environment

- **VIctory**: build unknown (`b99f876b74d4a77f03af5f878223b27bd647b5c35a79d5decd9f716504239e93`)
- **Adapter**: Forced WARP (software rasterizer)
- **Console target**: Xbox Series X
- **Title**: `GTA6.Xbox.v1.0.2.1-CYBERLEEK` (virtual drive `G:`)
- **Presentation**: 3840×2160 SDR, ~30 fps
- **Host**: D3D12 device on software adapter (WARP)

## Observed behavior

1. Title loads normally (DLL mapping + DirectStorage opens of `appdata0.rpf`, `common.rpf`, `levels.rpf`, `textures.rpf`, `audio.rpf`, etc.).
2. Host device reports: `host device on the software adapter (WARP)`.
3. During early frame presentation / pipeline creation:
   - Descriptor heap capped at 1 000 000 → `E_OUTOFMEMORY` (0x8007000E)
   - Large buffer allocations fail (~182 MB shared/shadow buffer + repeated 4 MB upload buffers)
   - `ID3D12Device::CreateCommittedResource` returns `E_OUTOFMEMORY`
   - Live object reports show thousands of resources, heaps, command allocators and command lists
4. Multiple first-chance exceptions `0xc0000005` (access violation) inside `d3d10warp.dll` (`d3d10warp.dll+0x495f58`)
5. Device removed: `DXGI_ERROR_DEVICE_REMOVED` / `0x887A0005`
6. VIctory exits with code `-2005270523`

## Key log excerpts
host device on the software adapter (WARP)

host view heap capped at 1000000 error=There are not enough memory resources available to complete this operation. (0x8007000E)

no shared buffer error=... (0x8007000E) size=182452224

no upload buffer error=... (0x8007000E) size=4194304   (repeated many times)

ID3D12Device::CreateCommittedResource: Returning E_OUTOFMEMORY

VIctory: first-chance exception 0xc0000005 at d3d10warp.dll+0x495f58

ERROR victory_gpu::host: host GPU device removed ... (0x887A0005)

VIctory finished. Exit code: -2005270523
## Analysis

The failure is **memory exhaustion on the WARP software device**, not a missing import or early boot problem. Large resource allocations fail under the current host D3D12 path when running on WARP. The access violations inside `d3d10warp.dll` and the subsequent device-removed error are downstream of the OOM.

This matches the current project status (world is reached, rendering fails) and is reproducible under the forced-WARP diagnostic configuration.

## Expected behavior

- WARP should either succeed with better resource usage / allocation handling, or fail more gracefully with a clear diagnostic instead of cascading AVs + device removal.
- Memory pressure on the software rasterizer should be manageable for diagnostic runs (or at least report which resource sizes/types are the biggest consumers).

## Notes

- Full log available if needed (very long; the relevant sections are WARP device creation → repeated 0x8007000E → AV in d3d10warp → device removed).
- Ran specifically with a custom WARP diagnostic setup to isolate host GPU / memory behavior from hardware-specific issues.
