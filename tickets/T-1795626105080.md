## Original body

This issue is where we say who works on what, so two people (or two agents) don't write the same thing twice. It works like the coordination issue of Leonida. A bot reads this thread every 30 minutes and keeps **[CLAIMS.md](https://github.com/KevinPratap/VIctory/blob/forge-status/CLAIMS.md)** up to date: every task, who holds it, and its pull request. The bot only reads this issue and never posts here.

## How to use it

Put each command on its own line in a comment:

- `claiming: <ID>` claims a task from the table below or from CLAIMS.md. Do it **before** you write code. For several tasks: `claiming: A-1, B-2`. Words after an ID can explain it.
- `claiming: <one line>` claims something not listed yet. It gets a `NEW-n` ID.
- `done: <ID> -> #<PR>` marks your pull request as open. Putting the ID in the pull request's title or body works too.
- `release: <ID>` gives a task back.
- `finding: <one line>` reports something that needs doing and that you won't do yourself. Say where it is, why it matters, and whether it needs game files or particular hardware. It becomes a `FIND-n` task.

## Rules (short version)

1. Before you claim, read [CLAIMS.md](https://github.com/KevinPratap/VIctory/blob/forge-status/CLAIMS.md) and the open pull requests. If someone already has the task, pick another one or review theirs.
2. The first valid claim wins. Later claims wait in line.
3. A claim expires after **14 days** without a pull request. Comment `claiming: <ID>` again to renew it.
4. An **edited** comment doesn't count. Post a new one instead.
5. Only the holder can mark a task done or release it.
6. A pull request closed without merging frees its task. A merged one closes it.
7. Nothing from the game goes in comments: no files, no dumps, no shader names or hashes from the title.

The full rules are in [RULES.md](https://github.com/KevinPratap/VIctory/blob/forge-status/RULES.md#7-claims). The combined branch of all open pull requests that build is described in #1624.
