### Problem
In `crates/victory-game/src/sgd5.rs`, `record()` extracts packed shader container records from memory/archive slices by searching for the marker `0x000D_DCE7`. When verifying sizes and extracting the compressed stream:
1. Slicing offsets (`at + 12..at + n`) and header offsets (`at + 8`, `at + 4`) used unchecked `usize` addition, which can panic on integer overflow with hostile/corrupt inputs near memory boundaries.
2. Direct index operations (`file[at - 5]`, `file[nul]`) relied on unchecked indexing rather than slice bounds checks. If `at` was located near boundary conditions (such as invalid offsets where `at < 6`), slice index panics or underflows could occur.
3. `name_before` used unchecked indexing `file[l]` when scanning backwards for the name length byte.

### Fix
1. Replaced raw arithmetic with `checked_add` and `checked_sub` throughout `record()`:
   - `start = at.checked_add(12)?` and `end = at.checked_add(n)?` with validation that `start <= end`.
   - `u32_at` computes `o.checked_add(4)?` safely.
2. Replaced direct indexing with bounds-checked `.get()` (`file.get(nul) == Some(&0)`, `file.get(at.checked_sub(5)?)?`).
3. Guarded `name_before` with `.get()` on both length extraction and substring slice.

### Tests Added
Added `rejects_boundary_and_malformed_records` in `crates/victory-game/src/sgd5.rs` covering:
- Marker located near the start of the buffer (`at < 6`), asserting `None` without panic.
- Header declaring `n < 12`, asserting `None`.
- Header where size cross-checks disagree (`u32_at(at + 4) != n`), asserting `None`.
- Record with `unpacked_size > MAX_UNPACKED` (`64 MiB`), asserting `None`.
- Truncated payload where `n` exceeds available buffer length, asserting `None`.
