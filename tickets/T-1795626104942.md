### Problem
In `crates/victory-core/src/config.rs` (line 20), `data_dir` is documented:
> "What titles write and must keep (persistent local storage). Never inside the cache, which may be deleted at any time."

However, `default_dir` (lines 130–137) resolved both `"cache"` and `"data"` using the exact same fallback chain:
```rust
let base = std::env::var_os("LOCALAPPDATA")
    .or_else(|| std::env::var_os("XDG_CACHE_HOME"))
    .map(PathBuf::from)
    .or_else(|| std::env::var_os("HOME").map(|h| PathBuf::from(h).join(".cache")))
```
On Linux, macOS, and POSIX environments where `VICTORY_DATA_DIR` is not explicitly set in `victory.toml`, `data_dir` defaulted to `$XDG_CACHE_HOME/victory/data` or `$HOME/.cache/victory/data`. A routine cache purge (e.g. `rm -rf ~/.cache`) would unintentionally delete the user's persistent saves, local storage, and `crashes.log`.

Furthermore, `default_dir` read from `std::env::var_os` directly rather than the `env` closure passed into `Config::resolve`, preventing default directory resolution from being unit-tested in isolation without mutating process environment variables.

### Fix
1. Factor default directory lookup into `default_dir_with(&env, name)`.
2. For `"data"`, query `XDG_DATA_HOME` (and fallback `$HOME/.local/share`) before falling back to cache locations:
   - Windows continues using `%LOCALAPPDATA%\victory\data` (highest precedence).
   - Linux/macOS defaults `data_dir` to `$XDG_DATA_HOME/victory/data` or `$HOME/.local/share/victory/data`, keeping persistent data strictly outside the cache.
   - For `"cache"`, behavior is unchanged (`LOCALAPPDATA` -> `XDG_CACHE_HOME` -> `$HOME/.cache`).
3. Parameterizing with `&env` enables pure, deterministic unit testing of directory resolution.

### Tests Added
Added 3 synthetic unit tests in `crates/victory-core/src/config.rs`:
- `default_data_dir_uses_xdg_data_home_on_unix`: verifies `data_dir` resolves to `$XDG_DATA_HOME/victory/data` while `cache_dir` resolves to `$XDG_CACHE_HOME/victory/cache`.
- `default_data_dir_falls_back_to_local_share_with_home`: verifies that when only `HOME` is present, `data_dir` falls back to `$HOME/.local/share/victory/data` and not `$HOME/.cache`.
- `localappdata_takes_precedence_for_both`: verifies Windows `%LOCALAPPDATA%` takes precedence for both directories.
