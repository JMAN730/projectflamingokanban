## Original body

Diagnostics-only: this affects only `--features diagnostics` builds that run with device-removed data on.

## Problem

With DRED command notes on, world frames took 9-12 s instead of under 1 s. Most of the recording threads' time went to `VirtualQuery`.

Cause: `describe` in `crates/victory-gpu/src/draw.rs` runs for every draw and dispatch (through `op_text` → `reads`). For a constant view, it first asks `texture::committed`, which uses `VirtualQuery`, before it reads 16 bytes. In the title's big pools each query walks the region's pages, about 1 ms per call, and a world frame makes thousands of them.

## Fix

`first_words` reads the 16 bytes with `host::read_into` (ReadProcessMemory). That call fails on an unmapped page and does not walk the region. Output is unchanged. One file, `crates/victory-gpu/src/draw.rs`, +15/-3, all inside `#[cfg(feature = "diagnostics")]`.

## Branch

https://github.com/Vaximous/VIctory/compare/main...fix/dred-notes-readprocessmemory — commit f4b6a96, based on ffe310e.

## Tested

- `cargo test -p victory-gpu --features diagnostics`: 53 passed, 0 failed, 1 ignored. Clippy `-D warnings` is clean with and without `diagnostics`.
- Runtime (RTX 4070 Ti, Windows 11): measured on our local integration build (main plus a set of open PRs), not on plain main. In that build, placed buffer views' notes also read title words through the same check. Five recording threads spent about 77% of their time in `VirtualQuery`, and frames took 9-12 s. With `ReadProcessMemory` instead, frames were back under 1 s. Main only has the constant-view path, so the gain there may be smaller.

## Related

`texture::committed` is also used on hot non-diagnostic paths (`host.rs`, `list.rs`), and #322, #388 and #119 remove region queries there. This issue is only about the DRED note.
