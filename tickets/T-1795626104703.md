## Original body

## What happens

A few seconds after launch the title allocates 6.5 GB of physical pages and maps them. Windows refuses the commit, `xmem` only logs a warning, and the title then stops on a breakpoint (`0x80000003`). From the outside it looks like a title crash, not a memory limit on the host.

```
DEBUG victory_hle::modules::xmem: XMemAllocatePhysicalPages n=99776 flags=0x380
DEBUG victory_hle::modules::xmem: XMemVirtualAlloc size=6538919936 kind=0x42000 flags=0x23 at=0xe1c800000
 WARN victory_hle::modules::xmem: committing physical pages failed len=6538919936 error=The paging file is too small for this operation to complete. (os error 1455)
VIctory: first-chance exception 0x80000003 at victory-image-b99f876b74d4a77f.dll+0x1e6c29f
  #0  victory-image-b99f876b74d4a77f.dll+0x1e6c29f
  #1  victory-image-b99f876b74d4a77f.dll+0x19f5289
  #2  victory-image-b99f876b74d4a77f.dll+0x580437e
  #3  victory-image-b99f876b74d4a77f.dll+0x43a4911
  #4  victory-image-b99f876b74d4a77f.dll+0x224070b
  #5  victory-image-b99f876b74d4a77f.dll+0x23cf00a
  #6  victory-image-b99f876b74d4a77f.dll+0x2215eca
VIctory: unhandled exception 0x80000003 at victory-image-b99f876b74d4a77f.dll+0x1e6c29f
```

99776 pages × 64 KB = 6,538,919,936 bytes, the same size as the failed commit.

## Where

`map()` in `crates/victory-hle/src/modules/xmem.rs` maps the section view, then `commit()` calls `VirtualAlloc(MEM_COMMIT)` on the whole 6.5 GB view at once. When that fails, it logs a `WARN` and returns `false`. The title gets no usable memory and hits its breakpoint.

## Memory at the time

From the title's own crash report:

- 32 GB RAM, a system-managed paging file of about 12 GB, so a commit limit of about 44 GB
- `memory.load_percent` 70: about 23 GB of RAM actually in use
- `system.memory.swap.free` about 6 GB, which is less than the 6.5 GB requested

RAM itself wasn't full. The commit limit ran out.

## To reproduce

1. Use the default system-managed paging file on a 32 GB machine, with normal desktop apps open.
2. `victory run <game exe> --execute`
3. The title stops within about 3 seconds of launch.

## Workaround

A fixed 32 GB paging file (initial = maximum = 32768 MB) fixes it: the allocation goes through and startup continues.

## Suggestion

- On a commit failure, report an error that names the paging file and the commit limit, or stop with that message, instead of only logging a `WARN`.
- Or check the commit limit at startup and warn when it's too low.
- Either way, add the page file requirement to the README's Requirements.

## Environment

- Windows 11, 32 GB RAM
- Release and diag builds of `main` (2026-11-23)
- Console: Series X

I ran `modules::xmem::tests::commit_limit_report_includes_request_and_system_commit` on Windows at `d2a4bae1`. It passed for the message with synthetic commit counters and for the fallback when counters are unavailable. The test exercises formatting only.
