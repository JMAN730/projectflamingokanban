## Original body

Seen once, on Windows 10 with two local patches: #28 for the loader and the Agility SDK exports from #84. RTX 4080 (driver 621.01), i5-13600K, main `97c78d1`, title build `b99f876b…`. AI-assisted (Claude); I did the run and the analysis below myself.

### What happened

After the start screen, story mode loaded; the loading art showed at about 150 s. At 3 min 28 s, two job threads faulted on the same instruction with the same stack:

```
VIctory: unhandled exception 0xc0000005 at victory-image-b99f876b74d4a77f.dll+0x4e33a92 (write 0x325a0570)
  r9 0x7f90560 r12 0x325a0560
VIctory: unhandled exception 0xc0000005 at victory-image-b99f876b74d4a77f.dll+0x4e33a92 (write 0x325a0390)
  r9 0x7f90380 r12 0x325a0380
  #0 +0x4e33a92  #1 +0x4e33350  #2 +0x79fb0  #3 +0x1649d60  #4 +0x35b6d2c
  #5 +0x4eeaa59  #6 +0x2677819  #7 +0x256fb83  #8 +0x221c29c  #9 +0x2215eca
```

The instruction is in a loop that clears 48 bytes per step:

```
144e33a8e: vxorps  %xmm0, %xmm0, %xmm0
144e33a92: vmovups %ymm0, 0x10(%r12)    <- faults
144e33a99: vmovups %ymm0, (%r12)
144e33a9f: addq    $0x30, %r12
```

In both threads `r12 - r9` is exactly `0x2A610000`. Nothing in the log hands out an address in that range.

### The title's own crash context

The title wrote this context to `T:`; its upload to backtrace.io was blocked as designed.

- Game State: Game Running. Frame 4079, running time 3m28s.
- Current SRL: `fbk_stry000_FBK_STRY000_INTRO`, state Prestream.
- Pools were populated (52 peds, 84 vehicles, 4,218 objects) and the player was placed, so the world had loaded.
- Game Physical: 2,177,984,304 / 2,305,818,624. Pool: 591,978,320 / 624,951,280.

### Same run, GPU side

There was no GPU failure in this run: no driver reset, no device removed. VIctory logged that 70 compute and 21 pixel shaders did not translate, and the host refused 4 compute pipelines with `E_INVALIDARG`.

In an earlier run on the same setup, the world's first frame ended in a TDR instead (`slow host submission ms=11341 lists=33`, then device removed).
