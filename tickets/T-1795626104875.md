### Bug

In `crates/victory-shader/src/emit/lower.rs` (`Lower::write_half`), SDWA destinations on 16-bit VALU instructions (`v_cvt_i16_f16`, `v_cvt_norm_i16_f16`, `v_add_f16`, etc.) match `(sd.dst_sel, sd.dst_unused)` as:

```rust
match (sd.dst_sel, sd.dst_unused) {
    (4, 2) => {}
    (5, 2) => high = true,
    (4 | 6, _) => keep = false,
    (5, _) => (high, keep) = (true, false),
    _ => return Err("an SDWA destination of a 16-bit operation"),
}
```

When `dst_sel = WORD_0 (4)` and `dst_unused = UNUSED_SEXT (1)` — the pattern AMDGPU's SDWA peephole pass emits to fold a 16-to-32-bit sign extension into a 16-bit instruction — the `(4 | 6, _)` arm treats `UNUSED_SEXT` identically to `UNUSED_PAD`, zero-extending bits `[31:16]` instead of sign-extending bit 15. For example, `v_cvt_i16_f16_sdwa v0, v1 dst_sel:WORD_0 dst_unused:UNUSED_SEXT src0_sel:WORD_0` with `-1.0f16` (`0xBC00`) silently produces `0x0000_FFFF` (`+65535`) instead of `0xFFFF_FFFF` (`-1`).

Separately, reserved `dst_unused = 3` on `WORD_0`/`WORD_1` was also silently treated as `UNUSED_PAD` instead of being refused.

### Fix

- Handle `(4, 1)` (`WORD_0` + `UNUSED_SEXT`) in `Lower::write_half` by sign-extending the low 16 bits into bits `[31:16]` (`(x << 16) >>a 16`), matching RDNA2 SDWA semantics and 32-bit `place_bits`.
- Keep `WORD_0 + UNUSED_PAD`, `WORD_0 + UNUSED_PRESERVE`, `WORD_1 + {UNUSED_PAD, UNUSED_SEXT, UNUSED_PRESERVE}`, and `DWORD` behavior intact, and refuse reserved `dst_unused = 3` on `WORD_0`/`WORD_1`.
- Added end-to-end synthetic GPU + WARP regression tests in `crates/victory-shader/src/emit/valu_tests.rs` (`sdwa_16bit_dst_unused_sext_sign_extends_word0`) covering `v_cvt_i16_f16_sdwa`, `v_cvt_norm_i16_f16_sdwa` (`src0_sel:WORD_1`), `v_add_f16_sdwa`, and all other `dst_sel`/`dst_unused` modes, plus a lowering unit test (`sdwa_16bit_reserved_dst_unused_is_refused`) in `crates/victory-shader/src/emit/lower.rs`.

### Verification

- **Before fix:** `sdwa_16bit_dst_unused_sext_sign_extends_word0` failed on both hardware GPU and WARP (`hardware: v_cvt_i16_f16_sdwa(0xbc00, WORD_0, UNUSED_SEXT) = 0x0000ffff, want 0xffffffff`).
- **After fix (Windows 11, native SM 6.6 hardware GPU + WARP + `dxil.dll` validation):**
  - `cargo test -p victory-shader`: 122 passed, 0 failed, 1 ignored.
  - `cargo clippy -p victory-shader --all-targets -- -D warnings`: clean.
