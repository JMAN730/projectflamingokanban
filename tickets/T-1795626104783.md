The stand-in gamepad in `crates/victory-hle/src/modules/gameinput.rs` maps
`KeyState.virtual_key` to pad buttons. A virtual key is the letter the key
types, so the table only holds on a US layout: on AZERTY the key labelled
`Z` sits where QWERTY has `W`, and `Q` where QWERTY has `A`. The left stick
therefore moves on the wrong physical keys and the two triggers swap.

Scan codes name the physical key, so one table serves every layout.

What changed:

- `FALLBACK_BUTTONS` becomes `[(u32, u32); 14]`, scan code to button, and
  `fallback` matches on `KeyState.scan_code` instead of `virtual_key`.
- The virtual-key letters stay in comments so the table still reads.
- A test holds `z` + `q` on an AZERTY board and expects the left stick, and
  checks that the key labelled `W` lands on the left trigger's physical key.

`the_stand_in_pad_reads_physical_keys_not_layout_letters`.
