### Bug

In `crates/victory-shader/src/emit/lower.rs`, the typeless `_b32` instructions `v_mov_b32` and `v_cndmask_b32` route source operands through `fsrc()` (which emits `dx.op.unary.f32(FAbs)` and `fsub -0.0, x`) whenever `abs` or `neg` modifiers are set:

- `v_mov_b32` (`lower.rs:3897-3904`): routes `v.abs != 0 || v.neg != 0` through `f(self, 0)` and `float(self, a)`.
- `v_cndmask_b32` (`lower.rs:4163-4167`): routes `v.abs != 0 || v.neg != 0` through `(f(self, 0), f(self, 1))` and `float(self, r)`.

On RDNA2 (GFX10.3), both `v_mov_b32` and `v_cndmask_b32` are typeless `_b32` instructions (`ReadsModeReg = 0` in LLVM AMDGPU) whose `abs` and `neg` input modifiers operate strictly bitwise on bit 31 (`& 0x7FFF_FFFF` / `^ 0x8000_0000`) — they do not flush denormals to zero or quiet signalling NaNs. On D3D12 hosts (where f32 arithmetic flushes subnormals and quiets sNaNs), emitting float `FAbs` / `fsub -0.0, x` corrupts subnormal values and sNaN payloads.

### Reproduction (Before Fix)

With synthetic RDNA2 compute shaders lowered to DXIL and executed on hardware (NVIDIA RTX 3050 6GB Laptop GPU, driver `32.0.16.1742`, Windows 11 `10.0.26300.0`):

```text
hardware: v_mov_b32_e64(-0x00000001) = 0x80000000, want 0x80000001
hardware: v_cndmask_b32_e64(-0x00000001, |0x3f800000|, 0) = 0x80000000, want 0x80000001
```

### Fix

- Added `Lower::src_bits` in `crates/victory-shader/src/emit/lower.rs` to read a raw 32-bit operand (preserving DPP `self.src0` and SDWA `select_bits`) and apply `abs` (`& 0x7FFF_FFFF`) and `neg` (`^ 0x8000_0000`) bitwise.
- Updated `v_mov_b32` to use `src_bits(inst, 0)` and write via `int(self, a)`, converting to float via `as_float` + `float(self, a)` only when `v.clamp || v.omod != 0`.
- Updated `v_cndmask_b32` to read both operands via `src_bits` and write via `int(self, r)`.
- Added two hardware + WARP + `dxil.dll` tests in `crates/victory-shader/src/emit/valu_tests.rs`:
  - `emit::valu_tests::v_mov_b32_modifiers_are_bitwise` (VOP3 `neg`, `abs`, `-|x|`, SDWA `neg`, and `clamp`/`mul:2` across normals, `±0.0`, `±inf`, `±denormal`, `±sNaN`, and `±qNaN` payloads)
  - `emit::valu_tests::v_cndmask_b32_modifiers_are_bitwise` (VOP3 mixed `neg`/`abs`, `-|x|` + `neg`, and one-sided `neg` with unmodified `src1` across the same value set)
