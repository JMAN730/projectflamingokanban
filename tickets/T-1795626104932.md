### Summary

Implements the two missing `XTaskQueue` waiter vtable slots in `crates/victory-hle/src/modules/xasync.rs`:
- **Slot `20` (`0xa0`)**: `XTaskQueueRegisterWaiter`
- **Slot `21` (`0xa8`)**: `XTaskQueueUnregisterWaiter`

Because external PR creation is restricted (`collaborators_only`), the CI-green branch is ready on my fork:

### Changes (`crates/victory-hle/src/modules/xasync.rs`)
- Validates queue handle, port (`WORK`/`COMPLETION`), non-null/non-`INVALID_HANDLE_VALUE` wait handle, callback, output token, and terminated queue state (`E_ABORT`).
- Duplicates the caller's Win32 handle (`DuplicateHandle` with `DUPLICATE_SAME_ACCESS`) so the wait stays valid if the caller closes their handle right after unregistering, and pairs it with a per-waiter manual-reset `stop_event` placed first in `WaitForMultipleObjects`.
- Waits for each submitted callback to return before re-arming `WaitForMultipleObjects`, preventing manual-reset events from flooding the queue before the callback can reset the event or unregister itself.
- Keeps a `Weak<Queue>` on the waiter thread (dropping the upgraded `Arc<Queue>` before waiting on callback completion) and cleans up waiters on `XTaskQueueTerminate` and `Queue::drop`, avoiding reference cycles and handle leaks.
- Non-Windows builds stay clean (`E_NOTIMPL`).

### Tests & Verification
Added 3 synthetic Windows unit tests in `xasync::tests`:
- `waiter_fires_on_signal_and_stops_after_unregister` (exercises slots `0xa0`/`0xa8` with an auto-reset event across multiple signals and unregister)
- `manual_reset_waiter_rearms_only_after_callback_returns` (verifies manual-reset re-arm semantics and safe unregistration from inside the callback itself)
- `waiter_validates_arguments_and_stops_on_terminate` (argument validation, `E_ABORT` after terminate, clean shutdown)
