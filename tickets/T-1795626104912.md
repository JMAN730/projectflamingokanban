## Original body

`v_cvt_f16_u16` (VOP1 0x050) and `v_cvt_f16_i16` (VOP1 0x051) are implemented in `crates/victory-shader/src/emit/lower.rs` but have no hardware test in `crates/victory-shader/src/emit/valu_tests.rs`. Their reverse-direction siblings `v_cvt_u16_f16` (0x052) and `v_cvt_i16_f16` (0x053) are exhaustively tested in `v_cvt_u16_and_i16_f16_saturate` with 16 cases.

## Implementation evidence

`lower.rs`, `valu16_op()`, around line 4388:

```rust
"v_cvt_f16_u16" | "v_cvt_f16_i16" => {
    let mut x = self.half_src(inst, 0)?;
    let op = if name == "v_cvt_f16_i16" {
        let k16 = self.s.m.i32(16);
        let t = self.s.m.bin(c, Bin::Shl, x, k16);
        x = self.s.m.bin(c, Bin::AShr, t, k16); // sign-extend i16 → i32
        Cast::SiToFp
    } else {
        Cast::UiToFp  // zero-extend u16 → u32
    };
    self.s.m.cast(c, op, x, f32t)
}
```

The `Shl 16` + `AShr 16` sign-extension for `v_cvt_f16_i16` is unique to this instruction path.

## Missing test

`valu_tests.rs` contains `fn v_cvt_u16_and_i16_f16_saturate()` (line 674) using opcodes `0x052` / `0x053`. Opcodes `0x050` and `0x051` do not appear anywhere in the test file.

The sibling test structure with `vop1(0x001, 0, 128)` to clear the high half applies directly.

## Interesting edge cases

| Input | v_cvt_f16_u16 | v_cvt_f16_i16 | Reason |
|---|---|---|---|
| `0x0000` | `0x0000` | `0x0000` | zero |
| `0x0001` | `0x0400` (subnormal) | `0x0400` | 1 → 2^-14 × 1 |
| `0x7FFF` | `0x7800` | `0x7800` | 32767 rounds to 32768.0 |
| `0x8000` | `0x7800` | `0xF800` | u16: 32768.0 / i16: -32768.0 |
| `0xFFFF` | `0x7C00` (inf) | `0xBC00` | u16: 65535 > max f16 / i16: -1 |

The case `v_cvt_f16_u16(0xFFFF)` is the one u16 value where the rounding mode changes the output: before PR #422 it rounds toward zero to 65504.0 (`0x7BFF`); after PR #422 it rounds to nearest even to infinity (`0x7C00`). The sign-extension case `v_cvt_f16_i16(0x8000)` = convert -32768 is exactly representable and not rounding-sensitive.

## Suggested test

Add `fn v_cvt_f16_u16_and_i16_match_rdna2()` to `valu_tests.rs` mirroring the existing sibling test:

```rust
#[test]
fn v_cvt_f16_u16_and_i16_match_rdna2() {
    // v_mov_b32 v0, 0; v_cvt_f16_u16 / v_cvt_f16_i16 v0, v1 (VOP1 0x050 / 0x051).
    // Clear the high half first (same preamble as v_cvt_u16_and_i16_f16_saturate).

    // (u16/i16 bit input, expected f16 from u16, expected f16 from i16)
    let cases: &[(u16, u16, u16)] = &[
        (0x0000, 0x0000, 0x0000), // 0 → 0.0
        (0x0001, 0x0400, 0x0400), // 1 → 2^-14 (smallest f16 normal)
        (0x000F, 0x0C00, 0x0C00), // 15
        (0x0400, 0x5400, 0x5400), // 1024
        // The u16/i16 split at 0x8000:
        (0x8000, 0x7800, 0xF800), // u16=32768.0 / i16=-32768.0 (exactly representable)
        (0x7FFF, 0x7800, 0x7800), // 32767: rounds to 32768.0 for both (nearest even)
        // Negative i16 cases (sign-extension path):
        (0xFFFF, 0x7C00, 0xBC00), // u16=65535->inf (after #422); i16=-1->-1.0
        (0xFFF0, 0x7BFF, 0xC800), // u16=65520->65504.0 (round down); i16=-16->-16.0
        (0x8001, 0x7800, 0xF800), // u16=32769 / i16=-32767 → -32768.0 (nearest even)
    ];
    for (op, what, pick) in [
        (0x050u16, "v_cvt_f16_u16", 0usize),
        (0x051,    "v_cvt_f16_i16", 1),
    ] {
        let shader = build_valu_cs(&[vop1(0x001, 0, 128), vop1(op, 0, vgpr(1))]);
        let inputs: Vec<[u32; 4]> = cases.iter().map(|c| [u32::from(c.0), 0, 0, 0]).collect();
        run_cases(&shader, &inputs, |backend, i, _, got| {
            let want = u32::from(if pick == 0 { cases[i].1 } else { cases[i].2 });
            assert_eq!(
                got & 0xFFFF, want,
                "{backend}: {what}({:#06x}) = {got:#010x}, want {want:#06x}",
                cases[i].0,
            );
        });
    }
}
```

Note: the expected value for `0xFFFF → v_cvt_f16_u16` is `0x7C00` (infinity, nearest-even rounding per PR #422). If the test is written before #422 merges, change that case to `0x7BFF` and update after the PR lands.

The test skips gracefully when no SM 6.6 device is available and runs on WARP. No game data needed.

### The expected bits

| source | table above expects | `main` gives |
|---|---|---|
| `0x0803` (2051) | `0x6802` (2052) | **`0x6801`** (2050) |
| `0x7FFF` (32767) | `0x7800` (32768) | **`0x77FF`** (32752) |
| `0xFFF0` (65520) | `0x7C00` (+inf) | **`0x7BFF`** (65504) |

And the step is not only truncating, it never overflows: 65520, 65536 and 1e30 (`0x7149F2CA`) all give `0x7BFF` (65504). `v_cvt_f16_f32` (VOP1 `0x00A`) of `1 + 3·2⁻¹¹` (`0x3F803000`) gives `0x3C01`, where nearest even would carry to `0x3C02`.

So `legacyF32ToF16` rounds toward zero and saturates, on both host backends, and every f16 result in the translator inherits that. This matches @fuzeofficlal's "the tie at 2,051 also goes from 2,050 (`0x6801`) on main to 2,052 (`0x6802`) with #422": the tests record `main`, and #422's merge has to update those rows. Whether RDNA2 truncates or rounds to nearest even is the open question — if it rounds, this is a defect of its own, wider than #422 (which would leave the saturation as it is), and worth reporting separately.

@MichaelSmithAI's corrections to the encodings in the issue hold — 1 → `0x3C00`, 15 → `0x4B80`, 1,024 → `0x6400`, −16 → `0xCC00`, 2,049 → 2,048 — except the 2,051 one, which `main` rounds down rather than up, and the two unsigned rows at 65,520 and 65,535, which stay finite here.
