### Comment 1 — @DaviTostes — 2026-11-24T02:56:43Z

Yes — this is tracked in **#340** ("experimental Linux/Wine support and compatibility documentation"), which already has a measured matrix; the project's target stays Windows and the Linux path is "Windows build under Wine/Proton", not native.

Short version of what we measured on Arch (Wine 11.22, vkd3d-proton 3.1, RX 9060 XT/RADV) and posted in #340:

- The Windows test binaries run under Wine without the native-Linux build (#112/#235 are the native route; current `main` still fails `E0425 host_resource` on Linux).
- `victory_gpu`: **52/52 on Wine's built-in D3D12**, **50/52 on vkd3d-proton** (empty pipeline-library blob and #128, an upload gap specific to vkd3d's mapped memory).
- Indirect execution needs a shader compiler: Wine's `d3dcompiler_47` rejects the clamp; a native Microsoft `d3dcompiler_47` or **#190** (clamp written by the project, no compiler) fixes it.
- `victory-hle`: 85/86 under Wine (only `WSAConnectByList`, addressed by #195/#217).
- Launcher/proton recipe: #191; SDL3 gamepad backend: #312 (dynamically loaded `SDL3.dll`, XInput fallback).

The detailed comment with the full matrix is here: https://github.com/Marvisak/VIctory/issues/340#issuecomment-7120169338

No game data used.
