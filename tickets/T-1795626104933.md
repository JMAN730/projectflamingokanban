### Summary

Implements two unclaimed `IDStorageQueueX` vtable slots in `crates/victory-hle/src/modules/dstorage.rs` (leaving `0x48`/`0x50` untouched to avoid overlap with PR #624):

### Changes (`crates/victory-hle/src/modules/dstorage.rs`)
- **`cancel_requests_with_tag` (`0x38`)**: removes unsubmitted and queued-not-yet-started reads matching `(request.tag & mask) == value`, flushes any newly unblocked status entries without recording cancellation as an error (matching GDK `IDStorageQueueX::CancelRequestsWithTag`), and notifies waiters blocked on queue capacity.
- **`query` (`0x58`)**: populates the 2020 `DSTORAGE_QUEUE_INFO` structure (`DSTORAGE_QUEUE_DESC`, `EmptySlotCount`, `RequestCountUntilAutoSubmit`), storing an owned `CString` for the queue name on `Queue` so `desc.name` stays valid across the queue's lifetime (including after `Close`). Null output pointers are tolerated.

### Tests & Verification
Added 2 synthetic Windows unit tests in `dstorage::tests`:
- `queue_info_layout_and_counts_track_enqueued_and_closed_state` (ABI size/offset assertions for `QueueDesc2020`/`QueueInfo`, null tolerance, empty/enqueued/submitted/closed counts)
- `cancel_requests_with_tag_drops_matching_reads_without_error` (bitmask matching, slot reclamation, non-error status completion, untouched buffers for cancelled reads, closed-queue no-op)
