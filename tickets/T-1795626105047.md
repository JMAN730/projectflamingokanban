## Original body

Most open shader PRs that add hardware tests were run only on NVIDIA, and some on no GPU at all. This runs each PR's `victory-shader` tests on an AMD RDNA2 GPU, so review has one AMD data point per PR. No game files: crate tests only.

**Short version:** in 82 PRs, nothing fails that passes on `main`, and the new tests pass on the Radeon 660M, with three kinds of exception. #1483, #1433 and #439 need vkd3d-proton 3.2: on the 3.1.0 that Proton Experimental ships, one of their tests ends the process inside RADV. #1489's new test cannot run under Proton at all (comparison sampling on a color texture), and #1554's new test has inputs that make it fail everywhere.

### Setup
- **GPU:** Radeon 660M (RDNA2, gfx1035) in a Ryzen 5 7535HS laptop. RADV, Mesa 26.3.1. D3D12 waves 32..64.
- **Runtime:** CachyOS (Linux 7.3.5), Proton Experimental 11.0-20261027b's Wine with its vkd3d-proton 3.1.0 and DXVK DXGI. The GPU was pinned with `VK_LOADER_DRIVERS_SELECT` (the laptop also has an RTX 3050).
- **Build:** on Linux with llvm-mingw 20261117 for `x86_64-pc-windows-gnullvm`, Rust 1.98.1. `dxil.dll` from DXC 1.9.2609 was loaded, so the test modules were validated.
- **Command:** each PR's head, `cargo test -p victory-shader -- --test-threads=1` (the whole suite), compared test by test with `main` (`ffe310e`) on the same GPU.

**Baseline.** On `main` here, 119 passed, 1 failed, 1 ignored. The failure is `emit::tests::stub_pipeline_is_created`: vkd3d-proton accepts the zeroed DXIL hash that the Windows runtime refuses (one of the Wine failures listed in #1218). It fails in every PR below too, and the table leaves it out.

**Caveat.** RADV is not AMD's Windows driver. #1172 is a case where the two differ: the Windows driver gives wrong lanes, and RADV is exact. So this adds to a Windows AMD run rather than replacing it.
