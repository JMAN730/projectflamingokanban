### Comment 1 — @UNYTIX — 2026-11-24T12:08:42Z

The follow-up to #811 is ready on a branch: [UNYTIX/VIctory@census-title-dlls](https://github.com/UNYTIX/VIctory/tree/census-title-dlls) (one commit, 30043d2, on top of ffe310e).

**What changed:** `census` now resolves an import that neither HLE nor the host provides against the exports of the DLLs it scanned in the importing image's folder, the way `run` binds it (`WithTitleDlls`). It uses the same `title_dll` filter, so it never takes a host or HLE DLL from the title. Those imports get a new `title` column instead of `missing`.

**Why:** on 1.0.2.1, `census --missing` listed 72 exports of the title's own DLLs as gaps, which hid the two real ones.

| `census --missing`, 1.0.2.1 | title | missing |
|---|---|---|
| before | – | 74 |
| after | 72 (libHttpClient.GDK 38, Bink2Scarlett 23, XboxBvhBuilder 7, amd_fidelityfx_loader_xbox 4) | 2 (`oleaut32.dll!#4`, `#6`) |

**Tests:** two new unit tests use synthetic export tables, with no game data:
- A title DLL's exports in the same folder resolve as title, by name and by ordinal. Unexported symbols and DLLs in other folders don't.
- A host-allowed DLL shipped in the title folder is not used.
