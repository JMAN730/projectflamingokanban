## Summary

Fixes four top shader translation blockers and improves waterfall descriptor tracking (tested on Windows 11, NVIDIA GeForce RTX 5060 Ti driver 621.01, Windows SDK `dxil.dll` 10.0.26100.0):

1. **64-bit typed image atomics** (`crates/victory-shader/src/emit/lower.rs`, `shader.rs`):
   - Support 64-bit `image_atomic_*` (`dmask: 0x3` for binop, `dmask: 0xf` for `cmpswap`), lowering to `dx.op.atomicBinOp.i64` / `dx.op.atomicCompareExchange.i64` with `pack64`/`split64` and `ATOMIC_INT64_TYPED` (`1 << 27` -> `SFI0 0x40_0000`) + `ATOMIC_INT64_HEAP` (`1 << 32` -> `SFI0 0x1000_0000`).
2. **SMEM descriptor size reads** (`crates/victory-shader/src/emit/lower.rs`):
   - In `descriptor_data()`, prefer `Fields::Image` / `Fields::Buffer` uses over `Fields::Smem`, and fall back to `Fields::Smem` (`s_buffer_load_dword*`) for SRV/UAV descriptors when no vector buffer use exists.
3. **Spilled lane masks through `v_writelane_b32` / `v_readlane_b32`** (`crates/victory-shader/src/structure.rs`, `resource.rs`, `emit/lower.rs`):
   - Share `resource::spilled_lane` across `resource`, `structure`, and `lower`.
   - Track spilled lane masks restored via `v_readlane_b32` in `structure.rs`, and handle constant masks (`NULL`/`0`/`-1`) in `v_cndmask_b32`.
   - In `lower.rs`, treat mask-returning `v_readlane_b32` as `LANE_MASK`, and resolve constant-lane `v_readlane_b32` reads from the spilled lane directly so inactive masks in sibling spill lanes do not poison unrelated scalar lanes.
4. **Waterfall descriptor copies** (`crates/victory-shader/src/resource.rs`):
   - Follow `v_mov_b32` and `v_readfirstlane_b32` in `copy_source` so VGPR-moved / waterfall-loop descriptors trace back to their `s_load` or VGPR phi.

### Comment 5 — @HrHd — 2026-11-24T12:44:08Z

The fork branch behind this issue needed five conflicts resolved against current `main` (`ffe310e`), and the two that matter are worth writing down because they are not mechanical — anyone rebasing it will hit them and can easily ship a broken merge.

**1. `crates/victory-shader/src/resource.rs`, `copy_source` (the actual hazard).** The fork collapses `v_readfirstlane_b32` and `v_mov_b32` into copy propagation. `v_mov` is already covered upstream, but collapsing `v_readfirstlane` silently breaks **all 28** per-lane-descriptor/waterfall tests: `first_lane_source` never fires, and the failures surface as `a descriptor neither loaded nor built` far away from the change. Fix used here: keep upstream `copy_source` and instead teach `classify` that a `v_readfirstlane` of a value that does not vary is a plain copy (`uniform_readfirstlane`, with a `first_lane_words` filter so no waterfall proof is demanded). That needs a per-register write count as a guard — a register written in two blocks is not SSA, and without the guard `a_per_lane_descriptor_some_lanes_do_not_write_fails` starts passing when it should fail.

**2. `descriptor_data`, which is also what #180 rewrites.** The fork's `s_buffer_load_dword` arm is mutually exclusive with #180's twin-load and only-measured paths in the same function. Merged here by one closure that prefers an image or vector-buffer use over the `s_buffer` fallback, and looks at the site's own loads first, twins second; the `s_buffer` arm then sits after `Fields::Buffer` and only sees the fallback case.

Measured here, pack of 25,322 programs, offline translator, same tree:

| | before | after |
|---|---|---|
| vertex + pixel | 13,020 | 13,127 |
| compute | 1,844 | 2,440 |
| mesh | 8,302 | 8,525 |
| `lane mask holding lanes elsewhere read as data` | 272 | **12** |
| total emitted | 23,166 | **24,092 (95.1 %)** |

141 `victory-shader` tests pass with the merge, including the 28 above.

Caveats, so nobody is surprised: `a scalar memory read as data` largely stops being its own class and reappears under `a descriptor read only as data` (394 → 860 in an earlier measurement of the fork alone) — it moves cases between buckets, it does not fix all of them; and `cross-lane operation outside compute` rises 46 → 154 as more compute gets far enough to hit it.

The remaining top class (**879 programs, a descriptor dword consumed as the address of another `s_load_dword*`**) is untouched by this branch. Filed separately as #798 with the shape and both possible fixes.
