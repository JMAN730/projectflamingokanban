## Original body

I tried VIctory and hit the host GPU failure described in the README. Here are my details in case they help, since the README says it has only been tested on an AMD RX 6700 XT.

System
- GPU: NVIDIA GeForce RTX 4070
- NVIDIA driver version: 621.24
- OS: Windows 11 [fill in if different]
- CPU: i9-14900kf
- VIctory commit: [run `git rev-parse --short HEAD` in the repo folder]

What I ran
- Built with `cargo build --profile diag -p victory --features diagnostics`
- Set `VICTORY_D3D12_DEBUG=1` and `VICTORY_D3D12_DRED=1`
- Ran `target\diag\victory.exe run <title exe> --execute`, output saved to a file

What happened
- The host GPU device was removed after a submission of 1 list (12 compute dispatches). Final error: 0x887A0005 (device suspended).
- The breadcrumbs named these compute programs: 9aa3629668b8e7ab, 010a50ce68d02c16, 44bb2d65d51ba5d1, 25c5ee5063e1a41f, 1547305c505a7559.
- Several of them show `Uav s0+288: uav None`, and one SRV buffer is at address 31960662016 (about 30 GB in), which may fall outside the 4 GB window mentioned in the README. I'm not sure whether either is the cause.
- On an earlier release-build run I got 0x887A0004 followed by 0x887A0006 with no breadcrumbs.
- My screens did not flicker or go black when it crashed.

**Warnings before the crash**
- Many "host pipeline refused: The parameter is incorrect (0x80070057)" warnings for compute shaders. I wonder if this is related to NVIDIA's 32-lane waves versus the 64-lane waves the README mentions, but that is only a guess.
- Many "shader does not translate" warnings, mostly: "an address in an SGPR that is no root parameter", "structured buffer of unknown stride", "64-bit image atomic", "scalar memory read as data", "barycentrics read directly", "lane-mask join of an untracked mask", and unsupported instructions v_swap_b32 and v_xnor_b32.

## With TdrDelay=60: no device removal, the title crashes instead

`HKLM\SYSTEM\CurrentControlSet\Control\GraphicsDrivers` set to `TdrDelay=60` and
`TdrDdiDelay=60`, rebooted, five runs since:

- device removed: **none of them**
- the world loads: `peak dropped 1380` draws in one frame, `lowest fps 0.6`
- every one ends in the title's own fault, at the same address:

```
unhandled exception 0xc0000005 at victory-image-b99f876b74d4a77f.dll+0x23cf683 (write 0x0)
  rax 0x0  rbx 0x0  rcx 0xd0024c348  rdx 0x1  rbp 0x0
  #0 +0x23cf683   #1 +0x2215c35   #2 +0x2215eca   #3 KERNEL32   #4 ntdll
```

Same address, same frame `+0x2215c35`, same null write, on the hardware adapter and on
WARP. That is consistent with the hang having been a timeout: with a long enough budget the
submission completes, and what remains is a title-side null write during the world load.

Note the cost: with `TdrDelay=60` a real hang freezes the desktop for up to a minute.

## Three host textures fail to create, and the format is not the reason

`VICTORY_D3D12_DEBUG=1` on the diag profile:

```
no host texture error=E_INVALIDARG (0x80070057)
  dimension 3, 2560x1440, 1 mip, format 86,  flags 5
no host texture error=E_INVALIDARG (0x80070057)
  dimension 3, 2560x1440, 1 mip, format 115, flags 1
no host texture error=E_INVALIDARG (0x80070057)
  dimension 3, 1024x4096, 1 mip, format 28,  flags 1   <- after a local substitution
```

Format 86 is `B5G5R5A1_UNORM`, 115 is `B4G4R4A4_UNORM`. Two local variants were tried:

| Variant | Result |
|---|---|
| clear the UAV flag for 86/115, keep the format | one still fails |
| substitute `R8G8B8A8_UNORM` (28) and keep the flags | **every one still fails** |

A plain `R8G8B8A8_UNORM` render target at 2560x1440 cannot be rejected for its format, so
what `CreateCommittedResource` refuses is elsewhere in the description. The first suspects
are the initial state (`legal_for(d.flags, texture_state(state))` in `host_texture`) and the
clear value passed through.
