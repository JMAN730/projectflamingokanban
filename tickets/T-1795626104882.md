## Original body

## What's wrong

The float compares that are always false or always true are lowered to LLVM's constant predicates. The four instructions are `v_cmp_f_f32`, `v_cmp_tru_f32`, `v_cmp_f_f16` and `v_cmp_tru_f16`. In `crates/victory-shader/src/emit/lower.rs`, the compare lowering maps:
- `"f"` to `pred::FALSE`, emitting `fcmp false`;
- `"tru"` to `pred::TRUE`, emitting `fcmp true`.

DXC folds those predicates away, so drivers never see them from it. **WARP removes its device at the first dispatch of a pipeline that contains one.** The dispatch fails with "The GPU device instance has been suspended".

A removed device stays removed for the whole process, so every later pipeline and dispatch on WARP fails as well. The DXIL validator accepts the shader, and the hardware adapter runs it (RTX 5080, driver 616.92).

The integer forms `v_cmp_f_*` and `v_cmp_t_*` are already lowered as constants (`self.lane(inst, Some(op == "t"))`), and they run on both.

This may be one way WARP loses its device on real shaders. It could matter for #653, where WARP removes its device during world load, but I haven't checked whether the title's shaders contain these instructions.

## Repro

`v_cmp_f_f32_e64 s20, v1, v2`, then `v_cndmask_b32_e64 v0, 0, 1, s20`, with any operands:
- **Hardware adapter:** runs and gives 0.
- **WARP:** device suspended.

`v_cmp_tru_f32`, `v_cmp_f_f16` and `v_cmp_tru_f16` behave the same, with 1 thread or many. `v_cmp_f_i32`, `v_cmp_t_i32` and every other float compare run fine.

## Fix

- **Branch:** https://github.com/Peppacodes/VIctory/tree/fix/fcmp-false-true
- **Compare:** https://github.com/Marvisak/VIctory/compare/main...Peppacodes:VIctory:fix/fcmp-false-true
- **Commit:** `e04929d`, on `main` (`ffe310e`), 0 commits behind it. Three files: `lower.rs`, `bitcode.rs` and `valu_tests.rs`.

What changed:
- Float `f` and `tru` are now constants, false and true, the same way the integer compares do it, before any operand is read. The RDNA2 ISA defines them as false and true whatever the operands, NaNs included.
- `pred::FALSE` and `pred::TRUE` stay in the table, marked unused, with a note on why they aren't emitted.

## Test

`float_compares_that_are_always_false_or_true`, in `valu_tests.rs`:
- It runs the four instructions with ordinary and NaN operands, on the hardware adapter and WARP.
- On `main`, WARP's dispatch fails: `warp: dispatch failed: The GPU device instance has been suspended`. With the fix it passes on both.

## How it was found

I swept every 32-bit VALU instruction the translator lowers on the hardware adapter against WARP. Each ran on about 400 edge-case inputs, one per thread, and the results were compared bit for bit. 200 instructions ran. These four were the only ones that removed a device.

With the fix, all 62 compares run and agree on both. The other differences were small:
- `v_sin_f32` and `v_sin_f16` on the tiniest inputs. For example, `v_sin_f32(0x00800000)` gives 0 on the RTX 5080 and `0x01c90fdb` on WARP. Both are within D3D's tolerance for sin.
- `v_med3_f16(+0, −0, 1)` gives +0 on the RTX 5080 and −0 on WARP. `v_med3_f32` agreed on every case.
- NaN payloads.
