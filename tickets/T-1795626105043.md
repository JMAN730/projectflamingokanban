### Comment 1 — @EduBertozzi — 2026-11-24T17:49:11Z

Thanks for the RDNA1 data point. Without mesh shaders, every world mesh pipeline is refused on `main`, which may account for much of what's missing from that frame.

#961 adds a compute fallback for exactly this case. Each mesh program runs as a compute shader that writes its triangles to buffers, and a vertex shader draws them. It turns on by itself when the device reports no mesh shaders. Two in-game runs so far, on an RX 470 and a GTX 1070 Ti, got the world's geometry drawn after fixes now on the branch (`31568ce` or later). RDNA1 would be a useful third, because it has 64-lane waves: the title's wave64 mesh programs can run there as written, without the 32-lane workarounds the NVIDIA runs need.

If you try it, the interesting log lines are `mesh shader translated as compute` (with its `MeshLayout`), any `host root signature refused`, and `no shader-writable buffer`.

## Part 2: Findings & Observations (AI-Assisted Analysis)

*(Interpretation of the telemetry above; not raw measurements.)*

1. **PR #961 translation & root signatures succeeded on RDNA1:**
   VIctory detected `mesh=false` and enabled the compute fallback automatically (`231` mesh shaders translated as compute, with `0` `host root signature refused` and `0` `no shader-writable buffer` errors).
2. **`mesh_indirect` `cs_5_1` FXC error (`E5005`) explains all 483 `0x80070057` refusals:**
   The **483** `host mesh fallback compute pipeline refused (0x80070057)` warnings in `victory-diag.log` match 1:1 with the **483** `vkd3d_compile_shader_stage` (`-3`) / `d3d12_pipeline_state_init_compute` (`0x80070057`) failures in `vkd3d-debug.log`. Because `mesh_indirect` is compiled as `cs_5_1` (FXC) while calling `.Load()` on `RWByteAddressBuffer` (`args`, `count`), FXC rejects it (`E5005`), preventing host compute pipeline creation even though the mesh shaders themselves translated. (Under SM 5.1, `.Load()` is only defined on read-only `ByteAddressBuffer` SRVs, whereas `RWByteAddressBuffer.Load()` requires SM 6.0+ / DXIL.)
3. **Why this report may be useful:**
   Isolates a concrete Proton/`vkd3d-proton` blocker on PR #961 (`mesh_indirect` `cs_5_1` vs `RWByteAddressBuffer.Load()`) separate from RDNA1 Wave64 mesh-shader translation itself.
