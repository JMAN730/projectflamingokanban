## Original body

# Windows 10 + KB5029331: system d3d12 still refuses the 1.1 heap-indexing flags — but XCL proves the Agility SDK path works on the same box

**AI-assisted:** yes
**Kind:** measured comparison of two runtimes on one host, plus the concrete API route that works. No game data.

## Environment

- Windows 10 22H2, UBR **3393** (KB5029331 installed — `d3d12.dll` and `D3D12Core.dll` both went `10.0.19041.1266/1806` → `10.0.19041.3393`)
- RTX 4070 SUPER 12 GB, Ryzen 7 7800X3D
- VIctory `main` @ `8e79c80` (built with Rust 1.98.1), release profile
- Title: Xbox Series 1.0.2.1

## Finding: the OS patch alone does not fix VIctory

After the KB5029331 patch, VIctory still fails at the same place:

```
WARN victory_gpu::pipeline::host: root signature: Unsupported bit-flag set (root signature flags c01).
WARN victory_gpu::pipeline::host: host root signature refused error=0x80070057 shaders=[vertex dfafaf38…, pixel 06295fb1…]
```

`0xc01 = ALLOW_INPUT_ASSEMBLER_INPUT_LAYOUT | CBV_SRV_UAV_HEAP_DIRECTLY_INDEXED | SAMPLER_HEAP_DIRECTLY_INDEXED`.
The system `d3d12.dll` at 3393 still refuses the two 1.1 heap-indexing flags, so the shaders' bindless
`ResourceDescriptorHeap[]` accesses cannot be expressed and the graphics pipeline is refused.

## The same host runs the same title through XCL with Agility active

XCL on this machine logs:

```
xcl: D3D12: Agility SDK v620 (C:\Users\Administrator\AppData\Local\XCL\D3D12)
30.0 fps stable, 1 374 618 draws with translated pipelines (0 skipped)
```

XCL does **not** export `D3D12GetInterface` and does **not** link `D3D12Core.dll` into its import table.
It ships the core in a directory and obtains it through the SDK configuration interface at device
creation, which is why the old in-box `d3d12.dll` never has to understand the flags itself.

## Conclusion / suggested route

1. The OS patch is necessary (without it `ID3D12SDKConfiguration1` is `E_NOINTERFACE`, `0x80004002`) but
   not sufficient: a runtime that talks to the in-box `d3d12.dll` still gets `0xc01` refused.
2. Loading the Agility core explicitly at device creation — the `ID3D12SDKConfiguration1` /
   `ID3D12SDKConfiguration::SetSDKVersion` route XCL uses — is the working path on Windows 10.
3. The export-activation route (export `D3D12GetInterface` + `D3D12SDKVersion`, core beside the exe)
   was measured earlier on this host and **fails with `0xC0000142`** during process init, with or
   without the core present (issue #622). It should stay default-off.
