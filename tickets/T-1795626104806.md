## Original body

`v_med3_f32_matches_rdna2_with_nan` fails on current `main` (8e79c80) on an NVIDIA GeForce RTX 3050 Ti Laptop GPU (driver 32.0.16.2114, Windows 11):

```
hardware: v_med3_f32(1.0, 2.0, NaN) = 2 (0x40000000), want 1
```

**Cause:** `med3` in `crates/victory-shader/src/emit/lower.rs` chooses the NaN case (least operand) with `fcmp uno`. NVIDIA's driver assumes no NaNs in that compare and folds it to false, so a NaN operand gives the plain median. `fract` next to it already works around the same driver behaviour.

**Fix:** test the operands for NaN on their bits (`|x| > +inf` as integers), which the driver cannot fold away. 17 lines in `lower.rs`, one commit:

- Branch: https://github.com/raphael-riesner/VIctory/tree/shader/med3-nan-bits
- Compare: https://github.com/Marvisak/VIctory/compare/main...raphael-riesner:VIctory:shader/med3-nan-bits

**Tested** on the same GPU:
- `cargo test -p victory-shader --lib v_med3`: fails before (above), both med3 tests pass after
- `cargo test -p victory-shader`: 89 passed, 1 ignored
- `cargo clippy -p victory-shader --all-targets`: clean

Not tested on AMD.

I tried to open a pull request, but creating one was refused for my account (pull requests seem limited to collaborators right now), so the fix is offered here instead. Happy to open the PR if that opens up again.

### Comment 1 — @slint6614-dev — 2026-11-24T09:36:08Z

Read the branch (`shader/med3-nan-bits`, 1 commit ahead of main, 0 behind). I reviewed the code but did not run it.

- `is_nan_bits` is right: `(bits & 0x7FFFFFFF) > 0x7F800000` as an unsigned compare is true exactly for NaNs (both quiet and signalling, either sign), and false for ±inf.
- It also covers `v_med3_f16`. That call site (`lower.rs` ~4384) passes operands from `half_fsrc`, which widens with `legacyF16ToF32`, so `med3` always sees f32 values. A NaN half stays a NaN after the widening, so the f32 bit test holds there too, and no separate 16-bit constant is needed.
- On AMD the old `fcmp uno` form already gives the RDNA2 result: on main, `v_med3_f32_matches_rdna2_with_nan` and `v_med3_f16_matches_rdna2_with_nan` pass on an RX 9070 (RDNA4) and a Ryzen 9600X iGPU (RDNA2) as the hardware device. So for AMD this change only replaces an equivalent compare.
