### Comment 1 — @andrewpozdnakov7-jpg — 2026-11-24T12:18:04Z

I reproduced the fixture link failure on `ffe310e` with Rust 1.100.0 (`x86_64-pc-windows-gnullvm`) and llvm-mingw 23.1.6. The Clang driver treated `/DELAYLOAD:victory-probe-delayed.dll` as an input filename.

The patch forwards `--delayload` through Clang on the LLVM MinGW target and retains the existing MSVC flag. `llvm-readobj --coff-imports` confirmed that `victory-probe-delayed.dll` is still in the resulting DLL's delay import table. Both `load_probe` integration tests passed on native Windows with each toolchain. The fixture passed `rustfmt --check`, and `cargo xtask policy` passed.

AI-assisted. Tested with the repository's synthetic fixture. Only the loader integration tests were rerun.
