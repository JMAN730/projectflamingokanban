## Summary

On Linux with Wine and an RTX 4070, the intro cutscene renders the 3D world (the city at dusk) with no Xid and no device removal. I used the `fxceless/victory-gta6` fork (`578d459`, on top of `ffe310e`) plus four small Linux patches, and skipped the shaders that crash the NVIDIA driver. Characters are still incomplete: Lucia's face is missing (only the eyes and teeth draw) and there is a square block on her hair. The three shaders behind that are listed below.

Related: #144 (NVIDIA pipeline-creation crash), #909 and #170 (Wine's HLSL compiler), #728 (SMEM descriptor size reads).

## Environment

- CachyOS, kernel 7.3.4, RTX 4070 12 GB, NVIDIA 620.70.06
- Wine 11.22, vkd3d-proton 3.2.0, DXVK `dxgi`
- Series X dump v1.0.2.1, `cargo xwin`, target `x86_64-pc-windows-msvc`, built with `--features diagnostics`
- Environment variables:
  - `VKD3D_DISABLE_EXTENSIONS=VK_NV_raw_access_chains`
  - `VICTORY_DXC=<dir with dxcompiler.dll + dxil.dll>`
  - `VICTORY_SKIP_PIPELINES=<list below>`

Our own `main`-based tree, with many open PRs applied, never got past a black screen and Xid 109 after about 60–100 s. AnyXboxX (Series S) failed to create the R9G9B9E5 render target, as in #741.

## Local patches on top of the fork

1. **DXC fallback for every runtime `D3DCompile` site.** On Wine, `d3dcompiler_47` fails some of the HLSL with E5005. This is the same failure as #909/#170, but it is not limited to the indirect clamp. The new `crates/victory-gpu/src/dxc.rs` loads `dxcompiler.dll` from `VICTORY_DXC`, maps `*_5_1` to `*_6_0` and compiles with `-O3`. It is used when D3DCompile fails at five places:
   - `indirect.rs`: the clamp in `make_for` and the worker in `compile_cs`
   - `inplace.rs`: the shade pass
   - `host.rs`: `compile()` and the card compare in `make_card_work`
2. **Stack size.**
   - `apps/victory/build.rs` passes `/STACK:16777216` for msvc.
   - Pipeline worker threads get `.stack_size(16 MiB)`.

   Without these, some translations overflow the default stack under Wine.
3. **Pipeline worker count.** `VICTORY_PIPELINE_WORKERS` sets how many workers make pipelines.
4. **Diagnostics.** A `making [stages + hashes]` line is logged before each pipeline is created, so the last line before a driver crash names the culprit.

## NVIDIA driver crash list (#144)

`vkCreateGraphicsPipelines` / `vkCreateComputePipelines` throw 0xc0000005 inside the driver for specific shaders, every time. I found them offline with a loop:
- run `victory translate --pipelines --jobs 1` in a throwaway prefix;
- after each crash, add the last hash it tried to `VICTORY_SKIP_PIPELINES`;
- run it again.

The face and hair artifacts start exactly when these three pixel shaders are first bound: `5ad3a82b…` (driver crash) and the two that use a descriptor as data. ## Performance

About 0.4–0.7 fps, and the CPU is the limit: the GPU is about 11 % busy. Most of the frame is the texture refresh waiting for title memory to "hold still" (about 566 ms per frame) plus copies. In the fork's `texture.rs` this path still goes through `committed()`/`VirtualQuery`, which is slow under Wine.

The intro stutter on the first run is cold pipeline creation: about 770 pipelines on an empty cache.

I can share the patch if it helps.
