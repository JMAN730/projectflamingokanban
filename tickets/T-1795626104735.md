## Original body

Leonida, another Xbox Series translation and compatibility project (GPL-3.0-or-later, like VIctory), was retired by its author this week and its repository is gone from GitHub. Its notes cover one of the gaps in VIctory's README ("Shaders: ... the ray-tracing builder's shaders"), and as far as code search shows VIctory has nothing on that area yet beyond the `image_bvh_intersect_ray` opcode. I'm posting a summary here so that work isn't lost. The full notes are archived in my fork, linked at the end.

Nothing from the game is in this issue: no addresses, tables, shader dumps or hashes. It holds only layouts and conclusions, in the form Leonida documented them, following `docs/asset-policy.md`. All credit goes to Leonida's author and contributors.

## What Leonida found

1. **The title's ray-tracing shaders walk the BVH themselves.** They use `image_bvh_intersect_ray` / `image_bvh64_intersect_ray` on AMD's hardware node format: a node pointer is the address shifted right by 3 with the node type in the low bits, there are box16, box32 and triangle nodes, and the base unit is 256 bytes. A host acceleration structure (DXR or Vulkan) is opaque to those shaders. The runtime has to place the console node layout in memory and emulate the intersect instructions. Leonida treated this as its central design decision: build AMD-format BVH data, not a host acceleration structure.

2. **`XboxBvhBuilder.dll` builds on the GPU with its own compute shaders.** Its constructor creates its compute pipelines through Xbox device slot 62, called with the compute-PSO shape (`D3D12_COMPUTE_PIPELINE_STATE_DESC`, two zero words, iid, out). On the PC interface, slot 62 is `CreateStateObject`, so it has to be routed to compute-PSO creation. Its build, copy and rehydrate entry points take `ID3D12GraphicsCommandList4/6/8`.

3. **The builder's 52 shader containers can go through the same recompiler as the title's shaders.** Each container carries an LLVM bitcode blob and an `XDAT`/`XBCH` record. The console executes the `XBCH` record, which unpacks to the same native-code container as the title's own compute shaders. Feeding the bitcode to the PC D3D12 compiler mostly failed, so that route is a dead end. Leonida's results, with its RDNA2 → SPIR-V translator: 52 of 52 containers unpacked, 51 translated and passed `spirv-val`, and the last (`Box16Rehydration`) needed `buffer_store_short`. None of them was ever checked against a reference on a GPU.

4. **The batched build descriptions,** recovered by static analysis of how the DLL reads them, not from headers:
   - `D3D12XBOX_BUILD_RAYTRACING_ACCELERATION_STRUCTURE_BATCHED_DESC2` is `0x50` bytes: the public build description, the postbuild-info count and pointer, then a 16-byte `D3D12XBOX_XDXR_STREAM_DESC`.
   - That stream description is a size and a pointer to 16-byte typed records. The DLL takes the first record of each type it wants, and stops walking at an unknown type.
   - The offline-statistics postbuild type (`0x10`) is always rejected with `E_INVALIDARG`, thrown as a C++ exception from exports that return `void`.

5. **Dehydrated bottom-level structures ship in the `*_bvh4` packs.** The DLL's rehydrate export works on CPU pointers (console unified memory) and makes no device calls. Leonida modelled the packing and matched the library's output byte for byte on 8 sampled structures. It never established whether the title rehydrates these structures or rebuilds them.

6. **A substitute builder.** Leonida also had its own GPU builder that writes the console BVH4 records. It covers paired triangle leaves, BOX16 nodes for `MINIMIZE_MEMORY` builds, refit for updates, and clone and compaction. It was checked against a CPU reference traversal on synthetic scenes. This is a reference design if running the DLL's own shaders turns out not to be viable.

## What stayed open

- Which path the title takes: the builder DLL, or the standard acceleration-structure calls.
- Whether the title ever passes a non-empty stream description.
- Whether the translated builder programs produce correct results on a GPU.
