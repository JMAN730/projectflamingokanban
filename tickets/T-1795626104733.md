### Comment 6 — @LooperSalty — 2026-11-24T11:01:00Z

Cause of the world-entry hang found on our RTX 4070 SUPER (diag build of main `58fed37` + the stack listed above, plus #294 root UAVs, #709, #571, #452, #581):

- With root UAVs translated, the hang always lands at the same moment (loading screen → first cutscene frame), whatever the loop limit. Skipping the 12 compute programs that root UAVs unblock removes it; bisecting leaves **one program that is enough on its own to hang the GPU**.
- That program is part of the title's ray-tracing BVH builder: its container carries a `XboxBvhBuilder/ResetToIndexBuffer` debug path, and it is dispatched from `XboxBvhBuilder.dll`'s build path (`BuildRaytracingAccelerationStructure`). It only writes a table of consecutive indices (0..6143 here); the builder's later passes (e.g. a split-instances pass reading that table through a root UAV) are partly translated, partly dropped, so the passes that do run wait on data that never comes and the list exceeds the 2 s TDR.
- **Dropping every shader whose container names `XboxBvhBuilder` (35 programs here) removes the hang**: more than 3 minutes past that point with no device removal, the other root-UAV programs still running. Ray tracing is lost, which the black scene does not show yet.

So on NVIDIA, until the whole builder translates, it may be safer to drop it as a unit than to run part of it. Our local switch is `VICTORY_SKIP_BVH_BUILDER=1` (it matches the marker in the raw container); happy to open a PR if useful.
