## Original body

## What's wrong

`Shadow::copy_back` (`crates/victory-gpu/src/shadow.rs:190`) brings the GPU's writes back into title memory one 64 KiB piece at a time:

1. It reads the piece from title memory (`read_into`).
2. It puts the GPU's bytes into that buffer.
3. It writes **the whole piece** back with `write_mapped` (`:225-228`).

The title's threads keep running during all three steps. If one writes any byte of the piece that the GPU didn't touch, between steps 1 and 3, step 3 overwrites it with the older value.

The function's own comment says why this matters: it copies back only the shader-written bytes because putting older bytes back "broke the title's own records (a fence list read as -1)". The merge loop does that per byte, but the write-back still covers the whole piece, so the same corruption can happen through this race.

## Example

- A shader writes byte 0 of a page.
- While `copy_back` runs, a title thread bumps a counter at byte 64 of the same page.
- `write_mapped` puts the old counter back. The title's increment is lost.

## Evidence

A test reproduces it with real write-watched memory and a host copy. A title thread keeps bumping a word in each of 64 pages while `copy_back` writes a shader byte back into each page. On `main` (dd54de2), on GitHub's `windows-latest`:

```
assertion `left == right` failed: title writes undone by the copy-back
  left: 63
 right: 0
```

The test watches one word in each of the 64 pages: 63 of the title's writes were put back to an older value. The test is below in case it helps whoever picks this up. The same module also holds the test for #722.

<details><summary>Tests (append to <code>crates/victory-gpu/src/shadow.rs</code>)</summary>

```rust
#[cfg(test)]
mod race_tests {
    use super::*;
    use std::sync::atomic::{AtomicBool, Ordering::Relaxed};
    use windows_sys::Win32::System::Memory::{
        MEM_COMMIT, MEM_RELEASE, MEM_RESERVE, PAGE_READWRITE, VirtualAlloc, VirtualFree,
    };
    const MEM_WRITE_WATCH: u32 = 0x20_0000;
    const PAGES: usize = 64;

    /// Write-watched title memory of `PAGES` pages, freed on drop.
    struct Title(usize);
    impl Title {
        fn new() -> Title {
            // SAFETY: a fresh allocation, freed on drop.
            let p = unsafe {
                VirtualAlloc(
                    std::ptr::null(),
                    PAGES * PAGE,
                    MEM_RESERVE | MEM_COMMIT | MEM_WRITE_WATCH,
                    PAGE_READWRITE,
                )
            } as usize;
            assert_ne!(p, 0);
            Title(p)
        }
    }
    impl Drop for Title {
        fn drop(&mut self) {
            // SAFETY: our allocation.
            unsafe { VirtualFree(self.0 as *mut _, 0, MEM_RELEASE) };
        }
    }

    /// A host copy of the title memory, brought up to date, with shaders of
    /// the submission declared to write all of it and byte 0 of every page
    /// written by "the GPU".
    fn submitted(base: usize) -> Option<Shadow> {
        let (buffer, data) = host()?.shared_buffer((PAGES * PAGE) as u64)?;
        // SAFETY: a live buffer.
        let gpu = unsafe { buffer.GetGPUVirtualAddress() };
        let s = Shadow::new(buffer, data, gpu, base as u64, (PAGES * PAGE) as u64);
        assert_eq!(s.update(base, PAGES * PAGE), PAGES * PAGE);
        s.writing(base, PAGES * PAGE);
        for p in 0..PAGES {
            // SAFETY: inside the copy.
            unsafe { s.data.add(p * PAGE).write(1) };
        }
        Some(s)
    }

    fn peek(at: usize) -> u8 {
        // SAFETY: the tests pass addresses inside their memory.
        unsafe { (at as *const u8).read_volatile() }
    }

    /// The title's threads keep writing words no shader writes, in every
    /// page shaders wrote, while the copy-back runs: none goes back to an
    /// older value.
    #[test]
    fn copy_back_does_not_undo_title_writes_made_while_it_runs() {
        let title = Title::new();
        let base = title.0;
        let Some(s) = submitted(base) else {
            return; // no host GPU here
        };
        let stop = AtomicBool::new(false);
        let undone = std::thread::scope(|t| {
            let writer = t.spawn(|| {
                let mut last = [0u32; PAGES];
                let mut undone = 0;
                while !stop.load(Relaxed) {
                    for (p, last) in last.iter_mut().enumerate() {
                        let at = (base + p * PAGE + 64) as *mut u32;
                        // SAFETY: inside the title memory.
                        unsafe {
                            if at.read_volatile() != *last {
                                undone += 1;
                            }
                            *last += 1;
                            at.write_volatile(*last);
                        }
                    }
                }
                undone
            });
            s.copy_back(base, PAGES * PAGE);
            stop.store(true, Relaxed);
            writer.join().unwrap()
        });
        assert_eq!(undone, 0, "title writes undone by the copy-back");
        assert!((0..PAGES).all(|p| peek(base + p * PAGE) == 1), "the shader's bytes");
    }

    /// The title writes a page once the copy-back has put the shader's
    /// byte there (its read of the page is done), while later pages are
    /// still being copied back: the next refresh brings the write in.
    #[test]
    fn a_title_write_during_copy_back_reaches_the_copy() {
        let title = Title::new();
        let base = title.0;
        let Some(s) = submitted(base) else {
            return; // no host GPU here
        };
        std::thread::scope(|t| {
            t.spawn(|| {
                while peek(base + PAGE) != 1 {
                    std::hint::spin_loop();
                }
                // SAFETY: inside the title memory.
                unsafe { ((base + 8) as *mut u8).write_volatile(7) };
            });
            s.copy_back(base, PAGES * PAGE);
        });
        assert_eq!(peek(base + 8), 7, "in title memory");
        s.update(base, PAGE);
        assert_eq!(peek(s.data as usize + 8), 7, "in the copy");
    }
}
```

</details>

## Suggested fix

In the merge loop, call `watch::writing` and `write_mapped` only on each run of bytes the GPU actually changed (`*h != *o && *t != *h`), not on all `n` bytes. The copy can keep taking `*h = *t` as now.

## Related

- #124, #401 and #693 restructure `copy_back` but all keep the whole-piece write.
- #261 fixes other cases where older bytes were copied back (overlapping and gap ranges); this is a separate path.
- #722 is about the same function: pages marked current after a title write.

### Comment 2 — @Hiiva — 2026-11-24T09:30:45Z

I reproduced both this race and #722 with deterministic synthetic tests on native Windows/MSVC, then added a combined fix on top of #261: https://github.com/Hiiva/VIctory/commit/d44fa0053b1e4c75602d0deee75e07795362afea

The test injects a title write immediately after copy_back reads a piece. Before the changes, that write is overwritten. Restricting write-back to GPU-changed byte runs fixes this test while the separate write-watch refresh test still fails. The four shadow tests pass, diagnostics Clippy passes with warnings denied, and the integrated workspace suite passes. These tests use tiny WARP allocations without shader dispatch. The branch retains scoped kernel-write leases (#723).

This implementation retains write_mapped for each changed run, preserving the existing unmapped-memory handling. xstraok's Wine timing above makes the possible cost clear. The integrated native Windows build has reached menus, intro and setup, but I have not yet measured world copy-back performance. The epoch fix also deliberately refreshes pages written by copy-back again.

### Comment 6 — @Dufftwt — 2026-11-24T14:20:01Z

I've fixed the per-run cost in `Dufftwt:fix/copy-back-only-gpu-bytes` (`67125b3`). For each 64 KiB piece, one `VirtualQuery` checks that the GPU's runs lie in committed read-write memory, and if so, they're stored directly. Elsewhere each run still goes through `write_mapped`. A read-only page is left alone, as before, instead of faulting. A new test covers that.

This was one `copy_back` of 64 pages on GitHub's `windows-latest`, in a release build, 3 rounds each:

| Shader writes | Runs per page | `write_mapped` per run | Stored directly |
|---|---|---|---|
| every 2nd byte | 32,768 | 15.6 s | 14–17 ms |
| every 16th byte | 4,096 | 2.0 s | 5.4–5.7 ms |
| whole pages | 1 | 10.7 ms | 10.4–11.6 ms |

So scattered writes now cost about what whole pieces did.
