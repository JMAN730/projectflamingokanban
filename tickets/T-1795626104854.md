## Original body

A descriptor dword that the program also reads as a number is rebuilt from the host view's dimensions (`descriptor_data`) and stops there (`a scalar memory read as data`). The largest sub-case is not a dimension read at all: the dword is consumed as the **address operand of another `s_load_dword*`**, so what is needed is a memory address, and the descriptor-bit rebuild in that function has none for it.

879 programs of 25,322 on build 1.0.2.1, the largest remaining emit class on the whole pack; for comparison the 64-bit image atomic class was 653 before #539. All 879 are this shape — bucketing them by the fields of the consuming instruction gives 879 "used by an SMEM" and no other kind.

Repro, no game and no GPU:

```
victory translate <game>/shaders.rpf
```

The class is listed with an example; `--list` gives one line per program.

Examples (build 1.0.2.1, all mesh/vertex in the mirror-reflection family):

- `shaders.rpf@0x1000c65 MSNC_VS_MirrorReflectionPedTransformSkinD_907647ea_Wrapped` at `0x5838` (offset within the program is from the same run; take it as a pointer, the programs differ per build)
- `shaders.rpf@0x1006b86 MS_VS_MirrorReflectionPedTransformDecalsD_db76baa6_Wrapped`
- `shaders.rpf@0x100897b MSNC_VS_MirrorReflectionPedTransformSkinDecalsD_907647ea_Wrapped`

The shape in `descriptor_data`: the site is an `s_load_dword*` from a table or heap; `used_kind`/the descriptor's `Role::Resource` entry resolves a *using* instruction whose `Fields` are `Smem`, i.e. the register is the base (plus a constant) or the soffset of a further scalar load, usually after `s_mov`/`s_add` copies. `descriptor_data` takes the `Fields::Image` and `Fields::Buffer` cases and the rest fall to the catch-all refusal.

Two ways this could go, and the reason I am filing rather than patching:

- route the use to the address machinery instead of the bit rebuild when the consuming instruction is an smem load — but `why_no_base` then reports `an address loaded from memory`/`an address in an SGPR that is no root parameter` (268 programs between them today), so the two classes would trade rather than shrink;
- or give the loaded dword the real device address of the view, which needs the address of a descriptor's target rather than its dimensions — larger, but it also feeds the 195/73 address classes above.

Per-build offsets and counts only, no assets. Written with AI assistance from my own runs.
