## What happens

In the world on NVIDIA, about 7 s of every frame is one compute dispatch: `[compute 00167d58cc5a78d7]`, `dispatch 16x16x16`, which takes **~7,000 ms each** on the GPU. With `VICTORY_SHADER_LOOP_LIMIT=64` the same dispatch takes **6 ms**. So a translated loop in this program does not terminate on the host and runs to the 2^20-iteration limit.

On older trees this program did not translate at all (`a descriptor read only as data`; it appears in #444 and #461). On current `main` it translates, and this is where its cost shows up.

## Measurements

**Setup:** RTX 4070 SUPER (Ada, 32-lane, driver 32.0.16.1088), Windows 11 26200.
- **Build:** diagnostics build of `main` 0aca934 + #695 (needed for anything to be visible on NVIDIA).
- **Switches:** `--console series-s`, `VICTORY_GPU_TIMING=1`, `VICTORY_D3D12_DRED=1`.

| Run | World GPU time per frame | `00167d58cc5a78d7` per dispatch |
|---|---|---|
| default loop limit | 7,000–12,500 ms | 6,800–7,100 ms (14 dispatches timed, 97 s in total) |
| `VICTORY_SHADER_LOOP_LIMIT=64` | **170–270 ms** | **6 ms** |

The next slowest programs in the default run are far behind: two mesh programs at ~1 s each (`c82b7a0b51f8f8a9`, `d0503aa87911743e`, 2 dispatches each) and two compute programs at ~0.1 s per dispatch (`776d835da5ffa646`, `8bbcbda6008eaa37`).

The slow-command line names its first table: a placed **structured** buffer view of 2 elements of 680 bytes (format UNKNOWN, `StructureByteStride` 680, 1,360 bytes) at a title address. That fits the descriptor-read-as-data path that used to refuse this program, and the structured/raw handling discussed on #48 and #695.

## Why it matters

This is the largest single cost in a world frame on the reference machine class. Without it, GPU time is a few hundred ms. The rest of the frame there is mostly CPU waits: 40 `GPU memory wait timed out; continuing (fail-open)` in ~5 minutes, 2 s each.

## Where to look

The loop's exit condition as translated, probably in the waterfall or descriptor-data handling this program goes through. Expect a loop whose exit compare reads a descriptor or lane value that differs on the host (zeros from a structured/raw view mismatch would do it, see #48), so it never matches. A GBV run, or dumping this program's DXIL, should show which loop it is.
