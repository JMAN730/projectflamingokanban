### Bug

On RDNA2 (GFX10.3), `v_writelane_b32` (`VOP3 0x361`) and `v_readlane_b32` (`VOP3 0x360`) both **ignore the `EXEC` mask** and **wrap their `src1` lane selector modulo the wavefront size** (`src1[4:0]` / `& 31` in Wave32, `src1[5:0]` / `& 63` in Wave64).

Two issues existed on `main` (`ffe310e`):

1. **EXEC guarding drops `v_writelane_b32` writes to inactive lanes:**
   - `crates/victory-shader/src/ir.rs:931-935` unconditionally adds implicit `EXEC` reads (`r.extend(mask(EXEC))`) for all vector instructions, including `v_readlane_b32` and `v_writelane_b32`.
   - `crates/victory-shader/src/structure.rs:599-606` attaches an `EXEC` guard to `v_writelane_b32` whenever `EXEC` is narrowed without a branch (including `EXEC == 0`, or when `exec_lo` is itself passed explicitly as `src0` to spill `EXEC` into a VGPR lane).
   - `crates/victory-shader/src/emit/lower.rs:4217-4232` writes `v_writelane_b32`'s result via `int(self, r)` (which forwards `guard` to `write_i`), wrapping the write in `select(guard, r, old)` so writes targeting inactive lanes are silently discarded.

2. **Unmasked lane selectors:**
   - `crates/victory-shader/src/emit/lower.rs:4205-4232` passes raw `src1` directly into `read_lane(a, lane)` (`dx.op.waveReadLaneAt`) and `cmp(EQ, me, lane)` without masking to `wave_size - 1`. Any `src1 >= wave_size` (including negative or wrapped values such as inline `32` or `-1`, or computed SGPR indices) either drops `v_writelane_b32` writes or passes an out-of-range lane index to `WaveReadLaneAt`.

### Reproduction (Before Fix)

With synthetic Wave32 RDNA2 compute shaders lowered to DXIL and executed on hardware (NVIDIA GeForce RTX 3050 6GB Laptop GPU, driver `32.0.16.1742`, Windows 11, Windows SDK `dxil.dll` `10.0.26100.0`):

- Narrowed `EXEC` (lanes `16..31` active), `v_writelane_b32 v1, 0xcafebabe, 0`:
  lane `0` stayed `0x00001000` instead of `0xcafebabe` (while control `v_add_nc_u32` correctly obeyed `EXEC` on lanes `16..31`).
- Constant wrapped selectors (`v_writelane_b32` with inline `32` -> lane `0` and `-1` -> lane `31`):
  lanes `0` and `31` stayed `0x00004000` and `0x0000401f` instead of receiving `s0` (`0x13579bdf`) and `s1` (`0x2468ace0`).

### Fix

- `crates/victory-shader/src/ir.rs`: Skip implicit `r.extend(mask(EXEC))` for `v_readlane_b32` and `v_writelane_b32` while keeping the destination VGPR read for untouched lanes and preserving explicit `exec_lo` source operands.
- `crates/victory-shader/src/structure.rs`: Keep `v_readlane_b32` and `v_writelane_b32` unguarded (`None`) even if `exec_lo` appears as an explicit operand.
- `crates/victory-shader/src/emit/lower.rs`:
  - Added `Lower::mask_lane()` to mask console lane selectors by `self.wave() - 1` (`0x1F` in Wave32, `0x3F` in Wave64), folding constants so DXIL never receives out-of-range lane constants (and emitting zero extra ops for in-range constants).
  - Applied `mask_lane()` to `v_readlane_b32` (on the console-lane path, leaving dynamic `MaskData::Host` host-lane reads untouched) and `v_writelane_b32`.
  - Updated `v_writelane_b32` to write via `self.write_i(inst, r, None)`.
- Added synthetic regression tests across four modules:
  - `ir::tests::readlane_and_writelane_do_not_read_exec_implicitly` (Wave32 & Wave64)
  - `structure::tests::readlane_and_writelane_are_unguarded_under_narrowed_exec`
  - `emit::lower::tests::writelane_and_readlane_lower_and_validate_in_wave32_and_wave64` (Wave32 & Wave64 + `dxil.dll` validation)
  - `emit::valu_tests::v_writelane_b32_ignores_exec_and_masks_lane` (narrowed `EXEC` + control `v_add_nc_u32`, `EXEC == 0`, wrapped dynamic selectors `32`/`37`/`u32::MAX`/`0x1000_001F`, and explicit `exec_lo` spill to inactive lane `0`)
  - `emit::valu_tests::v_readlane_and_writelane_wrap_constant_lane_selector` (inline `32` and `-1` on both `v_writelane_b32` and `v_readlane_b32`)
  - `valu_tests.rs` enumerates SM 6.6 adapters supporting `WaveSize(32)`, so hardware execution runs on capable GPUs while WARP-only CI (wave size 4) still runs full `dxil.dll` validation without failing on `CreateComputePipelineState`.
