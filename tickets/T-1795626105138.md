## What

On `main` (e00a0198) under Wine on RADV, the world's draws are dropped in the thousands every frame because the pipeline's shader is refused, not because the pipeline is still being built: the frame line says `0 being made` from the first world frames onward, and the offline re-translation of the same programs says **679 of 751** translate.

This is the cause of the missing picture in the report that follows; filed separately because it is a translation gap, not a frame-time one.

## Measured (one run, world frames)

| | |
|---|---|
| draws/frame | 1,478–4,749 |
| dropped without a host pipeline | 442–4,440 per frame |
| pipelines "being made" at the drop | 0 in every world frame |
| indirect executions dropped | 181–1,045 per frame |

Two frame lines as printed:

```
0.2 fps, 5509.1 ms/frame (4946.0 preparing: copies 4389.7 ms 219.1 MB, textures 284.3 ms 155.3 MB; 135.8 on the GPU; 413.5 copying back 29.5 MB), 4749 draws/frame, dropped 4440 without a host pipeline (0 being made) and 829 indirect
0.2 fps, 4406.9 ms/frame (4084.5 preparing: copies 2984.8 ms 310.7 MB, textures 765.4 ms 223.8 MB; 62.3 on the GPU; 181.8 copying back 39.1 MB), 3712 draws/frame, dropped 1752 without a host pipeline (0 being made) and 639 indirect
```

The per-hash tail of the same frames names the pipelines that cost the most, all `pixel` or `compute`, for example `dropped 11.0/frame without a host pipeline: pixel 2deec721a63fe8a5`, `dropped 9.0/frame: compute 21d27f785da6d2b1`.

## Offline re-translation of the world's programs

The 751 console programs a boot-to-world run translated, re-translated offline with this tree (`cargo xwin`, RADV pipeline build, dxil-spv + spirv-val): **679 ok, 72 refused** — compute 377 ok / 65 refused, mesh 81 / 1, pixel 144 / 6, vertex 77 / 0.

Refusals by reason (all 72):

| Reason | Count |
|---|---:|
| a whole-wave section step the simulation does not follow | 19 |
| an address not from a root parameter | 13 |
| an address from a phi | 8 |
| an address from a root parameter that is no address | 6 |
| a scalar memory read as data | 5 |
| a structured buffer of unknown stride | 4 |
| an address in an SGPR that is no root parameter | 4 |
| barycentrics read directly | 3 |
| a lane mask read as data | 3 |
| a descriptor neither loaded nor built | 2 |
| one each: an LDS the program does not allocate, `buffer_load_ushort`, a typed root view, an LDS operation | 4 |

`#461` classified runtime failures on another build (303 in three minutes, 93% dataflow); this is the offline set of one build on RADV, and the split is the same kind: address, mask and buffer-stride dataflow, not missing instructions.
