### Comment 4 — @guilhermemorelidev — 2026-11-23T23:42:58Z

Same crash on another Intel CPU, and I dumped the bytes at the fault address, so this is confirmed rather than a guess:

    crash-4e8aa70.bin: 0F 01 FC 48 83 C0 40 4C 39 D0 72 F4 ...

`0F 01 FC` is **CLZERO** (AMD-only, CPUID Fn8000_0008 EBX bit 0). The code is a cache-line zeroing loop:

    clzero
    add rax, 0x40
    cmp rax, r10
    jb  <loop>

Intel CPUs raise #UD (0xc000001d) on it, so the title (built for the Zen 2 console CPU) dies in System Init before the first frame, on every run. That also explains why this only affects Intel hosts (same fault as this issue's original report).

**System**
- CPU: Intel Core i5-14600KF (AVX2: yes, no CLZERO)
- GPU: AMD Radeon RX 9070, driver 26.11.2
- RAM: 32 GB DDR4
- OS: Windows 26H2 (build 26300.9974)
- VIctory: ZIP download of `main`, 2026-11-23
- Title build (from the game's own debug dump): 930.048.020-vb_sub_story

**Also tried (same fault address every time)**
- release and `diag` builds
- `VICTORY_D3D12_WARP=1`
- `--console series-s`
- `--unimplemented zero`

**Possible fix:** emulate CLZERO on hosts without it, either in the exception handler (zero the 64-byte line at rax, rip += 3) or by patching it when the image is prepared. There may be other AMD-only instructions behind this one; I can retest on Intel if a fix lands.

### Comment 6 — @jpinat — 2026-11-24T09:13:30Z

PRs are limited to collaborators right now, so leaving this here: after CLZERO/SSE4a, the other two AMD-only instructions XCL emulated, `rdpru` and `rdpid`, still aren't handled in `emulate_amd_only`.

Branch: https://github.com/jpinat/VIctory/tree/loader/emulate-rdpru-rdpid (one commit, `crates/victory-loader/src/crash.rs` only)

- `rdpru` (`0f 01 fd`, no Intel CPU has it): ECX 0/1 (MPERF/APERF) read the TSC, since only their ratio is meaningful; any other ECX gives 0 with CF clear.
- `rdpid` (`f3 [rex] 0f c7 /7`, missing on Intel before Ice Lake, e.g. Coffee/Comet Lake, which meet the AVX2 requirement): reads TSC_AUX via `rdtscp`.

I haven't seen the title execute either one; it's hardening for older Intel hosts, like the existing `clwb` path. 5 synthetic tests, no game data; `cargo test -p victory-loader` passes on Windows 11 / Ryzen (Zen 3), where both are native, so the #UD path is untested on real Intel hardware. If someone here on a pre-Ice Lake Intel could try it, that would confirm it. @Marvisak happy to adjust if you'd like it pulled in.
