## Original body

The release build at ffe310eb2098e52169f4c44db5ffdabf43a72622 opens briefly and exits before I can reach Settings. Repeated launches from the repository root with the same local package produced the same unhandled breakpoint at title-relative offset 0x1dac734. The next two stack frames were +0x5b97b29 and +0x63e78.

Environment: Windows 10 Pro 22H2 (19045.7846), GeForce RTX 3070, Windows driver version 32.0.16.1088, Rust 1.98.1 MSVC. To reproduce, build with cargo build --release -p victory and run victory.exe run <local title exe> --execute.

The loader reported zero missing imports for the bound modules. Immediately before the breakpoint the host rejected three root signatures with flags 0xc01 and E_INVALIDARG. This matches the graphics symptom in #84 and #175, but does not establish what triggers the breakpoint. Package completeness has not been independently verified. Separate synthetic test results on this PC are in #1605.

### Comment 1 — @EduBertozzi — 2026-11-24T19:54:03Z

The `0xc01` root signatures refused just before the stop point to Windows 10's built-in D3D12 runtime: it has no directly indexed heaps and stops at shader model 6.5 (#84). On `main` the title then stops early. In #741 the stop was at a different offset (`+0xb5a5f8`), and there it went away with the Agility runtime. So the quickest check is the same run with the D3D12 Agility SDK runtime loaded:

- **#175**: `cargo xtask agility`, then run that PR's `victory.exe`. It loads `target\<profile>\D3D12\D3D12Core.dll`.
- or **#969**: set `VICTORY_D3D12_AGILITY` to a folder holding `D3D12Core.dll` (from the `Microsoft.Direct3D.D3D12` 1.620.x package).

If the `0xc01` refusals are gone and `+0x1dac734` still happens, it's a separate problem worth this issue on its own. Section 2 of #1612 has both options side by side.

AI-assisted (Claude Code).


### Comment 2 — @HocotateGuy15 — 2026-11-24T19:56:54Z

Resolved locally. On PR #175 at 19aec59 I verified that the process loaded the app-local D3D12Core.dll from Microsoft.Direct3D.D3D12 1.620.2. With the original flat package directory, the 0xc01 refusals disappeared and the process still exited at exactly +0x1dac734.

The package layout manifest specified nested destination directories, but the copied files had all been placed in one directory. I restored 67 missing paths as hard links to the existing files using the manifest; no source files were missing for those entries. With the same executable, SDK, and game files, the next run stayed open past 15 seconds and reported 30 fps and 21 draws/frame. This resolves the reported startup exit on this machine. Settings and world entry were not tested. No new runtime patch was needed. AI-assisted.
