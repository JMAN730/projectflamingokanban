## Original body

Since #612 was merged (`9a92ccf`), **323 shader programs that emitted and validated on main no longer translate**. Reverting only that merge on the current main (`58fed37`) restores exactly those programs.

Measured offline with `victory translate --list --validate` over the title's `shaders.rpf` + executable (26,096 programs), dxil.dll 1.9.2602.17, comparing outcomes program by program:

| | failed | rejected by validator | validated |
|---|---:|---:|---:|
| main before the merge wave (`c2e7254`) | 3,734 | 185 | 21,983 |
| main `58fed37` | **4,063** | 161 | **21,678** |
| main `58fed37` with #612 reverted | 3,730 | 171 | 22,001 |

With #612 reverted, 323 programs go from failed back to validated and 10 from failed to rejected, and nothing else moves. The refusals they now hit:

| refusal | programs |
|---|---:|
| a descriptor read only as data | 227 |
| a scalar memory read as data | 32 |
| a structured buffer of unknown stride | 23 |
| the first half of an interpolation | 20 |
| a lane mask read as data | 17 |
| barycentrics read directly | 7 |
| a descriptor's address or format read as data | 3 |
| s_getpc_b64 | 2 |

What seems to happen: following phi dependencies to a fixpoint marks many more phis as read. Their missing incoming values, which were zero-substituted before, now reach the emitter's other refusals. That goes well beyond the `s_memtime` case in #604. (I posted the same numbers on #699, which makes the same change.)

Some of those zeroes may be wrong in the same silent way as the timestamp. Still, 323 working programs is a large in-game cost. Two ways out I can see:
- keep the stricter marking only for value kinds where a zero is known to be wrong (timestamps), or only when the missing edge carries such a value;
- revert until the affected refusals (mostly descriptor-as-data, which #136/#180 address) are handled.

### Comment 2 — @LAKSHYA-cmd-tech — 2026-11-24T09:14:17Z

Analysis of the 323 program translation regression and fix:

### Mechanism
In #612, `fill_phis` propagated `read_phis` transitively to all predecessor phis before the substitution decision. However, in retail shaders with wide joins across control flow (e.g. multi-register descriptors, structured buffer bounds, interpolation components), intermediate phis frequently join registers where one path carries a harmless non-data entity (such as `Val::Missing("a descriptor read only as data")` or `Val::Missing("a structured buffer of unknown stride")`).
Prior to #612, because no instruction directly called `get(intermediate_phi)`, the unread join safely substituted zero and emitted clean, validated DXIL. Marking intermediate phis as `read_phis` caused line 6746 (`Some(Val::Missing(why)) if read_phis.contains(...) => return Err(Stop::Retry(...))`) to abort emission for all 323 programs, even though no instruction in the program was actually reading that missing value as integer data.

### Solution
Distinguish direct readers (`direct_reads = self.read_phis.clone()`) from transitive predecessors:
1. When a phi is directly read by an instruction (`is_direct`), any incoming `Val::Missing(why)` triggers `Stop::Retry(phi.value, why)`.
2. When a phi is only an intermediate predecessor in a phi chain:
   - Values where zero substitution is known to produce incorrect behavior (such as `s_memtime` timestamps, i.e. `why.contains("scalar memory") || why.contains("s_memtime")`) still trigger `Stop::Retry(phi.value, why)`. This ensures #604 and the `a_missing_value_stays_missing_through_two_live_joins` test remain 100% satisfied.
   - For other missing entity types (unused descriptors, unknown buffer strides, interpolation halves), intermediate phis safely substitute zero (`false` for bits), restoring the 323 programs without crashing emission.

Verified: `a_missing_value_stays_missing_through_two_live_joins` passes, 89 passed in `crates/victory-shader`, clippy clean, `cargo xtask policy` ok (153 files ok).
Available on fork branch `fix/shader-phi-transitive-missing-values`.
