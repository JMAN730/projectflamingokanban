## What

The IR already modelled `v_swaprel_b32` and `v_movrelsd_2_b32` as M0-relative accesses (reads and writes over the range from the encoded register up to the program's VGPR count). The emitter did not handle either opcode. Their results became missing values, and any shader that used them failed to translate as soon as an effect read one.

- **`v_movrelsd_2_b32`**: `v[dst + M0[25:16]] = v[src + M0[9:0]]`. This shares the `v_movrel*` lowering, which now takes separate source and destination indices.
- **`v_swaprel_b32`**: swaps `v[dst + M0[25:16]]` and `v[src + M0[9:0]]`. The destination is written first and the source last, as on the console, so a register named by both keeps its value.
- **Helpers**: the select chain over an M0-relative range moves into `rel_read`, alongside `m0_halves` and `old_vgpr`, and is shared with the existing `v_movrel*` arms.

## IR fix

`ir::effects` deduplicated an instruction's reads but not its writes. For `v_swaprel_b32` the two indexed ranges always overlap up to the last VGPR, so every register in the overlap was written twice. That gave it two SSA values: `Inst::write` returned the first one, while later readers saw the second, which was never defined ("a value defined after its use"). `v_swap_b32 vN, vN` had the same problem. Writes are now deduplicated the same way reads are.

## Tests

- **`emit::lower::tests::m0_relative_moves_with_two_indices_translate`** (all platforms): both opcodes, followed by an LDS store of their result, must lower. It fails without this change.
- **`emit::valu_tests::m0_relative_swaps_and_moves_index_source_and_destination_apart`** (Windows, hardware and WARP): seven cases that check the values read back:
  - swaps in both directions;
  - both indices naming the same register;
  - `v_movrelsd_2_b32` with every ignored M0 bit set.
