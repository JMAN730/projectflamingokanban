## Summary
Introduces an opt-in runtime quality/budget switch `VICTORY_TEXTURE_MIP_DROP` (clamped `0..=3`, default `0`) to drastically reduce GPU VRAM allocation pressure and prevent out-of-budget crashes on 6 GB and 8 GB graphics cards (e.g. mobile RTX 3050/3060/4050/4060 and 8GB desktop cards).

Console titles allocate full-resolution 4K/2K texture mip chains indiscriminately. Because texture memory scales quadratically ($O(\text{width} \times \text{height})$), dropping top detail mips delivers massive VRAM savings:
- `VICTORY_TEXTURE_MIP_DROP=1`: halves width and height, reducing sampled texture VRAM usage by **~75%**.
- `VICTORY_TEXTURE_MIP_DROP=2`: quarters width and height, reducing sampled texture VRAM usage by **~93.75%**.
- `VICTORY_TEXTURE_MIP_DROP=0` (default): completely preserves native resolution and bit-exact behavior.

---

## Implementation Details

1. **Selective Downscaling (`crates/victory-gpu/src/resource.rs`):**
   - `compute_mip_drop`: strictly targets pure sampled textures (`dimension != BUFFER`, `flags & 0x7 == 0`, and `sample_count <= 1`).
   - Render targets, depth-stencil surfaces, UAVs, and buffers are unconditionally exempted to prevent breaking render passes and frame synchronization.
   - Resource dimensions (`Width`, `Height`, `DepthOrArraySize`) and `MipLevels` are scaled accordingly.
   - Includes unit test `mip_drop_computation_respects_constraints`.

2. **Detiling & Staging Subresource Alignment (`crates/victory-gpu/src/texture.rs`):**
   - Tracks `mip_drop` inside `Staging`.
   - Offsets console subresource reads during host staging detiling: `console_mip = host_mip + mip_drop`.
   - Host mip 0 consumes console mip `mip_drop`, cleanly skipping top-level unallocated mips without disturbing GNM tiling math or slice pitches.
   - Staging buffer footprints and total allocation sizes are downscaled to match the active host mip dimensions.

3. **D3D12 SRV Re-basing (`crates/victory-gpu/src/descriptor/host.rs`):**
   - Added `adjust_srv_for_dropped_mips` to clamp and re-base `MostDetailedMip` across all SRV dimension variants (1D, 2D, 3D, Cube, Arrays), preventing D3D12 debug layer validation errors.

### Comment 6 — @antikohza — 2026-11-24T14:46:31Z

Huge thank you to @MichaelSmithAI, @bittertea0323, and @crashbashash for the rigorous code review, hardware profiling, and real-title frame run data.

We have addressed all three findings in commit [`e22e746`](https://github.com/antikohza/VIctory/commit/e22e746dc718d70248a81d973690575ed36987e4) on `feat/texture-mip-drop-budget` ([full compare against main](https://github.com/antikohza/VIctory/compare/ffe310e...feat/texture-mip-drop-budget)).

---

### 1. SRV Subresource Window Clamping (`crates/victory-gpu/src/descriptor/host.rs`)
As identified by @MichaelSmithAI, the previous adjustment exposed out-of-window guest mips when a view straddled the drop boundary. 

All descriptor view variants (1D, 2D, 2DArray, Cube, CubeArray, 3D) are now routed through a unified `adjust_mips` helper:
```rust
pub fn adjust_mips(most_detailed: &mut u32, mip_levels: &mut u32, drop: u32, host_mips: u32) {
    let dropped_from_view = drop.saturating_sub(*most_detailed);
    *most_detailed = most_detailed.saturating_sub(drop);
    if *mip_levels != u32::MAX {
        *mip_levels = mip_levels
            .saturating_sub(dropped_from_view)
            .min(host_mips.saturating_sub(*most_detailed));
    }
    if *mip_levels == 0 {
        *mip_levels = 1;
    }
}
```
- **Straddled views:** For a 64×64 texture with 7 levels and a drop of 2, host levels 0–4 represent guest levels 2–6. A guest view requesting levels `{1, 2, 3}` (`most_detailed = 1`, `mip_levels = 3`) now calculates `dropped_from_view = 1`, clamps `*most_detailed = 0`, and adjusts `*mip_levels = 2`. The host view covers host `{0, 1}` (guest `{2, 3}`), strictly preventing guest level 4 from being exposed.
- **Pruned views:** If a view falls entirely within dropped guest mips (`surviving == 0`), `mip_levels` clamps to `1` (targeting host mip 0) to ensure D3D12 `MipLevels >= 1` runtime validity without unbounded reads.
- Added CPU unit tests (`srv_mips_adjustment_handles_straddled_and_dropped_views`) covering straddled, inside, outside, fully-pruned, and `u32::MAX` windows.

---

### 2. Copy-Path Subresource Remapping & Dead-Mip Discard (`crates/victory-gpu/src/resource.rs`, `list.rs`)
Following @bittertea0323's diagnosis and the `try/pr89` reference, `HostTexture` now stores `title_mips` and `mip_drop`, with subresource index remapping across array slices and mips:
```rust
pub fn map_subresource(guest_sub: u32, guest_mips: u32, drop: u32) -> Option<u32> {
    if guest_mips == 0 {
        return Some(guest_sub);
    }
    let slice = guest_sub / guest_mips;
    let guest_mip = guest_sub % guest_mips;
    if guest_mip < drop {
        return None; // Mip was dropped
    }
    let host_mips = guest_mips.saturating_sub(drop).max(1);
    Some(slice * host_mips + (guest_mip - drop))
}
```
- **Copy remapping:** Both source and destination subresources in `copy_texture_region` are mapped via `host_subresource()`. For example, retained guest mip 6 maps to host mip 4.
- **Dead copy pruning:** If a copy targets a dropped mip (`None`), it early-returns with zero-cost discard: staging allocations and D3D12 command tokens are completely skipped.
- **Coordinate preservation:** Texel copy coordinates (`DstX, DstY, DstZ`, `SrcBox`) in `CopyTextureRegion` remain 1:1 and are **not** downscaled, preserving required BC block alignment since surviving host mips have the exact same dimensions as their guest subresource counterparts.
- **Whole-resource copies:** In `copy_resource`, mismatched `mip_drop` copies are safely skipped with a one-time log.

---

### 3. Static Allocation Size Floor (`crates/victory-gpu/src/resource.rs`)
To eliminate the 1×1 host texture copy crash (frame 1405) at the root without runtime dynamic promotion overhead:
- Added a static size floor in `compute_mip_drop`: textures are only eligible for mip-dropping if `desc.width.max(desc.height) >= 1024` and `desc.mip_levels > k + 1`.
- `Texture3D` is excluded from drops.
- Textures $\le 512$ represent $< 2.5\%$ of game texture memory. Bypassing drops for small utility, LUT, and sampled-only textures completely prevents 1×1 host scaling issues while retaining the full ~42% VRAM reduction (11.3 → 6.6 GiB) on 2K/4K streaming textures.

---

### 4. Telemetry Note
The VRAM/GTT telemetry shared by @crashbashash on the RX 6800 XT highlights exactly why this patch is necessary: when allocation pressure crosses ~13 GB, drivers/vkd3d-proton begin spilling into GTT system memory (logging hundreds of fallback allocations), tanking frame presentation times into seconds per frame. Bringing VRAM down to ~6.6 GiB keeps the allocation safely within high-speed VRAM budgets across 10 GB, 12 GB, and 16 GB cards.

Verified with `cargo check --all-targets` and clean CPU test pass.

### Comment 9 — @antikohza — 2026-11-24T15:15:59Z

Spot-on catch, @bittertea0323. The 13,876-byte flat captures vs 2.4–3.0 MB full captures clearly pinpointed the issue.

We have resolved this in commit [`4c84a09`](https://github.com/antikohza/VIctory/commit/4c84a0977c27937a0f6c96580e4a1f9653d2d5f5) on `feat/texture-mip-drop-budget` ([compare against main](https://github.com/antikohza/VIctory/compare/ffe310e...feat/texture-mip-drop-budget)).

### 1. Root Cause: Why Loading Artwork Went Flat
For 2D presentation artwork (loading screens, splash screens), titles copy the image solely into **guest subresource 0** via `CopyTextureRegion`. No lower mips exist on disk or are ever uploaded for loading artwork.

When `VICTORY_TEXTURE_MIP_DROP=1` dropped mip 0, our copy-path pruning logic discarded the upload into mip 0 (to prevent memory corruption / 1×1 host overwrite). Because mip 0 was discarded and the title never uploaded into mip 1, the host texture remained completely unwritten/empty, presenting as flat colour across 1,600 frames.

### 2. The 3.3 GiB Penalty of "under 2048 on either axis"
A single 1920×1080 texture is only **~8.3 MB** uncompressed (or ~2.1 MB in BC7). Keeping it at full resolution costs less than 10 MB of VRAM.

The jump from **7.0 GiB to 10.3 GiB** (+3.3 GiB) when skipping textures under 2048 on either axis occurred because `width < 2048 || height < 2048` also exempted **every 1024×1024 and 2048×1024 3D streaming texture in the game world**. On 8 GB / 10 GB GPUs, 10.3 GiB will still push drivers into system memory / GTT spilling.

### 3. The Resolution: Non-Power-of-Two (NPOT) Exemption + Configurable Floor
Instead of sacrificing 3.3 GiB of world texture savings to protect an 8 MB loading screen, we distinguish 2D presentation assets from 3D world assets:

1. **Non-Power-of-Two (NPOT) Exemption:**
   ```rust
   // Exclude non-power-of-two (NPOT) textures: display artwork, loading screens,
   // video frames, and UI presentation surfaces (e.g. 1920x1080, 1280x720, 2560x1440).
   if !desc.width.is_power_of_two() || !desc.height.is_power_of_two() {
       return 0;
   }
   ```
   - **1920×1080 is non-power-of-two.** Standard display aspect ratios (1080p, 1440p, 4K, 720p, 21:9 ultrawide) used for loading artwork, video playback, and UI screens are non-power-of-two.
   - **3D streaming textures in RAGE / D3D12 BC mip chains are strictly power-of-two** (1024×1024, 2048×1024, 2048×2048, 4096×4096).
   - This keeps the 1920×1080 loading screen at 100% full quality (full 2.4–3.0 MB artwork captures, zero flat frames) while allowing all 1024/2048/4096 world textures to drop, **maintaining the full ~4.3 GiB saving (~7.0 GiB peak VRAM)**.

2. **Configurable Minimum Size Floor:**
   ```rust
   let min_size = crate::texture::texture_mip_drop_min_size(); // defaults to 1024
   if desc.width < min_size || u64::from(desc.height) < min_size {
       return 0;
   }
   ```
   - Defaults to `1024` (dropping 1024, 2048, and 4096 world textures, preserving utility/noise/LUT textures).
   - Testers who explicitly prefer your conservative mode can set `VICTORY_TEXTURE_MIP_DROP_MIN_SIZE=2048` to skip textures under 2048 on either axis.


### Comment 10 — @antikohza — 2026-11-24T15:50:17Z

Great catch, @DrDarkDK. Excellent synthetic test case with the 512×512 4× MSAA source and 1024×1024 3-mip destination.

We have addressed this in commit [`2df78b6`](https://github.com/antikohza/VIctory/commit/2df78b69db82e23e94e0e25845f788233fac635a) on `feat/texture-mip-drop-budget` ([compare against main](https://github.com/antikohza/VIctory/compare/ffe310e...feat/texture-mip-drop-budget)).

### The Issue
While `copy_texture_region` remapped subresource indices via `host_subresource()`, `list.rs::resolve` was passing raw guest `dst_sub` and `src_sub` directly to the host D3D12 command list.

For your test case (1024×1024 destination with 3 mips and `VICTORY_TEXTURE_MIP_DROP=1`):
- Guest mip 0 (1024×1024) is dropped.
- Guest mip 1 (512×512) corresponds to **host mip 0**.
- Guest mip 2 (256×256) corresponds to **host mip 1**.

Passing raw `dst_sub = 1` targeted host mip 1 (256×256), creating an invalid dimension mismatch when resolving the 512×512 MSAA source.

### The Fix
1. **Subresource Index Remapping & Dead-Mip Pruning (`crates/victory-gpu/src/list.rs`):**
   Both `dst_sub` and `src_sub` are now remapped through `host_subresource()`:
   ```rust
   let dst_sub = if let Some(hd) = crate::resource::host_copy(dst) {
       let Some(mapped) = hd.host_subresource(dst_sub) else {
           return; // Target mip was dropped; prune dead resolve
       };
       mapped
   } else {
       dst_sub
   };
   let src_sub = if let Some(hs) = crate::resource::host_copy(src) {
       let Some(mapped) = hs.host_subresource(src_sub) else {
           return;
       };
       mapped
   } else {
       src_sub
   };
   ```
   - In your test: guest destination mip 1 (`dst_sub = 1`) now maps directly to **host mip 0 (`dst_sub = 0`)**.
   - If a resolve targets a dropped guest mip (e.g. guest mip 0), it early returns, discarding the dead resolve.

2. **Per-Mip Subresource Dimension Matching:**
   Subresource dimensions are now computed per mip level (`(a.Width >> dst_mip, a.Height >> dst_mip)`) rather than comparing base resource mip 0:
   ```rust
   let dst_mips = u32::from(a.MipLevels).max(1);
   let src_mips = u32::from(b.MipLevels).max(1);
   let dst_mip = dst_sub % dst_mips;
   let src_mip = src_sub % src_mips;
   let dst_w = (a.Width >> dst_mip).max(1);
   let dst_h = (u64::from(a.Height) >> dst_mip).max(1);
   let src_w = (b.Width >> src_mip).max(1);
   let src_h = (u64::from(b.Height) >> src_mip).max(1);
   if (dst_w, dst_h) == (src_w, src_h) {
       list.list
           .ResolveSubresource(to, dst_sub, from, src_sub, format);
   } else if let Ok(list1) = list.list.cast::<ID3D12GraphicsCommandList1>() {
       let rect = RECT {
           left: 0,
           top: 0,
           right: dst_w.min(src_w) as i32,
           bottom: dst_h.min(src_h) as i32,
       };
       list1.ResolveSubresourceRegion(to, dst_sub, 0, 0, from, src_sub, Some(&rect), format, D3D12_RESOLVE_MODE_AVERAGE);
   }
   ```
   - For your test case: host destination mip 0 (512×512) matches the 512×512 MSAA source 1:1, invoking `ResolveSubresource(to, 0, from, 0, format)` cleanly on hardware and WARP.
