## Original body

The README lists one tested machine (RX 6700 XT, RDNA2). This is a live run on an RX 6600 (RDNA2, GFX10.3) using the diagnostics build, covering the menus, world load, D3D12 debug layer, DRED breadcrumbs, and shader loop-limit testing.

Environment
- GPU: AMD Radeon RX 6600 (RDNA2)
- CPU: AMD Ryzen 5 9600X 6-Core Processor
- OS: Windows 11 x64
- Rust: 1.98.1 (from rust-toolchain.toml), MSVC 2022
- VIctory: diag profile (cargo build --profile diag -p victory --features diagnostics)
- Flags tested:
  - VICTORY_D3D12_DEBUG=1 and VICTORY_D3D12_DRED=1
  - VICTORY_SHADER_LOOP_LIMIT=1000

Result
Menus boot and run at 30 fps, and the title loads into the world (observed on frames 1533-1537 and 7699-7724). Once in the world, host submissions slow to 3.3-3.7 seconds and trigger DXGI_ERROR_DEVICE_HUNG (0x887A0006).

Shader loop-limit test
Running with VICTORY_SHADER_LOOP_LIMIT=1000 did not prevent the hang. The 33-list submission still took 3384 ms and ended in 0x887A0006, which suggests runaway translated shader loops (>1000 iterations) are not the primary cause of the TDR.

D3D12 Debug Layer
Running with VICTORY_D3D12_DEBUG=1 reported a resource state mismatch on IASetVertexBuffers:
- Resource: title buffer 0x16020000+0xae00000 (subresource 0)
- Actual State: 0x8 (D3D12_RESOURCE_STATE_UNORDERED_ACCESS)
- Expected State: 0x1 (D3D12_RESOURCE_STATE_VERTEX_AND_CONSTANT_BUFFER)

DRED Breadcrumbs
Running with VICTORY_D3D12_DRED=1 stopped at command 403 of 1288 (op 5) in a 16-list submission. Lists and pipelines in flight included:
- List 5: compute f4ec8e2b4d2439f8, a3d1a26ad0c8c2cd, 34d88edf583f3778, 690e2883f9dd25d8, a1bf269d5b19f025
- List 7: vertex 6e750a37b1da6949 / pixel d7b97830ede61511; compute 914e86141fa3b37f, 8dd8d739047fe557, cc6c9f45e334afb7; indirect compute f41afb810c1e29c6, 130d3d04172e5456
- List 12: indirect mesh c5ffa556ab926155 / pixel c4a269f4eeba3cac
- List 14: compute f753697c1c03772b, 559fb027c6d5b1db
- List 15: compute 2c3592e9bbad543f

Why this report may be useful
This adds a second RDNA2 data point (RX 6600) alongside the RX 6700 XT, confirms the IASetVertexBuffers UAV-to-vertex-buffer state mismatch under the D3D12 debug layer, and rules out shader loop counts above 1000 as the cause of the world TDR.

### Comment 3 — @pickles976 — 2026-11-24T18:24:35Z

The "runaway translated shader loops" hypothesis has a known upstream producer worth ruling out before any loop-hunting: **wave-mode legalization without lane remapping**. RDNA2 advertises 32-lane waves; if the build ran the default `recommended_wave64_mode` (native Wave32, no emulate), cross-lane reductions return values from lanes that do not exist on the console semantics the shader was written against — and a loop whose exit condition consumes one of those values is not "sometimes wrong", it is **structurally free-spinning**: >1000-iteration guard trips, GPU resets, `0x887A0006` arrives exactly as reported, and the log shows a healthy machine right up to the hang. The one-run screen (identical setup, add `VICTORY_WAVE64_EMULATE=emulate`): if the world-stage hang moves or changes shape, this class produced it and the report becomes a data point for the default-policy debate; if it hangs identically, the loop hypothesis stands alone and the loop bisection is worth doing. (TdrLevel intake line applies here too, per #1054.)
