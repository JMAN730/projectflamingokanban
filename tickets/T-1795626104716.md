## Original body

## Bug Description

I'm trying to run GTA VI (Xbox Series S build) using VIctory on Windows, but the game crashes during execution with an unhandled exception.

The crash happens consistently at the same address, including when using the diagnostics build.

## PC Specifications

- **CPU:** Intel Xeon E5-2630 v4 (AVX2 supported)
- **GPU:** NVIDIA GeForce RTX 5050
- **RAM:** 8 GB
- **OS:** Windows 11
- **Console target:** Xbox Series S

## Steps to Reproduce

1. Install Rust and Visual Studio C++ Build Tools.
2. Download and compile VIctory.
3. Configure `victory.toml` with the game directory.
4. Build the diagnostic version:

`cargo build --profile diag -p victory --features diagnostics`

5. Enable logging:

`set VICTORY_LOG=victory_loader=debug,info`

6. Run:

`target\diag\victory.exe run "PATH_TO_GAME\game_scarlett_master.exe" --execute --console series-s`

## Crash Log

`VIctory: unhandled exception 0xc000001d at victory-image-b99f876b74d4a77f.dll+0x4ecc84a`

The stack trace includes:

- `victory-image-b99f876b74d4a77f.dll+0x247905f`
- `victory-image-b99f876b74d4a77f.dll+0x19f4f54`
- `victory-image-b99f876b74d4a77f.dll+0x580437e`
- `victory-image-b99f876b74d4a77f.dll+0x43a4911`

The console also displays:

`HTTP connection blocked destination=submit.backtrace.io:443`

## Expected Behavior

The game should progress through the supported boot sequence without an unhandled exception.

## Actual Behavior

Execution terminates with exception `0xC000001D`. Repeating the test using the diagnostic build produces the same exception at the same module offset.

## Question

Could this be an unsupported CPU instruction, an issue with the generated game DLL, or a missing implementation in VIctory?

Are there additional diagnostic commands I can run to identify the exact instruction causing the crash?

## Original comments

### Comment 1 — @leonardo-silva-pinheiro — 2026-11-24T02:56:47Z

The faulting offset `+0x4ecc84a` is a `clwb` instruction (same site as #103 and #210). The Xeon E5-2630 v4 is Broadwell, which has no CLWB. `main` emulates it since #45 (`7d33c46`), so please `git pull`, rebuild and retest; on #108 another Broadwell user confirmed the title boots past this after updating.

Two other notes:
- With 8 GB of RAM, the title's ~6.5 GB allocation at startup will likely hit the Windows commit limit next (#23). If `crashes.log` then reports error 1455, increase the paging file size.
- `HTTP connection blocked destination=submit.backtrace.io:443` is expected: VIctory keeps the title offline by design.
