## Original body

Title: Crash 0xc0000005 at title+0xb5a5f8 (read 0x68) ~2 s after XUserAddAsync, entering the world (NVIDIA RTX 3060)

Environment
- Windows 10 22H2 (10.0.19045.6456)
- NVIDIA GeForce RTX 3060 12 GB, driver 32.0.16.1656 (616.56)
- VIctory main @ ffe310e, release and diag builds
- Title 7952987A, Game Version 930.048.020, console series-x

Note: the README lists only an AMD RX 6700 XT as tested; this is an NVIDIA (wave32) GPU.

What happens
Boot, menus, intro and loading work. After loading into the world the screen
stays black and the title crashes, always at the same address:

  unhandled exception 0xc0000005 at victory-image-b99f876b74d4a77f.dll+0xb5a5f8 (read 0x68)
  #1 +0x5bb7cce  #2 +0x1dbdc0b  #3 +0x5bb7111  #4 +0x5bb7071  #5 +0x63e78
  (a second thread faults at the same address via +0x1dc5cb4 / +0x5bbf240)

Reproduced in 5 of 5 runs. With VICTORY_LOG=victory_hle=debug, the last
HLE activity before the fault is:

  XUserAddAsync: the offline local user options=1      (~2 s earlier)
  dstorage: submit commands=51
  title path path=D:\decorations\presets\*
  title path path=D:\decorations\presetgroups\*
  -> fault 0.1 ms later

Also logged at boot: "method not implemented" on device slots 0x218 and 0x1c8
(menus keep working afterwards, so probably unrelated).

What I tried
- Creating empty D:\decorations\presets and \presetgroups on the host: same crash.
  (Note: D: is not a virtual drive, so the title is probing the host's real D:.)
- PR #702 (gpu/dxr-bvh-builder): same crash at the same address, no DXR log lines.

Diag log attached.

With #175 alone and its app-local Agility runtime, their root-signature refusals disappeared and the game created its profile and settings saves. They later hit a GPU device hang during world loading. Your RTX 3060 already reaches the menus and intro, so the point to compare is the transition after loading. [Matched #741 run](https://github.com/Marvisak/VIctory/issues/741#issuecomment-7127517462)

Was your reported run already using app-local Agility? If it used the in-box runtime, could you compare the same save and settings with [#175](https://github.com/Marvisak/VIctory/pull/175) and its app-local runtime? The two observations that would help are whether the root-signature refusals change and whether the game gets past the point where the current run stops. Matching worker frames alone leaves the cause open.
