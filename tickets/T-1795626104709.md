## Original body

A sampler heap larger than `D3D12_MAX_SHADER_VISIBLE_SAMPLER_HEAP_SIZE`
(2,048) makes `HostHeap::new` return `None`. The heap is lost outright
instead of being capped like a view heap.

## Where

`crates/victory-gpu/src/descriptor/host.rs`, `HostHeap::new`:

- `make(count + extra)` with `sampler = true` and `count > 2,048` fails at
  `CreateDescriptorHeap` (2,048 is the sampler limit on every binding tier).
- The fallback arm is guarded by `!sampler`, so a sampler heap goes to the
  generic `Err(e) => { warn; return None; }` path.
- `Descriptor::host()` caches that `None` forever with `get_or_init`.
- `draw::State::bind` builds `SetDescriptorHeaps` with `filter_map(...host())`,
  so a heap without a host is dropped from the list. That also shifts the
  heap indices the translated root signature expects, not just the missing
  sampler heap.

View heaps behave differently: they cap at `PORTABLE_VIEWS` (1,000,000) and
keep the title's first `PORTABLE_VIEWS - DYNAMIC` slots; #21 remaps root
tables that reach past that cap.

## Fixing it

Sampler chunks plus a copy path for a table crossing a chunk boundary would
be the complete fix; sampler tables cross more often because the chunks are
small. At minimum the failure should be reported clearly instead of
silently dropping the heap.

Found in static review while discussing #35. I have not seen a title ask
for more than 2,048 samplers; a log line with the title's sampler heap size
would confirm whether this path is live.

### Comment 1 — @DaviTostes — 2026-11-24T00:12:04Z

Checked this against `main` `97c78d1` by code reading (no D3D12 here, so no GPU repro). The report matches the code:

- `HostHeap::new` sets `extra = if sampler { 0 } else { DYNAMIC }` and the cap arm is `Err(e) if !sampler && count + extra > PORTABLE_VIEWS`, so a sampler heap above 2,048 falls through to the generic `Err` → `None` (`crates/victory-gpu/src/descriptor/host.rs:68-100`).
- `Descriptor::host` caches that `None` with `get_or_init` (`crates/victory-gpu/src/descriptor.rs:79-92`).
- `draw.rs:410` builds `SetDescriptorHeaps` with `filter_map(...host())`, so the heap also disappears from the list and the indices shift.

A smaller intermediate step than chunking, if you want the heap to survive meanwhile: mirror the view path — on failure with `sampler && count > 2048`, `make(2048)` and keep the title's first 2,048 slots, recording `count = 2048` so `GPU_RANGES` and `cpu(index)` stay consistent. It still needs the #21-style remap once a root table reaches a slot past the cap, but it stops the whole heap (and the root heap indices) from vanishing for titles that only touch the low slots.

No game data used. AI-assisted (DeepSeek V4.1 Flash coding agent).


### Comment 2 — @WallasSCRIPTS — 2026-11-24T00:17:25Z

Update from #74: a sampler heap the host refuses is now capped at
`D3D12_MAX_SHADER_VISIBLE_SAMPLER_HEAP_SIZE` (2,048) instead of returning
`None`. That keeps the first 2,048 samplers and, importantly, keeps the heap
in `SetDescriptorHeaps`: `draw::State::bind` used to drop a hostless heap with
`filter_map`, shifting the heap indices the translated root signature expects.

The other half is still open here. `HostHeap::dynamic` is view-only, so
`State::tables` cannot remake a sampler table with an entry past 2,048; those
tables are not made at all. A complete fix needs sampler chunks plus a copy
path for a table crossing a chunk boundary. Sampler tables cross more often
because the chunks are small.

One correction to the original report: this is driver-dependent. The RX 7600
here accepts a 2,049-slot sampler heap, so the refusal is not universal —
the test in #74 forces it with `u32::MAX` so the path is exercised on any
host.


### Comment 3 — @WallasSCRIPTS — 2026-11-24T00:23:13Z

Follow-up to my earlier comment: the second half is now in #74 too. A capped
sampler heap reserves 256 scratch slots, and `HostHeap::dynamic`/`release`
use them like a view heap's. `State::tables` already remakes a table whose
entries reach past `host.count()`, so sampler tables past the cap now take
that path instead of being skipped. An uncapped sampler heap keeps all
2,048 title slots.

What remains is only the complete chunked design if a title needs more than
2,048 samplers simultaneously — this gives it the first 1,792 plus a 256-slot
scratch area, not more addressable samplers. #65 can stay open for that, or
be closed if the cap is enough in practice; I cannot tell without a log of
the title's sampler heap size and usage.

`cargo test -p victory-gpu`: 41 passed; clippy clean.
