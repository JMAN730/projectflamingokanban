#### 24. `VIC-BT-024` — resource::track() iterates blocks in index order instead of RPO, missing waterfall offset loads in split_irreducible copies (`P1`)
- **Location:** `crates/victory-shader/src/resource.rs` lines `172-190, 261-269, 360-385`
- **Prior-Work Check:** 0% overlap across Marvisak_VIctory (0 hits for offset_at or split_irreducible in resource.rs; #568/#180/#645 address unrelated waterfall/address features).
- **Root Cause:** In crates/victory-shader/src/resource.rs, track() (lines 172-190) iterates blocks in raw vector index order `for (b, block) in p.blocks.iter().enumerate()` rather than reverse postorder (RPO). When a block at a lower index references a descriptor loaded by an s_load in a higher-indexed block (for example, a block cloned and appended to p.blocks by structure::split_irreducible(), or a loop back-edge/reordered CFG block), out.scalar has not yet been populated for that higher-indexed block when the consumer is visited. Similarly, offset_at() (lines 261-269) only checks out.scalar entries populated prior to the current iteration, so waterfall detection misses the load and falls back to a uniform first-lane descriptor load.
- **Edge-Case / Verification Note:** Verified in ir.rs and structure.rs that reverse_postorder(&p.blocks) is used by both ir::ssa() and emit::lower::run(), specifically because raw block indices do not guarantee dominance order after CFG transformations or non-linear branch layouts. resource::track() is the only pass still iterating `0..p.blocks.len()` linearly while relying on previously-populated maps.
- **Synthetic Reproducer:** Construct a shader CFG where block 0 branches to block 2 (containing s_load_dwordx8 from a descriptor table with v_readfirstlane_b32 offset), which branches to block 1 (containing image_sample using that descriptor). Because block 1 is visited before block 2 in resource::track(), out.scalar does not yet contain block 2's load when block 1 is processed.
- **Proposed Fix & Risk:** - **Fix:** Iterate blocks in reverse_postorder(&p.blocks) in resource::track() (and run scalar address collection to a fixed point or in a dedicated pre-pass before descriptor/waterfall resolution so all s_load addresses are populated before any consumer inspects out.scalar).
- **Regression Risk:** Low; visiting blocks in RPO (or separating scalar-address collection from descriptor/waterfall resolution) strictly improves dominance coverage without changing valid in-order shaders. (Estimated size: `S`)

#### 25. `VIC-BT-025` — s_buffer_load_dword* adds unaligned base, soffset, and offset before dword-truncating instead of truncating each term independently (`P1`)
- **Location:** `crates/victory-shader/src/emit/lower.rs` lines `2834-2873`
- **Prior-Work Check:** Searched all 3,661 VIctory records for `s_buffer_load_dword` alignment / `& ~3` / `soffset` truncation (0 hits).
- **Root Cause:** Measured on both RX 6800 (`gfx1030`) and `gfx1036` hardware (`ProjectLeonidaL/leonida` `design.md:281`), `s_buffer_load_dword*` clears the low 2 bits of `base`, `soffset`, and `imm_offset` individually (`(base & ~3) + (soffset & ~3) + (offset & ~3)`) before summing: specifically, `sOFF = 3` and `IMM = 3` resolves to byte offset `+0`, NOT `+4`. `lower.rs:2834-2873` sums `offset + base + extra + soffset` first and only truncates/divides by 4 afterward, shifting the loaded dword by +4 bytes whenever the low 2 bits of two terms carry across bit 2.
- **Edge-Case / Verification Note:** Alternative hypothesis: constant-buffer addresses and offsets might always be 4-byte aligned. Falsification: byte-addressed structured buffers or packed scalar offsets in `soffset` can have non-zero low 2 bits; hardware explicitly masks each addend before addition.
- **Synthetic Reproducer:** Bind a buffer containing `[0x11111111, 0x22222222]` at offset 0. Execute `s_mov_b32 s4, 3; s_buffer_load_dword s5, s[0:3], s4 offset:3`. Hardware loads `0x11111111` (offset `(3 & ~3) + (3 & ~3) = 0`); VIctory computes `(3 + 3) >> 2 = 1` and loads `0x22222222`.
- **Proposed Fix & Risk:** - **Fix:** Mask `base`, `soffset`, and `offset` individually with `& !3u32` before summing them in `lower.rs:2834-2873`.
- **Regression Risk:** Very low; adds at most two bitwise ANDs on scalar SMEM address calculation. (Estimated size: `XS`)

#### 26. `VIC-BT-026` — s_cbranch_vccz and s_cbranch_vccnz AND vcc with exec instead of testing raw VCC (`P1`)
- **Location:** `crates/victory-shader/src/structure.rs` lines `1010-1021`
- **Prior-Work Check:** Searched all 3,661 VIctory records (847 issues/PRs + 2,788 issue comments + 26 review comments) for `s_cbranch_vccz`, `s_cbranch_vccnz`, and `vcc` AND `exec` in `structure.rs` (0 hits).
- **Root Cause:** `structure.rs:1010-1021` evaluates `s_cbranch_vccz` and `s_cbranch_vccnz` by computing `self.b.and(vcc, exec)` before checking whether the mask is all-zero. Per the RDNA2 ISA, `s_cbranch_vccz`/`s_cbranch_vccnz` test the full 32-bit/64-bit `VCC` scalar register (`VCC == 0` / `VCC != 0`) independent of `EXEC`. Whenever a shader sets bits in `VCC` for currently inactive lanes (e.g. via `s_mov_b32 vcc_lo, ...`, `s_or_b32 vcc_lo, ...`, or a prior `v_cmp` before narrowing `EXEC`) and branches on `s_cbranch_vccz`/`vccnz`, masking with `exec` flips the branch direction.

Falsification: loop-exit patterns save/OR `VCC` across iterations while narrowing `EXEC` (`s_and_saveexec_b32`), or load a wave-wide scalar mask into `VCC`; a synthetic shader setting `vcc_lo = 1` with `exec_lo = 2` and executing `s_cbranch_vccz` takes the wrong branch.
- **Synthetic Reproducer:** Assemble a Wave32 compute shader: `s_mov_b32 vcc_lo, 1; s_mov_b32 exec_lo, 2; s_cbranch_vccz target`. On RDNA2 hardware, `VCC != 0` so the branch is NOT taken; VIctory computes `vcc & exec == 0` and takes the branch.
- **Proposed Fix & Risk:** - **Fix:** Test the raw `vcc` lane-mask value directly in `structure.rs:1010-1021` without `self.b.and(vcc, exec)`.
- **Regression Risk:** Low; matches RDNA2 hardware semantics for scalar VCC branch instructions. (Estimated size: `XS`)

#### 30. `VIC-BT-030` — v_readlane_b32 and v_writelane_b32 do not mask lane index to S1[4:0] (Wave32) / S1[5:0] (Wave64) (`P1`)

#### 31. `VIC-BT-031` — v_writelane_b32 gates its destination write with EXEC, silently dropping SGPR spills to inactive lanes (`P1`)
