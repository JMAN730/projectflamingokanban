### Bug

In `crates/victory-gpu/src/list.rs` (`extern "system" fn allocate_upload`):

```rust
let align = usize::try_from(alignment).unwrap_or(0).max(16);
let Some(len) = usize::try_from(size).ok().and_then(|s| s.checked_add(align)) else {
    return std::ptr::null_mut();
};
if this.is_null() || !align.is_power_of_two() {
    return std::ptr::null_mut();
}
let mut block = vec![0u8; len];
```

Two bugs violate the "null on failure" contract across this FFI entry point:

1. **Invalid sub-16 alignments silently accepted:** `.max(16)` runs *before* `!align.is_power_of_two()`, so non-power-of-two alignments `3, 5, 6, 7, 9..15` (and values failing `usize::try_from`) are silently rounded up to `16` and succeed instead of returning null.
2. **Panic / abort across `extern "system"` on oversized or unallocatable requests:** `size + align > isize::MAX` (e.g., `alignment = 1 << 63` with `size = 16`, or `size = isize::MAX` with `alignment = 16`) passes `checked_add` and `is_power_of_two`, then panics with `capacity overflow` inside `vec![0u8; len]` (aborting the process because `extern "system"` cannot unwind). Similarly, unallocatable sizes below `isize::MAX` (OOM) trigger `handle_alloc_error` and abort instead of returning null.

### Fix

- Check `this.is_null()` and validate `alignment` (allowing `0` as default 16-byte alignment and rejecting non-powers-of-two before `.max(16)`).
- Allocate fallibly with `Vec::try_reserve_exact(len)` + `block.resize(len, 0)`, returning `null_mut()` cleanly on both `CapacityOverflow` (`len > isize::MAX`) and `AllocError` (OOM).
- Guard `offset >= align` before `start.add(offset)`.
- Added synthetic regression test `list::tests::allocate_upload_rejects_bad_alignments_and_oversized_requests` covering null list, sub-16 non-power-of-two alignments (`3..15`), oversized/wrapping/unallocatable sizes and alignments (`1 << 63`, `isize::MAX`, `u64::MAX`, `1 << 50`), and valid alignments (`0, 1, 2, 4, 8, 16, 64`) + `reset` cleanup.

### Verification

- **Before fix:** `allocate_upload_rejects_bad_alignments_and_oversized_requests` failed immediately on alignment `3` (`non-power-of-two alignment 3 must fail`), and oversized power-of-two alignments/sizes aborted across FFI.
