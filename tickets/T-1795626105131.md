## Original body

When running an Xbox Series X title (`TitleID: 00000000`) with the diagnostics build (`VICTORY_D3D12_WARP=1`), execution stops during `System Init` at `Frame: 0` with an `unhandled exception 0x80000003` at `victory-image-b99f876b74d4a77f.dll+0x2237178`.

### Environment
- **OS:** Windows 11 Pro 26H2 (build 26300.9974)
- **CPU:** Intel Core i9-9900K (8 cores / 16 threads, AVX2)
- **RAM:** 32 GB (31.9 GB usable)
- **GPU:** NVIDIA GeForce RTX 2080 Ti (11 GB, driver 621.24 / 32.0.16.2124)
- **VIctory Commit:** `ffe310e`
- **Rust / Toolchain:** Rust `1.98.1` (`x86_64-pc-windows-msvc`), Visual Studio 2022 Build Tools, Windows SDK `10.0.26100.0`
- **Workspace Tests:** 342 passed, 0 failed, 6 skipped

### Reproduction & Configuration
- **Build:** `cargo build --profile diag -p victory --features diagnostics`
- **Environment variables:**
  - `VICTORY_D3D12_WARP=1`
  - `VICTORY_LOG=victory_loader=trace,info`

### Observed Behavior
1. Image mapped at `0x7ffa645e0000` (preferred `0x140000000`), static TLS redirected (`index=12`, `patched=53246`).
2. Virtual drives mounted (`G:` and `T:`), console mode reported as `Xbox Series X`.
3. Imports bound: `88 hle`, `427 host`, `0 title`, `72 missing` across:
   - `XboxBvhBuilder.dll`
   - `amd_fidelityfx_loader_xbox.dll`
   - `libHttpClient.GDK.dll`
   - `Bink2Scarlett.dll`
4. Host DLL `rpcrt4.dll` refused by host policy.
5. `GameInput` and `dstorage` (staging buffer `33554432`, `16` workers) initialized.
6. `first-chance exception 0x80000003` followed by `unhandled exception 0x80000003` at `victory-image-b99f876b74d4a77f.dll+0x2237178`.
7. Breakpad generated local crash artifacts (`victory-20261124-150951-13156.crash.log` and `00000000-0000-0000-0000-000000000000.dmp`) on virtual drive `T:`; HTTP upload to `submit.backtrace.io:443` was blocked by `victory_hle::modules::net`.

### Debug Info Snapshot

- **TitleID / SharedId:** `00000000` / `77b255c47c1d11dd96b94ea8e3200862`

The main executable’s import counts point to a specific startup difference. In #417 the loader bound 88 HLE, 427 host, 72 title and 0 missing imports, listed all four sibling DLLs, and reached the start screen. Here the HLE and host counts match exactly, while the other 72 entries appear under “missing”. The successful run also logged the same rpcrt4 policy warning. [Comparison log](https://github.com/Marvisak/VIctory/issues/417#issuecomment-7120851807)

Could you paste the per-image load and bind lines from the existing trace for XboxBvhBuilder.dll, amd_fidelityfx_loader_xbox.dll, libHttpClient.GDK.dll and Bink2Scarlett.dll, plus any “unimplemented import called” line before the frame-zero breakpoint? Text excerpts are sufficient. The bind summary records resolution during loading. A call warning or stack would help determine whether an unresolved import was reached before the stop.


One read-only check before another run: list the exact on-disk spelling of the four DLLs beside the executable and query that directory with `fsutil file queryCaseSensitiveInfo "<title directory>"`. On ffe310e, the loader lowercases each imported name before checking whether the file exists. In a case-sensitive directory a mixed-case file can therefore be present and still be skipped. This explanation applies only where the lowercase lookup actually differs from the stored name. For example, an on-disk `amd_fidelityfx_loader_xbox.dll` already spelled exactly that way needs a different explanation if it was skipped. [Loader source](https://github.com/Marvisak/VIctory/blob/ffe310e/crates/victory-loader/src/windows.rs#L149-L153) · [Case-sensitive directory test in #762](https://github.com/Marvisak/VIctory/issues/762)
