## Original body

The guest command list at `ffe310e` skips the `ClearUnorderedAccessViewUint` and `ClearUnorderedAccessViewFloat` entries. A synthetic test on that commit stops at the missing slot check before creating a D3D12 device.

[Source commit `d359499`](https://github.com/fuzeofficlal/VIctory/commit/d3594990c99aab01bbb864e803022444e075d2b3) wires both entries for resource-backed textures. It uses a matching descriptor pair in the CPU-only and bound shader-visible heaps and uses the existing texture state tracker for the transition to UAV state.

I recorded a whole clear followed by a centered 2×2 clear for each of two 4×4 textures, `R32_UINT` and `R32_FLOAT`, on the same guest list. RTX 5090 and WARP both read back all 32 expected values, including the unchanged pixels outside the rectangles, with zero D3D12 debug-layer errors. Each diagnostics suite passed 53 tests with one benchmark ignored.

Buffer UAV clears need their own state handoff and are outside this patch.

Typed views clear as they are; the title's rectangles are scaled with the structured-to-word view. Float clears of raw and structured views, and structured views whose stride is not whole words, are refused and logged once.
