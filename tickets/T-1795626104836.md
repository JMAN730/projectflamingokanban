## Original body

### Problem

Under the Microsoft x64 COM ABI, member methods returning a struct larger than 8 bytes by value receive a caller-allocated hidden output pointer (`out`, after `this`) and must return that pointer in `RAX`.

In `victory-gpu`, all four `GetDesc` implementations currently return `()`, leaving `RAX` undefined for callers that read the returned pointer rather than their own stack slot:
- `ID3D12Heap::GetDesc` (`resource::heap_desc`, `HeapDesc` = 48 B)
- `ID3D12Resource::GetDesc` (`resource::resource_desc`, `ResourceDesc` = 56 B)
- `ID3D12CommandQueue::GetDesc` (`queue::desc`, `QueueDesc` = 16 B)
- `ID3D12DescriptorHeap::GetDesc` (`descriptor::desc`, `HeapDesc` = 16 B)

Other hidden-out-pointer methods in the workspace (`xsystem::analytics_info`, `resource::allocation_info`, `resource::allocation_info2`, and `resource::custom_heap_properties`) already return `out`.

### Fix on a fork

Since PR creation is currently limited to collaborators, the fix is pushed and CI-verified on a fork:

- **Branch:** https://github.com/BlueCatsz/VIctory/tree/fix/gpu-getdesc-return-ptr
- **Commit:** `ef2f8fa16e00856779e40bf1b3050eea508784c7`
- **Compare:** https://github.com/Marvisak/VIctory/compare/main...BlueCatsz:VIctory:fix/gpu-getdesc-return-ptr

#### Changes
- `crates/victory-gpu/src/resource.rs`: change `heap_desc` and `resource_desc` to return `*mut HeapDesc` / `*mut ResourceDesc` (`out`); update `resource::tests::heaps_are_zeroed_aligned_memory` and `resource::tests::committed_and_placed_resources_map_at_their_gpu_address` to verify `get_desc(obj, out_ptr) == out_ptr`, the populated fields, and null `out` handling.
- `crates/victory-gpu/src/queue.rs`: change `queue::desc` to return `*mut QueueDesc` (`out`) and add synthetic test `queue::tests::queue_get_desc_returns_its_output_pointer` (resolving vtable slot `0xe0` vs `0xd0` dynamically).
- `crates/victory-gpu/src/descriptor.rs`: change `descriptor::desc` to return `*mut HeapDesc` (`out`) and add synthetic test `descriptor::tests::heap_get_desc_returns_its_output_pointer`.
