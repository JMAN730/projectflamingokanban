## Original body

On Windows x64 at `d2a4bae1`, the shader emitter rejects a branch that reads an unsupported `s_memtime` result directly, but accepts the same read after two conditional assignments. The timestamp is still observable when the workgroup has X = 0 and Y = 1.

The synthetic compute shader enables the X and Y group-id SGPRs (`rsrc2 = 3 << 7`). Its relevant operations are:

```text
s_memtime s[6:7]
if group_id_x != 0: s6 = 0
if group_id_y != 1: s6 = 1
branch on s6 != 0
```

| Case | Lowering result |
|---|---|
| Direct branch on the low timestamp dword | Refused with `a scalar memory read as data` |
| Branch on the dword after both joins | Accepted |

I would expect the two live reads to agree. Reading the group id at the final branch instead makes the timestamp dead and should still lower. This concerns the emitter's acceptance decision; the experiment used no game data or native hardware reference.

`Lower::get` marks the phi used by the final comparison. The earlier phi is read only by the later phi. In `fill_phis`, an unmarked phi may substitute zero for a missing incoming value. Following incoming phi dependencies from the actual readers made the live and dead controls pass locally.

Reproducer: [test-only commit 4b2ea70f](https://github.com/Dathinel/VIctory/commit/4b2ea70f0940a4317dc934000d249dce0fce50f6). To run it on the stated base, apply the test-only commit, then run:

```sh
cargo test --frozen -p victory-shader --features host a_missing_value_stays_missing_through_two_live_joins -- --nocapture
```

On the original emitter, the assertion prints `left: None` (joined) and `right: Some("a scalar memory read as data")` (direct). I found this while testing #521; it also reproduces on unmodified `main` with only the test added. AI tools assisted with the reproducer and independent review.

We verified PR #699 against your reproducer `a_missing_value_stays_missing_through_two_live_joins`, and the test passes cleanly on Windows 11 MSVC.
