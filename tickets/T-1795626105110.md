## Original body

The workspace has no CI, so nothing runs the test suite before a merge.
Two cases from the last few hours, both merged into `main`:

1. `cargo test -p victory-shader` did not compile: `lowers` gained a second
   parameter in 3c86053 and one call site kept the old signature (E0061).
   Fixed on the branch `fix/s_bitcmp-test-rsrc2`. The test target fails on every host, not just one platform.
2. `cargo build --workspace` does not build on Linux: one `#[cfg(windows)]`
   helper is called from an ungated function in `victory-gpu/src/resource.rs`,
   and `victory-hle` has nine `windows_sys`/`xmem`/`lifecycle` references
   without a gate.

A single job would have caught the first one before merge:

```yaml
name: test
on: [push, pull_request]
jobs:
  test:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - run: cargo test --workspace
      - run: cargo clippy --workspace --all-targets
```

Two things worth deciding before adding it:

- Which host to run on. Windows is the only platform the tool actually targets
  today, and `cargo test --workspace` there also exercises the Windows-gated
  halves. Linux needs the two build fixes above first, but would then cover
  the host-independent crates cheaply.
- Whether the asset-policy check (`cargo xtask policy`, currently a local git
  hook) belongs in the same job.

Not asking for anyone to be blocked by CI: at 100 open pull requests a red
required check on an unrelated flake would hurt. A non-blocking job that only
reports would already have caught both failures above.

Happy to send the workflow as a pull request if that is wanted.
