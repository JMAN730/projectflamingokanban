## Original body

PR creation is limited to collaborators, so this is a branch ready to merge: [rpmaster2/VIctory@diag/slot-host-resource](https://github.com/rpmaster2/VIctory/tree/diag/slot-host-resource) (two commits, `d634ae9` and `915dd1b`, on top of `ffe310e`; the second also puts the same suffix on the per-draw `reads` line).

## What it does

`HostHeap::describe_slot` already prints the title view a heap slot holds, which is what the black-frame draw trace uses (`VICTORY_LOG=info,victory_gpu::draw=debug`, then `black frame <n>: ...` lines). For textures that text stops at the view's own words, for example:

```
reads ["... Srv s0+552: placed uav=false dim 1 1584x1 f0 layout 0x1 at 0xc8480160"]
```

so the report cannot answer the question #850 ends on: does the slot view a resource at all, and if so what is it? A slot that views nothing, a slot whose resource is the wrong size, and a slot whose resource is right but never written all look the same today.

The commit appends the host resource behind the slot: width, height, format and mip count, or `host none` when the slot holds no resource:

```
SrV s0+552: placed uav=false dim 1 1584x1 f0 layout 0x1 at 0xc8480160 host 1584x1 f0 mips 1
```

Same call site, diagnostics builds only, no extra logging at info or below, no behaviour change.

## Why it is worth having

On #850's chain the cutscene comes down to a full-screen triangle that samples one descriptor and outputs the flat clear colour; format, viewport, render target, depth, submission and upload are already excluded. The remaining probe is exactly "what does that slot resolve to", and this makes the existing black-frame trace say it. My own runs on RDNA4 show the same shape (frame 1199: several `vb 0x0+0 stride 0` draws, `targets []`, all sampling the same shader's SRVs), and with this patch those lines name the resource.

## Testing

- `cargo build --profile diag -p victory --features diagnostics`: ok.
- `cargo test -p victory-gpu --lib --features diagnostics`: 55 passed, 0 failed, 1 ignored, including two new tests: a slot without a resource, and a committed 64x32 texture on the real device naming its own size and format.
- The patch only adds a field to a diagnostics string; the two tests above cover both the empty and the texture case.
- Not exercised in a device-removed report yet on this host: my last GPU runs are paused after a driver reset froze the machine.

No game data in this report: formats, counts and error strings only.

### Comment 1 — @MichaelSmithAI — 2026-11-24T13:46:21Z

I checked the two log paths on d634ae9. The host-resource suffix works for a mirrored SRV. In an independent RTX 4090 Wine/GE 3.2 check on the earlier ad8dabb revision, an 8×4 RGBA8 texture reported `host 8x4 f28 mips 3`, and remirroring after release reported `null`.

The ordinary `black frame … reads` line still calls `State::reads` before binding. That method formats the guest view. The caller of `HostHeap::describe_slot` is `State::op_text`, which builds the recorded-operation diagnostic. Enabling the draw debug log alone therefore won’t add the host suffix to the quoted line. [Draw trace and reads](https://github.com/rpmaster2/VIctory/blob/d634ae91df47a8655794ca07bcc802e9f8de70d9/crates/victory-gpu/src/draw.rs#L795-L836) · [Recorded-operation caller](https://github.com/rpmaster2/VIctory/blob/d634ae91df47a8655794ca07bcc802e9f8de70d9/crates/victory-gpu/src/draw.rs#L557-L585)

For the #850 example, `dim 1 1584x1 f0` describes a **1,584-byte buffer**. The zero format belongs to the resource description. The SRV has its own format. The reporter also identified `dfafaf385b2f94e8` as the vertex shader and reported zero resource bindings for its paired pixel shader `06295fb1d1aefb78`. To trace the cutscene on a completed frame, the missing evidence is the host slot actually selected after table preparation (including a freshly copied table), together with the shader stage, draw and output target in that frame. [Reporter’s stage identification](https://github.com/Marvisak/VIctory/issues/850#issuecomment-7131788718)

If you want, I can add the post-preparation slot to the same line (an index into the host heap after `make_at`), which would close that gap in one run.
