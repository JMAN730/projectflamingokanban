## Original body

## What's wrong

`open()` in `crates/victory-hle/src/modules/xsystem.rs:185-187` returns `ERROR_FILE_NOT_FOUND` for every open below our stand-in for `HKLM\Software\Microsoft\Windows NT\CurrentVersion\OEM`. That includes a null or empty subkey. Both `RegOpenKeyW` and `RegOpenKeyExW` go through it.

Microsoft's docs:
- **`RegOpenKeyW`, `lpSubKey`:** if it is NULL or points to an empty string, the function returns the same handle that was passed in.
- **`RegOpenKeyExW`:** with a NULL or empty `lpSubKey` on a key that isn't predefined, `phkResult` receives a new handle to the key.

The host does both. I checked on `HKLM\Software\Microsoft\Windows NT\CurrentVersion`.

The impact is low. As the code's comment says, the title opens the full path and queries `ConsoleMode`. This only matters for code that opens the key again this way.

## Repro

After `RegOpenKeyW(HKLM, L"Software\\Microsoft\\Windows NT\\CurrentVersion\\OEM", &k)` succeeds:
- `RegOpenKeyW(k, NULL, &k2)` returns 2. Expected: 0, with `k2 == k`.
- `RegOpenKeyExW(k, L"", 0, KEY_READ, &k3)` returns 2. Expected: 0.

## Fix

- **Branch:** https://github.com/Peppacodes/VIctory/tree/fix/oem-key-empty-subkey
- **Compare:** https://github.com/Marvisak/VIctory/compare/main...Peppacodes:VIctory:fix/oem-key-empty-subkey
- **Commit:** `8e9f9b3`, rebased on `main` (`ffe310e`), 0 commits behind it. One file, with its test.

What changed:
- A null or empty path below our key opens the key itself. It returns the same pseudo handle, which `RegCloseKey` already accepts.
- A null `phkResult` there gets `ERROR_INVALID_PARAMETER` (87), which is what the host returns.
- Any other path below the key is still not found, since it has no subkeys.

## Test

`a_null_or_empty_path_opens_the_key_itself`, in `xsystem.rs`'s `device_type` tests:
- It calls both functions with a null and an empty subkey, on our key and on a host key for comparison.
- It fails on `main` (`left: 2`, `right: 0`) and passes with the fix.

Results on Windows 11 with Rust 1.98.1, using the CI's own commands:
- `cargo test --workspace --locked`: 343 passed, 0 failed, 6 ignored.
- `cargo clippy --workspace --all-targets --locked -- -D warnings`, with and without `--all-features`: clean.
- `rustfmt --edition 2024 --check xsystem.rs`: clean.
- `cargo xtask policy`: 154 files ok.

Not changed: the path must match `KEY` exactly, apart from case. The host also accepts a trailing or doubled backslash.

PR creation is limited to collaborators right now, so this is an issue with the branch. I can open a PR when it reopens.

No game files used. AI use: Claude Code (Claude Opus 5.5) found this in an audit of the HLE modules, wrote the fix and the test, and ran everything above.
