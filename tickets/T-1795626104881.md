I tested the three fork fixes posted here side by side, each on top of `main` at `ffe310e`. All three fix the bug. With a violating path, `victory config` exits 1 instead of 0.

**Differences between the three:**

- **kyle7908:** Violations stay on stdout. The integration test runs the built binary from a temp directory with its own `VICTORY_CONFIG`, and it places `.victory-root` markers there. That makes it independent of where the repo is checked out. It adds `tempfile` as a dev-dependency (already a workspace dependency, and `--locked` passes) and adds a README note.
- **pushkarreddyy:** The check moves into `check_config_policy`, and only that function is tested. Nothing checks the binary's exit status end to end. The tests also construct `victory_core::Config` with a struct literal, so they will need updating whenever `Config` gains a field.
- **Louisreed:** Violations move from stdout to stderr, and the error includes a violation count. Stderr is a reasonable place for them, but it changes the output beyond what this issue asks for. The tests point the cache and data directories inside the repo via env vars and run from the temp directory so no `./victory.toml` is read.

kyle7908's branch looks like the best one to merge: it was first, makes the smallest behaviour change, and its test checks the binary's exit status. Louisreed's violation count would be easy to add on top if wanted.
