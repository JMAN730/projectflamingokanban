## Original body

Two small UX additions (part 1 now folded into #113, see below), ready on my fork for whenever pull requests open again (#717). Neither touches the runtime.

### 1. Issue forms for test reports

> **Update:** issue forms already have pull requests (#9 / #113, #380, #543), so this part is not a separate proposal any more; its extra fields are [suggested on #113](https://github.com/Marvisak/VIctory/pull/113#issuecomment-7134211595). Part 2 is the proposal here.

Most issues here are test reports, and each one is written differently: the GPU, driver, Windows build, branch and logs end up in a different place every time, or are missing. That makes the data hard to compare across reports.

The branch [`ux/issue-forms`](https://github.com/EduBertozzi/VIctory/tree/ux/issue-forms) adds `.github/ISSUE_TEMPLATE/`:

- **Test report** (`[Test] ` title): the VIctory commit and build, GPU maker (dropdown), GPU and driver, system, how far it got and how it ended (dropdowns), time and frame rate, environment variables, and log excerpts. A checkbox confirms nothing from the game is attached.
- **Can't run** (`Can't run: ` title): the command, what you see, the output of `victory config`, the system, GPU and commit.
- **Code bug**: something wrong in the code that can be pointed at (file:line on a commit), with no game run needed.
- **`config.yml`** keeps blank issues and links "Getting started" and the hardware results thread (#49) for one-line "works / doesn't on my GPU" notes.

### 2. A menu when `victory.exe` is double-clicked

Today a double-click opens a console that prints clap's usage and closes. With [`ux/launcher-menu`](https://github.com/EduBertozzi/VIctory/tree/ux/launcher-menu), a console the process owns (checked with `GetConsoleProcessList`, or forced with `VICTORY_MENU=1`) shows a menu. Every command-line use is unchanged.

![The menu after a double-click, then 3 (Check this PC), on a Windows 10 + GTX 1060 machine](https://raw.githubusercontent.com/EduBertozzi/VIctory/ux/screenshots/launcher-menu.png)

<details><summary>The same as text</summary>

```
  V I C T O R Y
  your own copy of the title, on this PC
  ────────────────────────────────────────

  1  Run a game
  2  Run again   (nothing run yet)
  3  Check this PC
  4  Open the data folder   saves, crashes.log
  Q  Quit

  Choose:
```

</details>

**Check this PC** answers the questions most "can't run" issues ask, each with a one-line hint:

- Windows build (and the SM 6.5 limit of Windows 10's in-box D3D12, #84/#175)
- AVX2
- shader model 6.6
- mesh shaders (#3)
- the GPU's wave size (#578/#778)
- the game, data and cache folders, including the "outside the repository" rule

Colour is a 24-bit gradient (an original sunset palette, nothing from the title). It respects `NO_COLOR` and `CLICOLOR_FORCE`, and plain text is used when the console has no VT support. It adds `windows-sys` Console/Registry features and the workspace's `windows` crate (for the D3D12 check) to the app, plus `tempfile` for its tests.

Both branches sit on today's `main` (`ux/issue-forms` 3 commits, `ux/launcher-menu` 1). If either is wanted, I'll open the pull request once outside PRs are accepted. Feedback on fields or wording is welcome before that.
