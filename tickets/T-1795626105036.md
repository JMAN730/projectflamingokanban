## Original body

## Summary

Tested **Windows 10 IoT Enterprise LTSC (Build 19044 / 21H2)** + **NVIDIA GeForce RTX 4060 (8 GB)** on `ffe310e` with **PR #175** (D3D12 Agility SDK 1.620.2), **PR #189** (Wave64 compute emulation, `wave64_mode=Emulate`), and **PR #352** (mesh pipeline library topology):

- **PR #175 works on Windows 10 Build 19044 (LTSC 21H2):** clears the in-box SM 6.5 / `c01` root-signature refusals and early init crash (#348). First-boot screens, settings menu, profile/saves, and loading run at **30.0 fps** (`33.3 ms/frame`, `0 dropped`, `0 missing imports`).
- **PR #189 eliminates all Wave64 compute refusals (`0x80070057`: `0` refused)**, and **0** `E_OUTOFMEMORY` (`0x8007000E`) texture allocation errors occurred on 8 GB VRAM (contrast with #1226).
- **World entry still fails** with SFX/audio playing over a black screen (`0.2–0.6 fps`, `1,005–1,835` dropped draws/frame) followed by **`DXGI_ERROR_DEVICE_HUNG` (`0x887A0006`)** and Windows TDR (`Display` Event ID `4101` / `nvlddmkm` Event ID `153`) across 3 consecutive runs (2 `release`, 1 `diag` with `VICTORY_D3D12_DRED=1`).
- **Directly answers the open Wave64 question in #1117:** even with PR #189 (`wave64_mode=Emulate`) and PR #352 active, **every single ~2 s stall (6/6 submissions: `1,950–2,190 ms`, including the fatal `2,190 ms` submission at frame 1381)** contains **`[compute 9146291b38ea9ce1]`** (while all non-`9146291b` slow submissions completed in `278–778 ms`), and DRED reports `done == count` across all 8 submitted lists.

## Steps to Reproduce

1. Build on `ffe310e` + PR #189 + PR #175 + PR #352 (note: minor 1-hunk conflict in `apps/victory/src/main.rs` keeping both `data_dir` and `d3d12 sdk`), and run `cargo xtask agility`.
2. Launch (`release` for Runs 1–2; `diag` with `VICTORY_D3D12_DRED=1`, `VICTORY_LOG=info` for Run 3):
   ```powershell
   target\diag\victory.exe run <game_dir>\game_scarlett_master.exe --execute
   ```
3. Complete first-boot settings / load save and enter the start of the game.
