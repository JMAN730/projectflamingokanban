## Original body

## What's wrong

Microsoft's [XSystemGetXboxLiveSandboxId reference](https://learn.microsoft.com/en-us/gaming/gdk/docs/reference/system/xsystem/functions/xsystemgetxboxlivesandboxid) specifies a minimum buffer size of `XSystemXboxLiveSandboxIdMaxBytes` (`16` in `XSystem.h`):

- `sandboxIdSize`: "This value must be equal to or greater than the **XSystemXboxLiveSandboxIdMaxBytes** constant defined in XSystem.h."
- Return value: "If the function fails because *sandboxIdSize* is set to a value less than **XSystemXboxLiveSandboxIdMaxBytes**, the return value is set to **HRESULT_FROM_WIN32(ERROR_INSUFFICIENT_BUFFER)**."

In `crates/victory-hle/src/modules/xsystem.rs` (lines 37 and 64–66), `sandbox_id` calls `put_string(SANDBOX, size, buffer, used)` with `const SANDBOX: &str = "RETAIL";`. `put_string` (`crates/victory-hle/src/modules/xgameruntime.rs`, lines 145–149) only checks `size < text.len() + 1` (7 bytes).

As a result, calling `XSystemGetXboxLiveSandboxId(7, buf, &used)` returns `0x8007007A` (`HRESULT_FROM_WIN32(ERROR_INSUFFICIENT_BUFFER)`) on Xbox regardless of the sandbox's length, but returns `S_OK` here, writing `"RETAIL\0"` and setting `used = 7`.

## Impact

Low impact: titles that follow the GDK documentation allocate at least `XSystemXboxLiveSandboxIdMaxBytes` (16 bytes), so only a title passing a short buffer (7–15 bytes) diverges—it succeeds here and fails on Xbox.

## Fix

Define `SANDBOX_ID_MAX_BYTES: usize = 16` (`XSystemXboxLiveSandboxIdMaxBytes`) in `crates/victory-hle/src/modules/xsystem.rs` and have `sandbox_id` return `xasync::E_NOT_SUFFICIENT_BUFFER` (`0x8007007A`) whenever `size < SANDBOX_ID_MAX_BYTES`, before calling `put_string`. Leave `put_string` itself unchanged; the other two getters in `xsystem.rs` (`console_id`, 39 bytes, and `device_id`, 45 bytes) already match their documented minimums because their strings fill them exactly.

The fix is ready on a branch of my fork, since PR creation is limited to collaborators: https://github.com/BastienRodz/VIctory/commits/hle/sandbox-id-buffer-minimum (one commit on `main` `ffe310e`, `xsystem.rs` +26).

## Tests

`a_sandbox_id_buffer_under_the_documented_minimum_is_refused`: sizes 7 and 15 are refused with `E_NOT_SUFFICIENT_BUFFER` and the buffer is left untouched; size 16 gives `S_OK`, `"RETAIL\0"` and `used = 7`.
- **On `main`:** it fails at the first case, `size 7`, `left: 0`, `right: -2147024774` (`0x8007007A`).
- **With the fix,** on GitHub's `windows-latest` with the upstream CI's commands (clippy `-D warnings` with and without `--all-features`, then `cargo test --workspace --locked`): everything passes; `victory-hle` 95 passed, 0 failed (https://github.com/BastienRodz/VIctory/actions/runs/45397649553).

No game data used. AI-assisted: found with GPT-6.2 Astra, written with Gemini 4 Neon, reviewed and verified with Claude Code.

### Technical Analysis
In crates/victory-hle/src/modules/xsystem.rs:
sandbox_id delegates to put_string(SANDBOX, size, buffer, used) with const SANDBOX = RETAIL. Because put_string only checks size < text.len() + 1 (7 bytes), buffer sizes 7..15 erroneously succeed with S_OK.

However, the official GDK specification for XSystemGetXboxLiveSandboxId specifies:
- sandboxIdSize must be at least XSystemXboxLiveSandboxIdMaxBytes (16 bytes).
- If sandboxIdSize < XSystemXboxLiveSandboxIdMaxBytes, the return value must be HRESULT_FROM_WIN32(ERROR_INSUFFICIENT_BUFFER) (0x8007007A).

### Proposed Fix
Define const SANDBOX_ID_MAX_BYTES: usize = 16 in xsystem.rs and guard sandbox_id with:
if size < SANDBOX_ID_MAX_BYTES { return xasync::E_NOT_SUFFICIENT_BUFFER; }
before calling put_string. Add regression tests asserting that buffer sizes 7 and 15 return E_NOT_SUFFICIENT_BUFFER with unchanged buffers, while size 16 succeeds.

Preparing clean branch with Rust 2024 compliance on fork.
