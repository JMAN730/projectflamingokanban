## Original body

First 50-series report, as far as I can find. Plain `main`, no extra PRs.

**Machine**
- GPU: NVIDIA GeForce RTX 5090, 32 GB, driver 621.40 (32.0.16.2114)
- CPU: AMD Ryzen 9 9950X3D, RAM 64 GB, Windows 11 Pro 10.0.28000
- VIctory `main` at `ffe310e`, Rust 1.98.1 (pinned), `cargo build --profile diag -p victory --features diagnostics`
- Title: Series X dump, `game_scarlett_master.exe`, default console (Series X)
- `cargo test --workspace --locked`: 342 passed, 0 failed, 6 ignored

**Run**
```
$env:VICTORY_KEYS = '8:Enter,20:Enter,35:Enter'
$env:VICTORY_D3D12_DRED = '1'
target\diag\victory.exe run "<dump>\game_scarlett_master.exe" --execute
```
Cold shader cache (first run). Default hardware adapter, normal presentation path.

**What happened**
| Time from start | State |
|---|---|
| 0–110 s | boot, menus, loading: steady 30.0 fps, 5–39 draws/frame |
| ~2 min | world: 1.1–1.7 fps (600–884 ms/frame), 1,370–2,860 draws/frame |
| in the world | per frame, 776–3,398 draws dropped without a host pipeline (cold cache, pipelines being made) and 1,168–2,670 indirect |
| in the world | slow host submissions of 262–384 ms (32–33 lists each) |
| 178 s (~60 s in the world) | one submission of 11 lists took 4,839 ms, then `host GPU device removed ... 0x887A0006 (DXGI_ERROR_DEVICE_HUNG)` |

- Breadcrumbs of the last submission: list 0 complete, **list 1 stopped at 222/710**, lists 2–10 not started.
- `no dynamic slots for its tables`: reached `dropped=8192` (logged at powers of two) before the hang.
- 424 `shader does not translate` warnings (355 compute, 38 pixel, 27 mesh, 4 vertex), all `converter shader.dxil v1: GFX10 code at …`.
- 118 `host pipeline refused error=The parameter is incorrect. (0x80070057)`.
- `host view heap capped at 1000000 ... count=1245184`: the title asks for 1,245,184 view descriptors, NVIDIA allows 1,000,000.
- Peak private memory of the process: 23.0 GB.

So the 5090 ends the same way as the 2080 Ti / 3080 / 3080 Ti / 4060 Laptop / A4500 reports (#1440, #1465, #1496, #1508, #1479): a few seconds-long submission, then DEVICE_HUNG. Its speed does not get it past it; the 32 GB of VRAM does not either (the 4060 report suspected VRAM oversubscription; that is not the case here).

Runs of the #1520 integration branch, including one with the debug layer, are in a comment on #1520.

No game data, logs with title content or screenshots attached (asset policy). The full log and crashes.log stay on my machine; I can quote specific lines on request.

AI use: Claude Code (Claude Opus 5.5) ran the build, tests and run and wrote this report from the logs. I checked it.

### Comment 1 — @Bullet18x — 2026-11-24T20:04:07Z

Follow-up: narrowing down the NVIDIA world hang on the RTX 5090. Same machine and dump as above; diag builds; `VICTORY_KEYS=8:Enter,20:Enter,35:Enter`, `VICTORY_D3D12_DRED=1`; warm pipeline cache unless noted. Every run below except 6 ended in `DXGI_ERROR_DEVICE_HUNG` (0x887A0006).

**1. It is not one shader.** Across 10 hangs today (main, #352, #1041, #1520 runs and the ones below) the GPU stopped at a different command each time ("a list stopped at command N of M"): indirect mesh draws (op 5, `indirect kind 10`), mesh draws (op 42), compute dispatches (op 0/6), each with a different shader hash. No hash repeats, so skipping one pipeline with `VICTORY_SKIP_PIPELINES` would not help.

**2. `VICTORY_GPU_TIMING=1` (main `ffe310e`)**: the slowest single commands are 25–108 ms (four indirect compute pipelines repeat 9–29 times at ~29–79 ms each; a few mesh draws reach ~100 ms). Nothing near the ~2 s TDR on its own; the submission that hangs is a different, ordinary-looking list (it stopped at 1,579/1,791 on a 50-group mesh draw).

**3. `VICTORY_SHADER_LOOP_LIMIT=32` (main)**: the world runs **2–5× faster** (2.4–8.4 fps instead of 1.1–1.8), but it still hangs ~35 s into the world (an 11-list submission of 5,463 ms, stopped in an indirect mesh draw). So the loop guard costs time but is not what hangs.

**4. Wave64 emulation, #189 (`54b333f`, applies cleanly on `ffe310e`)**: `host pipeline refused` goes from 114–138 per run to **0** (the id=622 wave64 refusals are gone), but the hang comes *sooner* (~15 s into the world: an 8-list submission of 4,913 ms, stopped at 451/834 on a mesh draw). `shader does not translate` rises from 424 to 535 (476 compute). So the refused wave64 pipelines are not the cause either.

**5. View heap PRs.** The title asks for 1,245,184 view descriptors (the debug layer also sees 1,572,864 and 1,376,256); NVIDIA's limit is 1,000,000.
- **#1548** (`4002dd7`): `host view heap capped at 1000000 count=1245184 capped=737856 dynamic=262144`. The `no dynamic slots for its tables` drops are **gone** (none logged; `main` reaches `dropped=8192`, #1520's branch `dropped=262144`), but it still hangs ~37 s into the world (stopped at command 3/78, a mesh draw).
- **#1523** (`946edfe`): its search finds `host_limit=1000000` on this driver, `left_out=310720`; dynamic drops as on `main` (`dropped=8192`); hangs ~30 s into the world (command 3/86, a mesh draw).

So the dynamic-slot shortage is not the trigger either. What neither PR changes: 310,720 (#1523) to 507,328 (#1548) of the title's own descriptor slots still have no place in the host heap. (See the update below: those slots are not actually used before the hang.)

**Update: the slots past the limit are not used before the hang.** `mirror()` on `main` logs `title slot past the host heap` the first time *any* title slot at or past the host heap's title count is asked for (draw or not). In 11 runs on `main`-based builds (title count 934,464) and on #1548 (title count 737,856), that warning never appears before the hang: 0 times. So the title does not use any slot above ~737,856 by then, and the 1M cap is not what hangs. (The 376,256 warnings on #1520's branch come from that branch mirroring the whole heap at boot, `for_draw=false`, not from draws.)

**6. GPU-based validation (`VICTORY_D3D12_DEBUG=1`, `VICTORY_D3D12_GBV=1`, main).** Too slow to reach the world: during loading (4.4 fps, ~90 s in) the title itself faults, `unhandled exception 0xc0000005 at victory-image-….dll+0x23cf683 (write 0x0)`, no device removal. (Its crash reporter then tried to upload the minidump to `submit.backtrace.io`; VIctory blocked it as intended: `HTTP connection blocked destination=submit.backtrace.io:443`.) Before that, GBV reported **5× id=940** in pixel shaders during the menus: `SRV Dimension Expected: D3D12_SRV_DIMENSION_TEXTURE2D, SRV Dimension In Descriptor: D3D12_SRV_DIMENSION_TEXTURE1D, Descriptor Heap Index: [0]`. So at least one descriptor is made as a 1D view where the translated shader declares a 2D texture. No other GBV error appeared before the fault; the world could not be checked this way.

**Summary of what does *not* stop the hang on this machine**: skipping a single shader (it moves), `VICTORY_SHADER_LOOP_LIMIT=32`, wave64 emulation (#189), the mesh-topology library fix (#352), a full dynamic range (#1548), probing the heap limit (#1523), the #1520 integration branch; and the 1M view-heap cap is not reached by the title before the hang.
